用語は `00-glossary.md`。ティップイン／ティップアウトの機構は `45-drivability-filters.md`、
SMG 側は `80-smg-shift-tuning.md`。慣性低下が壊すもの全体は

**値の出典**: `Full 211323000401PD31_TERRA.bin`。**あなたの BIN の数値は違いうる。**

**アドレス表記**: XDF アドレス。ツールが編集する 64 KB パーシャル BIN ではそのままオフセット

## 0. この文書が答えること

軽量フライホイールに替えたあと、**慣性比 `r = J_new / J_old` を実測し、
そこから各パラメータの補正量を機械的に導く**ための手順。

既存の 2 文書はどちらも正しいが、繋がっていなかった:

- `lightweight_flywheel_tuning.md` — 慣性比 **0.82 を仮定**して 7 制御ドメインの変更セットを出す。
  比そのものは推定のまま。
- `80-smg-shift-tuning.md` §3.5 — `K_SMG_J_MOTOR` の機構を逆アセンブルで確定。

足りないのは「比を測る」部分と、「**測った比をどこに掛けるか**」の判断である。
後者のほうが重要で、間違えると 4〜20 倍ずれる（§3）。

## 1. 純正の J は測らなくてよい — ROM に書いてある

| 定数 | XDF | bank | 幅 | スケール | 純正値 |
|---|---|---|---|---|---|
| `K_SMG_J_MOTOR` | `0x280A` | slave | 8 bit | `X/128` | **0.25 Nms²** |
| `K_MD_J_MOTOR` | `0x9554` | master | **16 bit** | `X/268` | **0.268657 Nms²** |

**∴ 交換前のデータログは要らない。** BMW 自身が J_old を較正値として書いている。
測るのは **J_new の絶対値だけ**で、比は割り算で出る。

2 つが 7 % 違うのは**単位系ではなくエンコードの違い**（どちらも Nms²）。
BMW が自分自身と食い違っているだけなので、**比はそれぞれ自分の純正値に対して取る**。

> **`K_MD_J_MOTOR` は 16 bit である。** `0x9554` のバイトは `00 48` で、raw 72 が 2 バイトに跨がる。
> 8 bit として読むと上位バイトを拾って**きれいな 0** が返り、
> そのまま計算すると実効慣性比が全ギアぴったり 1.0 になって
> **「補正不要」という正しそうな答えに化ける**。実装ではここを明示的に弾いている。

物理的な裏取り: S54 の DMF ≈ 10.5 kg、回転半径 `k ≈ 0.115 m` なら `J ≈ 10.5 × 0.115² ≈ 0.139`。
残り（クランク＋等価往復系＋ダンパ）≈ 0.11。合計 ≈ 0.25 で較正値と一致する。

## 2. J_new の測り方 — 停車ニュートラル・ペダルスイープ回帰

### 2.0 ★ 訂正 — ブロック 83 は「ログできるチャンネル」ではない（2026-08-16）

**本節は当初、DS2 selection 83（EGAS）を単独ポーリングして `md_ind_opt_korr` と `d_n40` を
取る手順だった。その手順は実行不可能である。**

selection 83 は**ライブテレメトリではなく、EGAS 故障のフリーズフレーム**である。逆アセンブルの証拠:

| 場所 | 内容 |
|---|---|
| master `0x030B84` の 0x53 分岐 → `0x031198` | `movea.l #$ffda48,a1` ＋ 52 バイトコピー |
| master `0x024A66`（唯一の書き手） | `tst.b (a1) / bne.w $24b82` → **バイト 0 が非ゼロなら書かない**、次に `move.b #$1,(a1)` |
| master `0x024B82` | `cmpi.b #$ff,(a1) / addq.b #$1,(a1)` — 2 回目以降は**カウンタを増やして戻るだけ** |
| master `0x03079C` | 52 バイト専用クリアルーチン |
| 参照カタログ | バイト 0 の名前は `freeze_flag`「EGAS event counter」 |

**∴ 故障が起きていない車では 52 バイトすべてゼロのまま、何 Hz でポーリングしても変わらない。**
実際、この設計で記録した測定は「265 サンプル受信・265 サンプル棄却」で終わった。

**ライブのトルクを取る手段はブロックには存在しない。**8 ブロックのうち `md_*` を持つのは 83 だけで、
唯一の例外 `md_llri`（block 19 off 77）はアイドル I 項である。

### 2.0.1 ★ 置き換え — DS2 `0x06` はマスタの **ライブ RAM** を読める

トルクは RAM から直接読む。DME は `flash_req_parse`（master `0x00289C`）で
**master `0x3AD6` の領域テーブル**（65 エントリ × 10 バイト、`{id, variant, lo, hi}`）を引いて
アドレスを解決する。そのうち 4 つが RAM 窓である:

| segment | 範囲 | 中身 |
|---|---|---|
| **`0x01`** | `0x00FF8000`–`0x00FF8FFF` | `MD_IND_NE` `MD_DYN_ST` `SA_WE_ST` `GANG` `MD_MOTOR` `V` |
| **`0x04`** | `0x00FFD000`–`0x00FFEFFF` | `MD_FW` `MD_FW_FILTER` `MD_LS_DELTA` `MD_DP_DELTA` `MD_IND_OPT_KORR` `N` `RF` `TMOT` |

**エンジン稼働中に安全である根拠は 3 つ、すべて逆アセンブル由来:**

1. **ハンドラは単なるバイトコピー。** segment `0x01`/`0x04` は `0x001FD8` に分岐し、
   領域の境界チェックのあと `count` バイトを応答バッファへ写すだけ。LOGIN もプログラミングモードも
   状態変更も無い（唯一の例外: `0x4000`–`0x4018` の 25 バイトは `0xFF` で返る）
2. **ゲートがライブ値より緩い。** アプリのコマンド表（master `0x3A1F0`）は
   `mask & $ffd003 == 0` で許可を出す。selection 読み（`0x0B`）は mask `0xA0`、
   メモリ読み（`0x06`）は mask `0x20`。**`0xA0` が 0 なら `0x20` も必ず 0** なので、
   `pollLiveMeasurement` が動く状況では必ず動く
3. **本ツールの READ が既にやっている。** 32 KB × 2 の読み出しは LOGIN 無しの `0x06` である

**アドレスとスケーリングの出典は同一。** フリーズフレーム書き込み `0x024A66` が
RAM から block 83 の各オフセットへ**逐語コピー**しており、参照カタログの型がそのまま RAM の型になる:

```
0x024B28:  move.w $ff81a6.l, $26(a1)     MD_IND_NE       -> block 83 offset 38  (uint16 x 0.1 Nm)
0x024B30:  move.w $ffd8e6.l, $28(a1)     MD_IND_OPT_KORR -> offset 40           (uint16 x 0.1 Nm)
0x024B60:  move.b $ff8180.l, $30(a1)     MD_DYN_ST       -> offset 48
0x024B78:  move.b $ff8247.l, $33(a1)     SA_WE_ST        -> offset 51
```

**制約**:

- **count は 128 バイトで頭打ち**（`0x002A16: cmpi.l #$80,(a3)`）。超えると**エラーにならずに切り詰められる**
- **アトミックではない。** バイト単位コピーなので 16 bit 変数の上下バイトが割れうる。外れ値棄却が要る
- **スレーブ RAM（segment `0x08`/`0x0B`）はこの較正では拒否される。**
  `0x001FD8` が master `0x3FFC` を `'M'` と比較し、本イメージは `4D 4D`（"MM"）
- **実車での確認が必要。** 上記はすべて静的解析である。ツールは**非破壊プローブ**
  （`0xFF81A6` を 2 バイト読むだけ）を測定開始のゲートにしている。拒否されるときの応答は `0xB0`

### 2.1 原理

停車・ニュートラルではエンジンがプラントの全部になる:

```
M_ind(n) = J·α + M_loss(n)          α = dω/dt [rad/s²]
```

回転数を 500 rpm のビンに分け、**ビンごとに `md_ind_ne` 対 `α` を線形回帰**する。
**傾きが J、切片が M_loss(n)。**

ビン分割が効いているのは、**ビン内では M_loss が定数なので切片に落ちる**点である。
摩擦・ポンプ損失のモデルが一切要らない。**これが重要なのは、DME の引きずりトルク信号が
使い物にならないから**である — `MD_IND_SCHLEPP` は
`(MD_MIN_F_LLRA * (MD_LLRA_KO + MD_LLRA)) >> 10` を 0 でクリップした値で
（`MD_Minimum_Moment`、master `0x017542`）、**アイドル学習適応から作った推定値であって
回転数分解された摩擦曲線ではない**。これを `M_loss(4000 rpm)` として使うと
そのモデル誤差がそのまま J に乗算で乗る。

**そして J は回転数に依存しない。** だから**ビン間で J が一致すること自体が手順全体の検証になる**。
ばらついたら測定が壊れている（後述の `jSpread`）。

> **`md_ind_opt_korr` ではなく `md_ind_ne` を使うこと。** 前者は**最適点火時**の指示トルクで、
> `md_eta_calc`（slave `0x0155AA`）が点火効率 `ETA_NE` を掛けた後者が実際に出ているトルクである。
> `KL_DYN_TZ_DBGR` は速いティップインで 3〜12 °KW 引くので、**前者はスイープの立ち上がりで過大に出る**。

### 2.2 なぜ「停車」なのか

ティップイン／ダッシュポットのスルーレートリミッタは
**`K_MD_DF_VMIN` = 3 km/h 未満でバイパスされる**（`45-drivability-filters.md` §1）。
つまり停車していればトルク要求は素通しで、`md_ind_ne` はフィルタのランプではなく
**エンジン自身の曲線の上に乗る**。変数をモデル化するのではなく消している。

それでもサンプルごとに `md_dyn_st` を見る。「バイパスされるはず」と「バイパスされた」は別の主張である。

> **★ ギア・車速・エンジン状態のゲートは無くなった。** `gang` / `v_antrieb` / `zustand_motor` は
> フリーズフレーム側の信号で、1 テレグラムでは取れない。代わりに効くのは:
>
> - **ギアが入っていれば J は桁で外れる。** `KL_MD_JFZ_GANG` は 1 速 0.701、6 速 12.0 Nms²
>   に対しエンジン単体は約 0.21。妥当性レール（0.10–0.35）が余裕を持って捕まえる
> - **`md_dyn_st` は毎サンプル見ている。** 停車では立たないはずなので、立てば走っていた証拠
> - **停車・サイドブレーキは手順であって検査ではない。** そう書いてある

### 2.3 操作

- **ブロック 3 ＋ RAM 読み 1 回**（`0x06`, segment `0x01`, `0xFF8180`, 40 バイト）。
  `n` は **1 rpm 分解能**で、`n40` の 40 rpm より 40 倍細かい
- **暖機**（水温 **80 °C 以上**）、**ニュートラル、停車、サイドブレーキ**
- ペダル **15 / 20 / 30 / 40 %** で **2000 → 5000 rpm** まで吹かし、
  **全閉にして 2000 rpm まで落ちるのを待つ**。これを **6 回**
- **落ちる途中でアクセルに触らない**

> **★ 惰性降下は「検算」ではなく「測定の半分」である（2026-08-16 訂正）。**
> 燃料カット中 `md_ind_ne` は **0**（このチャンネルは符号無しなので負にならない）。
> **トルク 0 かつ大きな負の α** という点は、ペダルスイープがどれだけ多くても到達できない
> 回帰直線のもう一方の端である。当初の設計はこれを `fuel-cut` ゲートで**全部捨てていた**。
> 捨てると各ビンは似た点の塊に直線を引くことになり、傾きと切片を分離できない。

> **★ 全開禁止・上限 30 % という制約は消えた。** これは `d_n40` の ±5080 rpm/s 飽和を
> 避けるための制約だった。`n` は 1 rpm の単なるカウンタで飽和しない。
> 40 % まで使ってよい（開度の広がりが回帰の spread そのものなので、むしろ望ましい）。

### 2.4 検算 — 無負荷自由降下

トルク 0 の区間では `J·α = −M_loss(n)`。回帰から出た `J` と `M_loss` が予測する勾配と、
実測を照合する。判定は `sa_we_st` のビットではなく **`md_ind_ne` が 0 であること**で行う
（燃焼トルクが無いことが、予測が語っている条件そのものだから）。

> **この検算が見つけられないもの**: `md_ind_ne` にスケール誤差 `k` があると
> **J も M_loss も同じ `k` 倍**になり、この式では `k` が約分されて消える。
> §4.3 参照。

## 3. ★ 測った比をどこに掛けるか — クラス分け

**これが本文書の中心。全部に同じ係数を掛けてはいけない。**

| クラス | 見ている慣性 | 係数 |
|---|---|---|
| **A** | エンジン単体（クラッチ切・N・アイドル） | **× r** |
| **B** | エンジン＋車両（ギヤが入っているときのみ作動するもの） | **× r_eff(gang)** |
| **C** | J が ECU の式の分母そのもの | **J から直接** |
| **D** | 慣性効果ではない | **係数なし** |

> **★ 訂正（2026-09-05）— クラス分けが 2 件間違っていた。**
> `K_N_TAU_DN` はクラス A に置かれていたが、**時定数であって慣性項ではない**。
> フィルタに J は入っておらず、周囲のラグ（10 ms タスク・20 ms タスク・`K_LLS_TAU2`・
> 吸気→トルク遅れ）もフライホイール交換でスケールしない。**クラス D。**
> `KL_DYN_TZ_DBGR` も同じ理由でクラス D — こちらは**角度クロック**（クランクセグメント数で
> 持続を数える）なので、回転が上がれば壁時計時間が自動で縮み、`r` の入る余地が構造的に無い。
>
> **クラスを間違えるとは、補正則を間違えるということ**である。`K_N_TAU_DN` は
> クラス A に置かれていたせいで `current * r` になり、再測定のたびに値が下がるラチェットを
> 起こしていた（§7.3）。

### 3.1 ★ クラス B — ギヤが入っていると比は 0.82 ではない

`KF_MD_LS_KOMF` / `KF_MD_DASHPOT*` は 3 km/h 未満でバイパスされる。
**∴ ギヤが入って走っているときしか効かない。** そのときのプラントは `J_eng + J_fz(gang)`。

`KL_MD_JFZ_GANG`（master `0x955E`、y `0x956E`、16 bit、`X/268`）＝ **BMW 自身の
クランク軸換算車両慣性**:

| gang | 0 (N) | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| `J_fz` [Nms²] | 0.0 | **0.701** | **1.601** | **3.399** | **5.0** | **8.0** | **12.0** |

`r_eff(g) = (J_new + J_fz) / (J_old + J_fz)`、J_old = 0.2687、r = 0.82 のとき:

| ギア | **r_eff** |
|---|---|
| N / 停車 | **0.820** |
| 1 | **0.950** |
| 2 | **0.974** |
| 3 | **0.987** |
| 4 / 5 / 6 | **0.991 / 0.994 / 0.996** |

> **`lightweight_flywheel_tuning.md` §1.1 の `KF_MD_LS_KOMF` × 0.82 は、
> 慣性の議論としては 4〜20 倍の過補正である。**
> 正しくは 1 速 ×0.95、2 速 ×0.97、3 速以上はほぼ ×1.00。

**さらに: `KF_MD_LS_KOMF` にはギア軸が無い**（軸は `md` × `n`）。
ギア依存は**別テーブル `0x927C`（段別係数、XDF 未定義）**にある。
∴ **r_eff は rpm×負荷マップではなく段別係数テーブルに掛けるのが軸的に正しい。**
rpm×負荷マップはログが指した症状セル用に温存する。

駆動系諸元も全部 slave にあるので検算できる:
`K_SMG_I_GANG_1..6`（`0x28CD`–`0x28D2`、`X/60`）= 4.2333 / 2.5333 / 1.6667 / 1.2333 / 1.0 / 0.8333、
`K_SMG_I_HA`（`0x28CC`）= 3.6333、`K_SMG_R_RAD_DYN`（`0x280C`、16 bit、`X/10`）= 307 mm。
質量 1450 kg で手計算すると 2–3 速が BMW の表と一致する。

### 3.2 ★ クラス C — `K_SMG_J_MOTOR` は物理定数ではなく「つまみ」

機構は `d2 = min(指令スルーレート, T / K_SMG_J_MOTOR)`（`80-smg-shift-tuning.md` §3.5）。
唯一の消費者 `smg_shift_deltaN_request_update`（slave `0x038314`）の**呼び出し元は 2 つ**:

- `smg_shift_reg_prestep_flatten_profile`（slave `0x0377AE`）
- **`smg_shift_phase3_clutch_reengage_regulator`（slave `0x037C6A`）** ← クラッチ再係合

**∴ ブリップだけでなく、発進と変速のたびに効く。**
0.25 → 0.20 は再係合レギュレータの許容スルーレートを **+25 %** にする。

> **重要な反転**: 0.20 は物理値としてはむしろ正しい（ΔJ ≈ −0.045 → 0.205）。
> つまり**「実物理値に合わせたこと」自体が症状を作りうる**。
> 純正 0.25 はレートクランプとして意図的に保守的で、較正の他の部分はその平滑化を前提に
> 合わせ込まれている。
> **∴ このパラメータは「正確にすべき物理定数」ではなく「再係合の穏やかさのつまみ」として扱う。**

症状が **発進直後・低速からの踏み込み**／**変速直後の踏み足し**なら、
どちらも再係合イベントなので**まずここを純正へ戻す 1 行の A/B が最短**。

### 3.3 クラス D — 慣性では説明できないもの

| 対象 | なぜ係数が無いのか |
|---|---|
| **DMF ダンパの喪失** | 慣性ではなく**バネと減衰**。駆動系シャッフルモードが +8〜10 % 上がり、減衰要素が消える。どんな比を掛けても戻らない。**4–10 Hz は DS2 では測れない**（最速の 1 ブロックでも Nyquist ≈ 5 Hz）。加速度計以外に手段が無い |
| 失火しきい値 | 本物の失火の偏差も健全時のばらつきも**同じ 1/J** で増える。「慣性比のぶん上げる」は論法として成立しない |
| ARF | `K_AR_TMOT_MIN` = 130 °C の到達不能ゲートが残り、`MD_AR` の読み手が復元コードに存在しない |

## 4. 測定側の制約 — 正直に書く分

### 4.1 ★ 取り下げ — `d_n40` の打ち切り補正はもう要らない（2026-08-16）

**当初の §4.1 は `d_n40` の非対称な打ち切り誤差の補正を定義していた。その節はまるごと不要になった。**

`d_n40` は selection 83 の信号で、その block は §2.0 のとおり更新されない。置き換えた
selection 3 の `n` は **1 rpm 分解能の符号無し 16 bit カウンタ**で、派生量が一切入っていない。
中心差分すれば不偏で、飽和もしない。

∴ 以下は**すべて削除**された:

| 消えたもの | それが守っていたもの |
|---|---|
| 打ち切り補正（正: 補正なし／負: −40／ゼロ: −20） | `d_n40` の `(D_N_SEGMENT + 0x14) / 0x28` を 0 方向へ切り捨てる実装 |
| 飽和棄却（±5080 rpm/s） | 符号付きバイトのレール |
| 2 系統勾配の一致要求 | どちらのチャンネルも単独では信用できなかったこと |
| 「ペダル上限 30 %」 | 上の飽和を避けるための操作制約 |

**記録として残す価値のある事実**（`d_n40` を別用途で読むときのために）:
`D_N40 = (D_N_SEGMENT + 0x14) / 0x28` は 0 方向へ切り捨てるので、`trunc((x+20)/40) = k` の解は
`k>0` で `[40k−20, 40k+20)`（中点＝報告値）、`k<0` で `(40k−60, 40k−20]`（中点＝報告値−40）、
**`k=0` で `(−60, 20)` という二重幅の不感帯**（中点 −20）になる。正側は既に不偏で、
「丸め誤差だから両側補正」は正側に無い偏りを作る。

### 4.2 その他

- **アトミックでない読み。** `0x06` のハンドラはバイト単位コピーなので、10 ms タスクが
  16 bit 変数を更新している最中に読むと上下バイトが割れる。0.1 Nm/LSB で割れると数千 Nm に
  飛ぶので、**外れ値棄却が必須**
- **2 テレグラムのスキュー。** ブロック 3 と RAM 読みの間は 9600 baud で約 20 ms。
  タイムスタンプは 2 回目の後に取るので、**スキューは毎サンプル同じ定数**であり
  ばらつきではない。定数ずれは切片に乗るので `M_loss` の妥当性レールが見える位置にあるが、
  ばらつきなら傾きに乗って何にも見えなかった
- **勾配窓とトルクは同じ区間の平均で対にする。** `J dω/dt = M − M_loss` を区間で積分して
  区間長で割ると `J·ᾱ = M̄ − M̄_loss` になる。中心差分は**区間平均の α** なので、
  相手は**区間平均のトルク**でなければならない。中心サンプルのトルクと対にするのは
  トルクが一定の場所でしか正しくない近似で、ベンチでは J が **6.5 % 低く**出た（平均に直して 2 % 未満）
- **スロットルの開閉を跨いだ窓は捨てる。** その窓は 2 つの regime を平均していて、
  平均はどちらの曲線の上にも無い。スイープあたり 2〜3 点で、ビンの傾きを引っ張るには十分
- **サンプルレートは実測して記録する。** 理論値を書かない。2 テレグラムで 9600 baud、
  実測期待値は約 5 Hz

### 4.3 ★ この手順が原理的に見つけられない誤差

`md_ind_ne` は**モデル出力**であって測定値ではない。DME が実測充填と点火効率から計算している。
モデルに乗算的な誤差 `k` があると:

- 傾き（J）も切片（M_loss）も**同じ `k` 倍**になる
- **自由降下の検算でも `k` は約分されて消える**

測定領域はこの `k` を小さくするように選んである — 暖機後・閉ループ・停車なので、
λ は閉ループで 1 に補正され、`rf_korr` は恒等列に乗る。
だが**測っているわけではない**。

押さえられるのは **`M_loss(4000 rpm)` が S54 のモータリングトルク（およそ 20〜80 Nm）に
収まるか**という物理的な事前分布だけで、これは `k` を ±30 % 程度にしか縛れない。

> **∴ `J_new` の絶対値は「モデルが正しければ」付きの数値である。**
> 各パラメータの最終値は**ログでの A/B が決める**。提案値は出発点であって答えではない。

## 5. 既存 VE チューニングとの切り分け

### 5.1 ログは型で分ける

2 つのログは互いに使えない:

| | VE ログ {3,19} | 慣性ログ {83} |
|---|---|---|
| 持っている | `rf`, `aq_rel`, `tabg`, `tmot`, `la_f_regler1/2` | `n`(1 rpm), `tmot`, `wdk1`, `md_ind_ne`, `md_dyn_st` |
| 欠けている | 慣性側の全部 | **`tabg` も `la_f_regler` も `aq_rel` も無い** |

実装では**別の型**にしてある（`LiveMeasurement` と `EgasMeasurement`）。
フラグではなく型なので、取り違えは**コンパイルエラー**であって
「もっともらしい間違った答え」にはならない。

### 5.2 ★ イメージの切り分け — ここだけが本物の競合

**書き込みは常に 65536 バイト全体である。**
`writePartialBinInner` はそれ以外の長さを拒否し、データ領域全体を消去してから書き直す。
**∴ 領域による住み分けは成立しない。**

```
BASE_A ─┬─ VE セッション    → TUNED_VE     （Alpha-N だけ変更）
        └─ 慣性セッション   → TUNED_INERTIA（Momentenmanager/SMG だけ変更）

TUNED_VE を書き込み → 車は VE 済み
TUNED_INERTIA を書き込み → 64 KB 全上書き → ★ VE の変更が完全に消える
```

**アドレスが 1 バイトも重なっていないのに全部消える。**
しかも両方のセッションが「自分は少ししか変えていない」と表示するので、**差分を見ても気づけない。**

対策は書き込み直前の**系譜チェック**:
ECU が保持している 2 つの CRC（slave `0x3FFC` / master `0xBFFC` の格納値）を読み、
セッションの BASE のそれと突き合わせる。**8 バイト、2 交信**。
64 KB 再読み込みは 9600 baud で約 123 秒かかり、**毎回のフラッシュを倍にする安全チェックは
やがて切られる**ので、この形にしてある。

残る риск は CRC 衝突（ペアで約 2³²分の 1）。
「間に別のものを焼いたか」という実際の問いには十分で、偽造への防御ではない。

正しい進め方は**直列**:

```
フラッシュ → 再 READ → その READ を BASE に次のセッション
```

skill が警告している **stmts=0 の罠**そのもの。

**本当の理由はこちら**: ゲートを開けると**両側の制御則が同時に立ち上がる**。
上向きの `KL_LFR_TZ_POS` は**既に完全較正済み（最大 15 Nm）**で今日死んでいるだけなので、
`KL_LFR_TZ_NEG` に何を書くかと無関係に効き始める。
∴ **ゲートだけを先に単独で書く**のが安くて情報量が多い。「ゲートは開いたか」と
「ランプの形は正しいか」を別のログに分けられる。

**F4 は 4/5/6 速を含めてはいけない** — §7.1 の燃料カット崖。

**F5 は束ねてはいけない** — 軸を動かすと隣接セルの意味が全部変わる。

| `KL_SMG_MOT_J_MOTOR` (0x2ACC) | **用途は回収済み。** `smg_vehicle_dynamics_observer_update` が `smg_mot_j_motor`（0xFFDBDA）に書き、`smg_dn_regulator_update` が `039082: muls.w $ffdbaa,d0 / asr.l #7` で**勾配をフィードフォワードトルクに換算**する。`K_SMG_J_MOTOR` が上限を決め、こちらが値付けする — **対**。**片方だけ下げたのが今回の症状の最有力原因。**「変更しない」は既定のままだが、理由は「未回収」ではなく「相互作用する 2 つ目のつまみ」 |
| `K_WE_DN40_HARD` (0x0E1E) | −5000 rpm/s。下限 −5120 まで **3 段**の余地はあるが（旧記述の「1 段」は誤り）、hard/soft 分岐の意味を変えるので触らない |
| `KL_SA_N40_GANG` index 1–6 | in-gear は車両慣性が支配的で比がほぼ 1 |
| `KL_LFR_TZ_POS` (0x9CA4) | 既に完全較正済み（5 rpm で 2.0 Nm、30 rpm で 15 Nm）。**死んでいるのはゲートのせい**であって値のせいではない |
| `K_SMG_R_RAD_DYN` (0x280C) | `K_SMG_J_MOTOR` の 2 バイト隣。誤爆注意 |
| 失火しきい値 | 本物の失火偏差も同じ 1/J で増えるので「慣性比のぶん上げる」は成立しない |
| DMF ダンパ関連 | バネと減衰の喪失。係数では戻らない。4–10 Hz は DS2 で測れない |

## 8. 検証ログと合否基準

| 群 | 操作 | 見る信号 | 合否 |
|---|---|---|---|
| **F1** | **3 速以上の惰行ダウンシフト ×20** | `d_n40`(RAM `0xFF805E`)、`gang`(`0xFF8250`)、`sa_we_st`(`0xFF8247`) — すべて seg 0x01 | 再係合時の `d_n40` ピーク中央値が **8 カウント（1723→1400 rpm/s）** 下がる。**`sa_we_st` bit3 が立ったイベントは除外**（`0391da/0391e4` の 2 ビットが揃うと加算が丸ごと飛ばされる） |
| F2（SA/WE） | クラッチを切って惰行 ×6 以上 | `sa_we_st` bit3 が落ちた瞬間の `N40`(RAM `0xFFEDD0`, seg 0x04) | **+80 rpm ＝ 2 カウント**。`d_n40` がレールに乗ったイベントだけを採る |
| F2（勾配） | アイドルへの復帰 | `D_N_GEFILTERT`(RAM `0xFFEC9E`) と入力の `D_N_SEGMENT`(`0xFF805A`) | フィルタ出力の立ち上がりが速くなる。落ち込み深さの差は 8〜13 rpm しかない |
| **F3** | **停車・暖機・ステアリングをフルロックまで** | `MD_RES_LRW_ST` bit1(RAM `0xFFD910`)、`MD_LLR_TZ`(`0xFF8240`)、`LWS_LRW`(`0xFF81B8`) | 520 度超で **bit1 が立つ**。bit0 は停車していれば書き込み前から立っているので判定に使えない |
| F4 | 1・2 速 1500–2000 rpm で 1/3 踏み増し | `MD_FW`(`0xFFD8B0`) / `MD_FW_FILTER`(`0xFFD8B2`) / `MD_LS_DELTA`(`0xFFD8B8`)、`SCHALT_M_ST`(`0xFFEDE0`) bit0 | 入力と出力の差が縮む。**`MD_LS_DELTA` 単体で 5 % を証明しようとしない** — 4 項の積なのでばらつきに埋もれる |
| 全群 | 各群の後 | block 179 `lu[0..5]` | 失火マージンの再確認。最初に出やすい DTC は **D5** |

> **★ 訂正（2026-09-05）— 旧版の合否基準の半分は実行不可能だった。**
>
> 1. **信号が block 83 から読めない。** selection 83 は EGAS フォールトのフリーズフレームで、
>    健全な車では 52 バイトのゼロが永久に返る（§2.0）。旧表の `n40` / `md_ind_wunsch` /
>    `gang` / `s_krafts` / `md_dyn_st` はすべてそこから読む前提だった。
>    **上の表は全部 RAM 直読み（DS2 `0x06`）に置き換えてある。**
> 2. **F1 の「発進」は効かない場面。** `K_SMG_J_MOTOR` はシフト相 3–4 でしか作用しない
>    （`0x03A23A` の case 1 が別ハンドラ、`0x037832` が相を限定）。旧版の操作指示は
>    **この定数が効かない場面ばかりを見ていた**。
> 3. **F2(SA/WE) の「二段しゃくりの消失」は達成不能。** 2 段目は `KF_MD_WE` の 0 % 列で決まり、
>    1500/2500/6000 rpm 行がバイト一致なので、しきい値が 2080 でも 2160 でも同じセルを読む。
> 4. **F3 の操作が違った。** 「ブリップ後の回転落ち」ではなく**据切り**。
>    権限が使えるのは `K_LFR_V_MAX` = 2 km/h 以下だけ。

> **★ 訂正（2026-08-16）— `MD_LS_DELTA` は読める。**
> 「どのブロックにも載っていないので `md_dyn_st` bit6 が唯一の直接証拠」と書いていたが、
> *ブロックに* 載っていないだけで RAM にはある。DS2 `0x06` の segment `0x04` で
> `MD_LS_DELTA`(`0xFFD8B8`) と `MD_DP_DELTA`(`0xFFD8BA`)、さらに**フィルタの入力と出力**
> `MD_FW`(`0xFFD8B0`) / `MD_FW_FILTER`(`0xFFD8B2`) が 1 テレグラムに収まる。
> ∴ **F4 の検証は推定ではなく直接測定になる** — 入出力を同時に見て差を取るだけ。
> bit6 は依然として有用だが、もはや唯一ではない。

## 10. 確立できなかったこと

| 項目 | 状態 |
|---|---|
| **`md_ind_ne` の絶対確度** | モデル出力なので乗算誤差 `k` が J に 1:1 で乗る。自由降下の検算でも約分されて検出できない。`M_loss` の物理的妥当性で ±30 % 程度にしか縛れない（§4.3） |
| **`0x06` RAM 読みの実車確認** | 領域テーブル・ハンドラ・コマンドゲートはすべて逆アセンブル由来で、この車では未実行。ツールは非破壊プローブを測定開始のゲートにしている（§2.0.1） |
| **純正フライホイールでの `t_old`** | 交換前のログは存在しない。本手順が絶対 J を出すのはそのため — 比を取る相手が無いから |
| **DMF ダンパ喪失の定量** | 4–10 Hz は DS2 で測れない。加速度計を付けるか、`KF_MD_LS_KOMF` の症状セルを実走で詰めるかの二択 |
| **`KF_MD_LS_KOMF` と `KF_MD_LS_SPORT` のどちらが使われているか** | `0x172C4: btst.b #$0,$ffede0 (SCHALT_M_ST)` が選ぶ。**手で編集した KOMF が経路に入っていない可能性がある。** 走行前に `SCHALT_M_ST` をログすれば 1 分で決着する |
| **`KL_MD_LS_W_GANG` を r_eff で補正してよいか** | `r_eff` は慣性比で、それをトルク**レート**リミッタに掛けている。純正の形（1.00/0.75/0.80/0.90…）はギアのトルク倍率を追っており慣性を追っていない。リミッタが守るのはクラッチを越えるトルクの**速度**。**バイナリはこの選択を裁定しない — ツール側のモデリング判断である** |
| **2 テレグラム構成の実測レート** | 未実測。**理論値を書かない** — 9600 baud で約 5 Hz の見込みだが、60 s ログのタイムスタンプ**平均**差から出して、ここに記録すること。中央値ではない — 分布が二峰で、実測 2940 サンプルのランでは中央値 8.8 Hz に対し平均 6.6 Hz だった |
| **MT 車での有効性** | SMG 経路は `cfg_s.getriebetyp == 0x40` でゲートされ、`smg_can_istgang` を CAN から取る。フレームが無ければ SMG 側は死にコード |
