# 第 1 部 — エンジンの中で何が起きているか

## 1.1 DME は 2 つの別々の仕事をしている

アイドリング中、DME は次の 2 つを**同時に、しかし別々の仕組みで**やっている。

| | 仕事 | 決めるもの |
|---|---|---|
| **仕事 A** | 空気を **どれだけ入れるか** を決める | **回転数** |
| **仕事 B** | 入った空気が **どれだけだったか** を見積もる | **燃料** |

この 2 つは直接つながっていない。**唯一のつながりは、実際のエンジンという物理そのもの**である。
仕事 A がバルブを開ける → 空気が入る → 仕事 B がその開度から空気量を見積もる。

チューニングで迷子になるのは、ほぼ必ずこの 2 つを混同したときである。
「アイドルが不安定だから燃調を直す」は間違い。**燃調は仕事 B、アイドルの安定は仕事 A** である。

## 1.2 仕事 A ― 空気を入れる側

### 1.2.1 目標回転数を決める

`KL_LFR_NSOLL_GRUND` という 4 点のカーブが、水温から目標回転数を出す。

| 水温 | −30 °C | 20 °C | 50 °C | 80 °C |
|---|---|---|---|---|
| 目標回転 | 1050 rpm | 920 rpm | 870 rpm | **870 rpm** |

アドレスは X 軸 `0x9A64`、Y 軸 `0x9A6C`。16 bit、そのまま rpm。

これに始動直後のオフセット（`KL_LFR_NSOLL_OFFSET`、始動後 60 秒保持してから
毎秒 0.977 rpm ずつ減衰）や、A/C 要求時の下限（`K_LFR_NSOLL_AC` = 870 rpm）が
**MAX セレクト**で重なる。つまり「一番高い要求が勝つ」。

### 1.2.2 目標との差を、トルクの要求に変える

実回転が目標より低ければ、DME は「もっとトルクが要る」と判断する。この判断をするのが
**LFR（Leerlaufregelung in Momentenstruktur）**、20 ms 周期の閉ループ制御器である。

出力は **トルク [Nm]** であって、空気でも点火時期でもない。MSS54HP はすべての制御要求を
一度トルクに変換してから、モーメントマネージャがそれを空気・点火・燃料に配分する。

LFR の中身:

| 項 | パラメータ | この車の値 |
|---|---|---|
| **P（比例）** | `KL_LFR_DQP_POS`（X `0x9ABE` / Y `0x9ADE`、16 点、`x/80` Nm） | 回転落ち **60 rpm までは 0**。80 rpm で 0.5 Nm、300 rpm で 9 Nm |
| **I（積分）** | `KF_LFR_DQI`（Z `0x9BB2`、15×8、Nm/秒） | — |
| **点火（速い枝）** | `KL_LFR_TZ_POS` / `KL_LFR_TZ_NEG` | 後述（1.2.5）。この車では **アイドル中は不活性** |

**P 項に 60 rpm の不感帯がある**ことは覚えておく価値がある。60 rpm 落ちるまで、
比例的な即応は一切かからない。それより小さい落ち込みは、遅い積分だけが戻す。

### 1.2.3 トルクの要求を、空気の要求に変える

モーメントマネージャがトルク要求を空気質量の要求 `ML_SOLL_DPR` [kg/h] に変換する。

### 1.2.4 空気の要求を、アイドルバルブとスロットルに配分する

ここが構造上いちばん大事な分岐である。`egas_compute_throttle_target`（master `0x0270B0`）:

```
ML_SOLL_LLS = min(ML_SOLL_DPR, ML_SOLL_MAX_LLS)          ← アイドルバルブの取り分
ML_SOLL_WDK = PT1(max(0, ML_SOLL_DPR − ML_SOLL_MAX_LLS)) ← 余りがスロットルの取り分
```

**アイドルバルブが先に食い、あふれた分だけがスロットルに回る。**
`ML_SOLL_MAX_LLS` は `KL_LFR_SOLL_MAX_LLS`（X `0x9A32` / Y `0x9A3E`）から作られ、
600 rpm で 34 kg/h、900 rpm で 46 kg/h。アイドルの要求（後述、約 19 kg/h）はこれをはるかに
下回るので、**アイドル中の空気は事実上すべてアイドルバルブが供給している。**

### 1.2.5 空気の要求を、バルブの開度指令に変える

`KF_LLS_TV`（X `0x9DE2` = rpm、Y `0x9DF6` = kg/h、Z `0x9E10` = デューティ %、13 行 × 10 列）。

この車の値（低 kg/h 側の抜粋、870 rpm を挟む 800 / 950 rpm 列）:

| Y（要求空気） | 800 rpm | 950 rpm | 参照 BIN（800 rpm） |
|---|---|---|---|
| 11 kg/h | 21.0 % | 21.0 % | 14.0 % |
| 15 kg/h | 30.0 % | 30.0 % | 23.0 % |
| 20 kg/h | 40.0 % | 40.0 % | 33.6 % |
| 25 kg/h | 45.0 % | 44.0 % | 38.0 % |

**この車のバルブマップは参照より一律 6〜7 ポイント開いている。** これは後で効いてくる。

出た値は一次遅れ（`K_LLS_TAU2` = 32、約 80 ms）を通り、14 %（`K_LLS_TV_MIN`）と
97 %（`K_LLS_TV_MAX`）でクランプされ、PWM としてバルブに出る。

**`KF_LLS_TV` は純粋なフィードフォワードである。** マップを引いてからバルブに出るまでの間に、
回転数の誤差も積分項も一切足されない（`lls_tv_calc` master `0x025D0A` の全命令を確認済み）。

### 1.2.6 点火による速い戻しは、この車のアイドルでは効かない

LFR には点火時期を直接動かす速い枝がある（`KL_LFR_TZ_POS` / `KL_LFR_TZ_NEG`）。
ところがその出力は次のように潰される:

```
lfr_calc 0x026A4C:  btst.b #1, MD_RES_LRW_ST     ← パワステ負荷予約のフラグ
         0x026A54:  beq  → 0x026A6A
         0x026A6A:  clr.w MD_LLR_TZ               ← 無条件でゼロ
```

`MD_RES_LRW_ST` bit1 は `KL_MD_RES_LRW`（`0x97D8`）が非ゼロを返すときだけ立つ。
**この車の X 軸は 460 / 490 / 500 / 520 deg** —— ステアリングをロック手前まで切った状態である。

> **結論**: 直進の停車アイドルでは `MD_LLR_TZ` は常に 0。**点火による速い戻しは存在しない。**
> 回転が上がりすぎたときも下がりすぎたときも、戻すのは遅い積分だけである。

## 1.3 仕事 B ― 空気を測る側

### 1.3.1 この DME にエアフロメーターは無い

`k_rf_cfg`（`0xE5E4`）はこの BIN で `0x02`。HFM（エアフロ）ビットも MAP 直接ビットも
MAP 積分ビットも立っていない。**空気量は完全に「開口面積の計算」から出る。**

### 1.3.2 開口面積を足す

```
AQ_ABS = AQ_ABS_LLS + KL_AQ_ABS_WDK(WDK_SEGM)
         ↑バルブ分      ↑スロットル分
```

バルブ分は `KL_AQ_ABS_LLS`（X `0xE014` / Y `0xE024`）がデューティから引く:

| デューティ（raw / %） | 400 / 8 % | 1000 / 20 % | 1500 / 30 % | 2500 / 50 % | 3500 / 70 % |
|---|---|---|---|---|---|
| 面積 | 0 | 4 | 13 | 56 | 103 |

**この曲線は非線形で、30〜50 % の区間がいちばん急である。** デューティ 7 ポイントの差が
面積では 2 倍以上になる。

スロットル全開時の面積は 11781（`KL_AQ_ABS_WDK` の最終点）。

### 1.3.3 面積を相対値にする

```
AQ_REL = AQ_ABS / 11781 × 100    [%]
```

### 1.3.4 テーブルの Y 座標に変換する

```
aq_rel_rf = AQ_REL / kl_aq_rel_rf_fakt(N)
```

`kl_aq_rel_rf_fakt`（X `0xE058` / Y `0xE070`）は **除数**で、1.0 未満なので `aq_rel_rf` は
`AQ_REL` より**大きくなる**。

| rpm | 900 | 1100 | 1300 | 1400 | 1600 | 1800 | 2100 | 2400 以上 |
|---|---|---|---|---|---|---|---|---|
| 係数 | 0.700 | 0.700 | 0.750 | 0.800 | 0.850 | 0.900 | 0.950 | 1.000 |

### 1.3.5 Alpha-N テーブルを引く

`kf_rf_soll`（X `0xD2FE` = rpm、Y `0xD326` = `aq_rel_rf` %、Z `0xD356` = RF、24 行 × 20 列、`x/1000`）。

**これがこのツールが調整する主テーブルである。**

### 1.3.6 3 つの追加項と、温度・気圧補正

```
rf_soll_no_filter = kf_rf_soll(N, aq_rel_rf)
                  + (AVAN1_SOLL_FAKTOR × (kf_rf_soll_kath − kf_rf_soll)) >> 14   ← ① 触媒暖機ブレンド
                  + kf_rf_soll_ask(N, aq_rel_rf)                                 ← ② スノーケルフラップ
rf_soll_filter    = PT1(rf_soll_no_filter, τ)                                    ← ③ 一次遅れ
rf_soll           = (rf_soll_filter × RF_PT_KORR) >> 12
RF                = (rf_soll × rf_korr) >> 10
```

| 項 | 中身 | この車では |
|---|---|---|
| ① **触媒暖機ブレンド** | 冷間用の別テーブル `kf_rf_soll_kath`（Z `0xD770`）へ、係数 `AVAN1_SOLL_FAKTOR`（16384 = 全ブレンド）で線形に寄せる | 触媒暖機中のみ有効。第 4 部で扱う |
| ② **ASK 加算** | CSL スノーケルフラップが開いたときの加算 | **480 セル全ゼロ**。フラップ診断も削除済み → **フラップは無効化されている** |
| ③ **一次遅れ** | 上昇時 `kf_rf_soll_tau_up`、下降時 `k_rf_soll_tau_down` = 0.070 | 常時。**定常サンプルしか使えない理由** |
| `RF_PT_KORR` | `KL_RF_TAN_KORR(吸気温) × KL_RF_P_UMG_KORR(大気圧)` | 常時。#920 の条件（42–56 °C、959 mbar）で 0.98 前後 |
| `rf_korr` | 排気温度による増量。ゲートは `rf_soll > kl_rf_korr_rf_min` **かつ** `V > 20 km/h` | **停車中は常に 1.000** |

### 1.3.7 RF から先

```
RF ──→ TL = RF_TI_CONST × RF / 2000  ──→ TI（噴射時間）              燃料
   ──→ ML = N × (RF × m_norm / 1000) / 25000                        空気質量 [kg/h]
   ──→ KF_MD_MIN_LW_N_RF ほか（RF 軸のトルクモデル）                  トルク → 点火・EGAS
   ──→ KF_TI_N_RF（rf 軸）                                          低開度の増量行の選択
```

`m_norm` は `K_RF_HUBVOLUMEN`（`0xD21C` = 3.201 dm³）と `K_RF_LUFTDICHTE`（`0xD21E` = 1.136 kg/m³）
から作られ、**870 rpm・RF 100 % で 94.9 kg/h** に相当する。

> **重要**: `kf_rf_soll` を 1 セル動かすと、燃料だけでなく **空気質量の見積もりとトルクモデルも
> 同時に動く。** 「燃料だけ 1 % 濃くする」ことはこのテーブルではできない。

## 1.4 この車のアイドルを、数値で 1 本につなぐ

Session #920 の整定アイドル（578 サンプル）の実測中央値から、鎖全体を通してみる。

```
目標回転 870 rpm（KL_LFR_NSOLL_GRUND @80 °C）
   ↓ LFR が閉じて、空気要求 ML_SOLL ≈ 18.9 kg/h
   ↓ KF_LLS_TV(870 rpm, 18.9 kg/h) = 36.7 % デューティ
   ↓ KL_AQ_ABS_LLS(36.7 %) = 27.4         ← バルブ分
   ↓ + KL_AQ_ABS_WDK(0.9 %) = 8.2          ← スロットル分
   ↓ AQ_ABS = 35.6 → AQ_REL = 35.6/11781×100 = 0.30 %
   ↓                                実測 AQ_REL（rawLoad 中央値）= 0.317 %   ✓ 一致
   ↓ aq_rel_rf = 0.317 / 0.700 = 0.453 %
   ↓ kf_rf_soll(870, 0.453) ≈ 0.215
   ↓ × RF_PT_KORR ≈ 0.98
   ↓ 予測 RF = 22.07 %                実測 RF 中央値 = 22.0 %              ✓ 一致（比 0.998）
   ↓ ML = 94.9 × 22.0/100 = 20.9 kg/h
```

**両側とも実測と合う。** これが「アプリが読んでいる表と DME が読んでいる表が同じである」
ということの中身であり、1 バイトでも書く前に確かめるべき唯一の前提である。

参照 BIN の `KF_LLS_TV` で同じ計算をすると `AQ_REL` = 0.173 % にしかならず、実測の 0.317 % に
届かない。**つまりこの BIN のバルブマップが、実際に車で動いているものである。**

# 第 2 部 — 何が測れるか

書き込む値は、必ず「測れる何か」から出さなければならない。この車で測れるものは 4 つしかない。

## 2.1 λ トリム — `kf_rf_soll` の誤差そのもの

O2 センサーが実際の混合比を測り、DME は目標に合うよう噴射時間を補正する。その補正量が
`la_f_regler`（ログ列 `Lambda 1/2`）である。

**トリクが 1.00 でないということは、`kf_rf_soll` が今いるセルで間違っているということである。**
トリムが 0.98 なら、DME は燃料を 2 % 抜いている ＝ テーブルが空気を 2 % 多く見積もっている。

**この車の実測**（暖機後の整定アイドル）:

| | bank1 | bank2 |
|---|---|---|
| 暖機中（水温 51–80 °C） | 0.9674 | 0.9490 |
| 暖機後（水温 ≥ 85 °C） | **0.9978** | **0.9851** |

**測れないもの**:
- **空気の量**。トリムは混合比しか語らない。
- **λ ループが開いている間のこと。** 冷間始動直後、全開、ティップイン、オーバーラン復帰では
  トリムは存在しないか凍結している。

## 2.2 `MD_LLRA`（需要適応）— `KF_LLS_TV` の誤差そのもの

LFR には長期学習がある（`lfra_adapt`、master `0x025B52`）。定常アイドルで I 項が
0 から離れたままなら、その分を恒久的なトルクオフセットとして覚え、I 項から差し引く。

**`MD_LLRA`（RAM `0xFFD8F2`）が 0 でないということは、`KF_LLS_TV` のフィードフォワードが
間違っているということである。** マップが正しければ、LFR は補正する必要がなく、学習も 0 になる。

学習の速さ:

| | 値 | 意味 |
|---|---|---|
| `K_LFR_DMDADAPT_MAX`（`0x9D42`） | **1.0 Nm** | **1 相（＝ 1 回のアイドル進入）あたりの最大移動量** |
| `K_LFR_T_ADAPT`（`0x9D44`） | 3.0 s | 相の中で再武装しない死時間 |
| `K_LFR_TAU_ADAPT`（`0x9D40`） | 15.07 s | 時定数 |
| `K_LFR_MDADAPT_MAX / MIN`（`0x9D46`/`0x9D48`） | +40 / −30 Nm | 絶対クランプ |
| `K_LFR_TMOT_ADAPT`（`0x9D4E`） | 70 °C | これ未満では学習しない |

> **1 回のアイドルでは 1.0 Nm しか動かない。** 連続したアイドルの中で A/C を入れたり
> ステアリングを切ったりしても、相は 1 つしか発生しない。**10 Nm を学習させるには、
> エンジンを止めて掛け直すサイクルが 10 回要る。**

`MD_LLRA` は不揮発保存される。**フラッシュしても消えない。**

## 2.3 モデルゲート — 「同じ表を見ているか」

第 1.4 節の計算をログの全サンプルに対して行い、`実測 RF ÷ 予測 RF` の分布を見る。

**この車の実測**: 中央値 **0.9938**、標準偏差 **0.0054**（578 サンプル）。

標準偏差 0.0054 は **`rf` チャンネルの分解能そのもの**（22 に対して 0.1 刻み = 0.45 %）。
つまり、その値が表現できる精度で正確に一致している。

**中央値と散らばりの両方を見ることが必須である。** `RF_PT_KORR` を掛け忘れた場合、
吸気温 42 °C の区間と 56 °C の区間が逆方向にずれるので **中央値はほとんど動かない**。
動くのは散らばりだけ（0.0054 → 0.010）。中央値だけ見る検査はこの誤りを通してしまう。

**このゲートが証明している範囲**: Session #920 の 578 サンプルのうち **87 % が同じ 1 セル**
（870 rpm 列、y 0.391–0.610 の内挿）に落ちている。**証明されているのは 1 動作点である。**
480 セル全体のモデル誤差を証明したわけではない。

# 第 3 部 — 測定値を、書き込む値に変える

## 3.1 `kf_rf_soll`（測定側）

```
新しい値 = 今の値 × STFT × LTFT × rf_korr
```

**掛け算であって割り算ではない。**

| 項 | 何か | 停車アイドルでは |
|---|---|---|
| `STFT` | λ トリム（2.1） | 実測値 |
| `rf_korr` | 排気温度補正 | **1.000**（車速 0） |
| `LTFT` | λ 長期学習 `laa_f`（両バンク平均） | **1.000**。`K_LAA_TMOT_MIN` = 100 °C で学習窓が空なので学習が動かない。1.000 でなければ書かない |

### `KF_TI_N_RF` は掛けない

以前はここに `TI_F_STAT`（`KF_TI_N_RF`）も掛けていた。「`rf = 0.10` 行の 1.148–1.297 は BMW の
意図的な増量で、λ=1 のループが取り返すから掛け戻す」という読みである。**車はそう言わなかった。**

#920 の暖機後・閉ループ 1,479 点で、係数が約 1.17 から厳密に 1.000 へ落ちる `rf = 0.15` の
折れ点をまたぐと:

```
トリム中央値           0.9685 → 0.9699   （+0.1 %）  連続
トリム × TI_F_STAT     1.0728 → 0.9699   （−9.6 %）  跳ぶ
（トリム−1）を（TI_F_STAT−1）に回帰した傾き:  −0.025
```

増量説なら傾きは **−1**、段差を持つのは**トリムのほう**のはずである。実際はトリムが連続で
**積が跳ぶ**。λ ループはこの係数を取り返しておらず、`KF_TI_N_RF` は意図的な増量ではなく
**短パルス域のインジェクタ補償**である。掛ければ車が求めていない補正を最大 +15 % 作る。
証拠は `scripts/verify-ti-factor.mjs`。

`KF_TI_N_RF` の値そのもの（`rf ≥ 0.15` は厳密に 1.000、`rf = 0.10` 行だけ 1.148–1.297）と、
DME がそれを噴射時間に掛けている事実は**そのまま正しい**。変わったのはチューニングの補正式に
入るかどうかだけである。

### この車での実際の計算

アイドルセルは `kf_rf_soll`(870 rpm, y 0.453) ≈ **0.215**。

```
新しい値 = 0.215 × 0.9978（bank1）× 1.000 × 1.000 = 0.2145
                    ↑ 0.9915（両バンク平均）を使うなら 0.2132
```

**変化量は 0.9 %。** `kf_rf_soll` の 1 LSB は 0.001 なので、0.215 に対して **0.47 %**。
つまり **2 段分**しかない。

### 証拠にならないサンプル

| 除外 | 理由 |
|---|---|
| λ トリムが無い | 1.0 として投票させない（`calculator.ts` は `if (!banks.length) return`） |
| `V > 20 km/h` | そこでは `rf_korr` が生きており、モデルに無い項が入る |
| トリムが凍結（分散 ≈ 0） | 収束した 0.87 と凍結した 0.87 は見分けがつかない |
| `ti < K_LA_TI_MIN` | DME が λ ループを開いている |
| 訪問が 1 回 | 同じ運転点の反復であって独立な観測ではない |

**なぜ「訪問」で数えるのか**: `la_f_regler` は 2 点制御で、1–2 Hz のリミットサイクルを持つ。
DS2 のサンプルレートは 3–5 Hz。30 サンプルは「1 周期を 30 点で見た」だけかもしれない。
信号待ち 1 回は 1 観測であって 30 観測ではない。**5 秒以上離れた 3 訪問**を要求するのはこのため。

## 3.2 `KF_LLS_TV`（空気側）

**`MD_LLRA` [Nm] を デューティ [%] に変換する係数は存在しない。** トルクから空気への
換算はエンジンの運転点に依存し、DME 内部でもマップを経由している。

したがって手順は反復になる:

```
1. MD_LLRA を N 回のアイドル進入で測る（N ≥ |MD_LLRA| / 1.0）
2. MD_LLRA > 0 なら KF_LLS_TV の該当セルを +1.0 ポイント上げる
   （MD_LLRA > 0 = LFR が余分にトルクを要求している = 空気が足りない = バルブをもっと開ける）
3. フラッシュ → 適応クリア → 再学習を N 回待つ
4. |MD_LLRA| が縮んでいれば方向は正しい。2 に戻る
```

**1 サイクルに数日かかる。** これは省略できない ―― 学習が 1 進入 1.0 Nm でしか動かないため。

## 3.3 `KL_LFR_NSOLL_GRUND`（目標回転）

**これは測定ではない。選択である。**

データが「アイドルは何 rpm であるべきか」を教えてくれることはない。決めるのは人間である。

```
0x9A70（50 °C）: 現在 870 = 0x036A  →  900 なら 0x0384
0x9A72（80 °C）: 現在 870 = 0x036A  →  900 なら 0x0384
```

16 bit、`math = x`、**1 rpm 刻み**。900 は表現可能。

# 第 4 部 — 冷間の扱い

## 4.1 冷間には別のテーブルがある

`kf_rf_soll_kath`（CSL Alpha-N Cold）。触媒暖機中、DME は 2 つの表を線形にブレンドする:

```
rf_soll_no_filter = kf_rf_soll + (AVAN1_SOLL_FAKTOR / 16384) × (kf_rf_soll_kath − kf_rf_soll)
```

`AVAN1_SOLL_FAKTOR` = 0 なら暖機後の表そのまま、16384 なら冷間の表そのもの。

## 4.2 2 つの表は軸が違う ―― ここが最大の落とし穴

```
kf_rf_soll  Y（0xD326）: 0.098 / 0.146 / 0.195 / 0.391 / 0.610 / 0.806 ...
kath        Y（0xD740）: 0.098 / 0.195 / 0.391 / 0.610 / 0.806 / 1.001 ...
                                 ↑ 0.146 が無い
kf_rf_soll  X（0xD2FE）: 600 / 870 / 1100 / 1300 / 1400 ... 7900
kath        X（0xD718）: 600 / 900 / 1000 / 1100 / 1300 ... 4600（低回転が密、上は 4600 止まり）
```

**行番号で対応させてはならない。** `kf_rf_soll` の row 3 は y = 0.391、
`kath` の row 3 は y = **0.610** である。

同じ (rpm, y) で内挿した実際のブレンド幅:

| 動作点 | `kf_rf_soll` | `kath` | 比 |
|---|---|---|---|
| 870 rpm, y 0.391 | 0.2001 | 0.2073 | 1.036 |
| **実動作点 875 rpm, y 0.453** | **0.2161** | **0.2301** | **1.065** |
| 1100 rpm, y 0.391 | 0.1362 | 0.1972 | **1.448** |
| 1300 rpm, y 0.610 | 0.2358 | 0.2748 | 1.165 |

**暖機後のアイドル回転域ではブレンド幅は 6 % 程度しかない。触媒暖機アイドルが実際に居る
1100–1400 rpm では 15–45 % ある。**

## 4.3 ブレンド係数はログから逆算できる

```
AVAN1_SOLL_FAKTOR / 16384 = (RF / rf_korr / RF_PT_KORR − kf_rf_soll) / (kf_rf_soll_kath − kf_rf_soll)
```

停車アイドルなら `rf_korr` = 1.000 なので、右辺はすべてログと BASE から出る。

**ただし測る場所を選ばないと分解能が足りない。** 870–900 rpm では分母が 0.007–0.015 しかなく、
`rf` の 1 LSB = 0.001 に対して全レンジ 7–15 段。ゲートの標準偏差 0.0054 だけで全スケールの 9 % を
食ってしまう。**1100–1400 rpm で測ること。** そこでは分母が 0.039–0.061 に広がる。

冷間始動のファストアイドルは放っておいてもこの帯にいる —— #921 は 1530 rpm から始まり、
122 秒の窓のあいだ 1100 rpm 前後を保った。**狙って作る運転状態ではなく、ただ録ればよい。**

## 4.4 冷間ログで何が見えたか（Session #921 で実測）

**この節は当初「こう見えるはずだ」という予想だった。実測して、3 つのうち 2 つが誤りだった。**

Session #921: 冷間始動、138 秒、停車のまま、水温 25 → 60 °C、回転 1530 → 1020 rpm、
VE プロファイル 4.81 Hz、662 点。

### 冷間テーブルは、暖機後のテーブルと同じ精度で裏付けられた

|---|---|---|

### ブレンドは 122 秒で、ランプではなく切り替えで外れる

| t [s] | 水温 | 回転 | `f` |
|---|---|---|---|
| 105 | 55 | 1042 | 0.949 |

## 4.5 λ が閉じる前にブレンドが外れるなら、冷間テーブルは λ から導けない

Session #921 の 662 サンプルすべてで `stft1` / `stft2` は**厳密に 1.000**、`lambdaFreeze` は 0、

つまりこのランには混合比の情報がゼロで、冷間テーブルは**検証はできたが補正はできない**。

そしてブレンドは 122 秒で外れる。したがって:

> **`kf_rf_soll_kath` が生きている窓と、λ が閉じている窓は、重なるのか。**
> 重ならなければ、この表は λ トリムからは原理的に導けない。

決めるのは簡単で、冷間始動から 5 分ほど回して `stft` が 1.000 を離れる時刻を読むだけである。
122 秒より前なら重なりがあり、導出できる。後なら、この表は別の証拠源（ワイドバンド）を
必要とし、この車の装備では届かない。

# 第 5 部 — 順序と、その理由

## 5.1 なぜ空気側が先なのか

`KF_LLS_TV` を動かすと、次が連鎖する:

```
バルブのデューティが変わる → AQ_ABS_LLS が変わる → AQ_REL が変わる
→ aq_rel_rf が変わる → アイドルが kf_rf_soll の別の行に移動する
```

**この車のアイドルは今 y ≈ 0.453 に居る。** 空気側を動かせばここが動く。
測定側を先にやると、**もう使わないセルの証拠を集めたことになる。**

`KL_LFR_NSOLL_GRUND`（目標回転）はさらに強い。回転が変われば摩擦トルク・`ML_SOLL`・
`KF_LLS_TV` の動作点・`AQ_REL`・`kf_rf_soll` の行がすべて同時に動き、
**`MD_LLRA` も再学習になる。**

## 5.2 したがって順序は

```
1. 目標回転（KL_LFR_NSOLL_GRUND）        ← 決めるなら最初に。後から変えると全部やり直し
2. バルブのフィードフォワード（KF_LLS_TV）  ← MD_LLRA で判定
3. 暖機後の測定側（kf_rf_soll）           ← λ トリムで判定
4. 冷間の測定側（kf_rf_soll_kath）        ← 冷間ログで判定
```

## 5.3 フラッシュのたびに必要なこと

1. **初回の書き込みは FULL VERIFY。** QUICK が許されるのは、その VIN で FULL が 1 回通り、
   チェックサムが一致したあとだけ。
2. **フラッシュ後は適応クリア。** `MD_LLRA` は不揮発なので、クリアしないと
   **フラッシュ前の学習値を読んでしまう。**
3. **クリア後は再学習を待つ。** 1 進入あたり 1.0 Nm。
4. **読み返して、その READ から子セッションを分岐する。**

# 第 6 部 — 車がどう変わるか

## 6.1 閉ループの向きが、2 つの側で逆である

| | ループが閉じている先 | 1 段動かすと |
|---|---|---|
| **測定側**（`kf_rf_soll`） | **λ**（混合比） | トリムが同じ量を戻す。**定常では体感なし** |
| **空気側**（`KL_LFR_NSOLL_GRUND`） | **回転数** | LFR が新しい釣り合いへ動く。**定常アイドルそのものが変わる** |

「アイドルが `kf_rf_soll` のどの行に載るか」である。

## 6.2 測定側の修正は、λ ループが開いている瞬間にしか現れない

| 状態 | λ ループ | 表を直すと |
|---|---|---|

| オーバーラン復帰 | 開 | 復帰時のショック |
| 全開 | 開 | 出力と安全マージン |

## 6.3 この車で「直しても意味がない」と分かっているもの

| | 実測 | 結論 |
|---|---|---|
| 暖機後アイドルの λ トリム | bank1 0.998 / bank2 0.985 | 補正 0.9 % = **量子化 2 段**。書いても丸め以下 |

### A-④ 表が合っているかの判定と、直し方

**考え方**: 表は「この空気量が欲しければ、このデューティを出せ」と言っている。
実際にそのデューティで**どれだけ入ったか**は、RF から分かる。両者が違えば表が間違っている。

```
[1] 実際に入った空気の総量（第 1.3.7 節の ML）
        ML_total = 0.0010908 × rpm × rf                                   [kg/h]

[2] そのうちバルブ分の割合を面積比で出す
        A_valve    = KL_AQ_ABS_LLS(llsTv × 50)          ← 0xE014/0xE024（下表）
        A_throttle = KL_AQ_ABS_WDK(wdk1 × 10)           ← 0xE036/0xE046
        ML_valve   = ML_total × A_valve / (A_valve + A_throttle)          [kg/h]

[3] 表の誤差
        k = mlSollLls / ML_valve

        k = 1.00  → 表は正しい。触らない
        k > 1.00  → 要求より少ししか入っていない。バルブをもっと開ける必要がある
        k < 1.00  → 入りすぎ。閉じる必要がある
```

`KL_AQ_ABS_LLS`（デューティ raw → 面積）:

| raw | 400 | 1000 | 1500 | 2500 | 3500 | 4000 | 4500 | 5000 |
|---|---|---|---|---|---|---|---|---|
| **%** | 8 | 20 | 30 | 50 | 70 | 80 | 90 | 100 |
| 面積 | 0 | 4 | 13 | 56 | 103 | 122 | 134 | 137 |

`KL_AQ_ABS_WDK`（スロットル raw → 面積）: X = 0/55/130/230/380/520/690/1000（raw、1000 = 100 %）、
Y = 0/45/257/782/2014/3898/6250/11781。

**クロスチェック**: `k` > 1 なら `mdLlra` は正（＋）のはずである。符号が食い違うなら、
どこかの読み取りが間違っている。書かずに調べ直すこと。

#### 書き込み

誤差 `k` は「バルブが表の言うほど流れていない」という **Y 軸のスケール誤差**である。
したがって列全体を Y 方向に伸縮する:

```
新しい値(rpm, y) = 今の表(rpm, y × k)
```

**1 回の書き込みで `k` は [0.90, 1.10] にクランプすること。** それ以上は 2 回に分ける。

**計算例**（`rpm` 870、`mlSollLls` 18.9、`llsTv` 36.7 %、`rf` 22.0 %、`wdk1` 0.9 % だった場合）:

```
ML_total   = 0.0010908 × 870 × 22.0            = 20.88 kg/h
A_valve    = KL_AQ_ABS_LLS(1835)                = 27.4
A_throttle = KL_AQ_ABS_WDK(9)                   =  7.4
ML_valve   = 20.88 × 27.4 / 34.8                = 16.5 kg/h

|---|---|---|---|

#### 書いたあと

1. フラッシュ（初回は FULL VERIFY）
2. **適応クリア**（`MD_LLRA` は不揮発。消さないと前の学習値が残る）

4. `k` が 1.00 ± 0.03 に入るまで繰り返す

### B-④ どう直すか

```
新しい値 = 今の値 × STFT × LTFT × rf_korr
```

| 項 | 値の出どころ | 停車アイドルでの値 |
|---|---|---|
| `STFT` | `stft1` と `stft2` の升内平均 | **実測** |
| `rf_korr` | — | **1.000**（車速 0 なので） |
| `LTFT` | `laa_f`（λ 長期学習、両バンク平均） | **1.000**（`K_LAA_TMOT_MIN` = 100 °C で学習窓が空） |

**この車の実測での計算**:

```
stft1 = 0.9978、stft2 = 0.9851  →  平均 0.9915

0xD3D0 : 0.200 × 0.9915 = 0.1983  →  raw 200 → 198   （−2 カウント）
0xD3F8 : 0.260 × 0.9915 = 0.2578  →  raw 260 → 258   （−2 カウント）
```

**1 LSB = 0.001。変化は 2 カウント = 1.0 %。** 書けるが、量子化 2 段分でしかない。

**停止条件**: `|STFT − 1|` が 1 LSB 相当（この升では 0.5 %）を下回ったら収束。書くものはない。

**体感**: **なし。** λ ループが閉じているので、トリムが同じ量を戻す（第 6.2 節）。

**バンク差は直せない**: `stft1` と `stft2` が 1.3–1.8 % 違うが、`kf_rf_soll` は両バンク共通である。

### C-③ どの升に落ちるか

X・Y の求め方は STEP B と同じ（`aq_rel_rf = rawLoad / kl_aq_rel_rf_fakt(rpm)`）が、
**引く軸は kath 自身の軸である**（上表）。

### C-④ どう直すか

冷間はブレンドなので、2 段構えになる。

**第 1 段 — ブレンド係数を測る**

```
f = AVAN1_SOLL_FAKTOR / 16384
  = (rf/100 / RF_PT_KORR − kf_rf_soll(rpm, aq_rel_rf)) / (kf_rf_soll_kath(rpm, aq_rel_rf) − kf_rf_soll(rpm, aq_rel_rf))
```

停車アイドルなら `rf_korr` = 1.000 なので、右辺はログと BASE だけで出る。

**測れる場所は 1100–1400 rpm に限る。** 870–900 rpm では分母が 0.007–0.015 しかなく、
`rf` の 1 LSB = 0.001 に対して全レンジ 7–15 段しかない。
1100 rpm なら分母は 0.039–0.061 に広がる。

**確認**: この BIN ではアイドル域全体で `kath > kf_rf_soll` なので、
**触媒暖機中はモデルゲートの比が 1 を「超える」**（1100 rpm で最大 1.45）。
上がらなければブレンドが抜けている＝十分に冷えていない。録り直す。

**第 2 段 — 表を直す**

λ トリムが補正しているのは**ブレンド後の値**であって、kath 単体ではない。

```
blend = kf_rf_soll + f × (kf_rf_soll_kath − kf_rf_soll)

補正後の blend を  blend × STFT  にしたいので

新しい kath = kf_rf_soll + (blend × STFT − kf_rf_soll) / f
```

`f` = 1（全ブレンド）なら、単純に `新しい kath = kath × STFT` になる。

**体感**: **ある。** 冷間始動の毎回。ただし真に開ループなのは O2 ライトオフ前の十数秒で、
触媒暖機中は λ 制御が動いている。

## A.1 アイドルセルに何が課されているか

```
