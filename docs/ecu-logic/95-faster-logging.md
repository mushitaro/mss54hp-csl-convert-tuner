# 95 — ログを速くする三つの道と、その go / no-go

読み取りのみの調査。**結論を先に: 専用 DS2 ブロックは no-go。** 得られる速度は
RAM 読みの 1.8 倍にすぎず、代償は「プログラム領域へのフラッシュ」という、
このツールがこれまで一度も通っていない経路である。しかも同じ目的に対して
**10 倍速い手段（CAN 100 Hz）が、すでに他者の手で作られている。**

---

## 1. 三つの道と、その値段

| 手段 | 実測または見積 | ECU への変更 | 失敗したときの状態 |
|---|---|---|---|
| **A. RAM 4 バイト読み**（実装済み） | 約 4.7 Hz（モデル値） | **無し** | 無し。落ちれば両ブロック読みに戻るだけ |
| **B. 専用 DS2 ブロック** | 約 9 Hz | **プログラム領域**のパッチ | ブートブロック復旧が要る |
| **C. CAN 100 Hz 送出** | 100 Hz | 同上（ただし他者が実装済み） | 同上 |

A はすでに動いている（`logProfile.ts` の VE プロファイル、`ramMap.ts` の
`LAMBDA_TRIM_RAM_READ`)。B と C は同じ壁の向こうにあり、**その壁は
「プログラム領域を書けるか」の一点**である。

---

## 2. B が壁の向こうにある理由

DS2 の `0x0B` ブロック表とハンドラは**プログラム領域のコード**である。

- ハンドラ本体: master `0x030B84`（`ds2_handler`、`master/030b84.txt`）。
  selection 3 は `case 0x1c` として現れる。
- このツールが書けるのは `Mss54HpDataTuneLayout` が指す **65536 バイトの
  キャリブレーション partial のみ**（`ds2.ts`）。`writePartialBinInner` は
  それ以外の長さを拒否する。ブロック表はその外にある。

したがって新ブロック（例: 選択 0xE0 = N, RF, AQ_REL, TMOT, TABG, WDK1,
LA_F_REGLER1/2, TETV を 1 テレグラム 24 バイトで返す）を足すには、
**DME プログラムのフラッシュ**が要る。必要になるもの:

1. プログラム領域へ書く DS2 経路（消去セクタと 4 つのチェックサム再計算を
   含む full-flash シーケンス。このツールには無い）
2. 0401 マスタでのブロック表・オフセット表・コードケイブの特定
3. ハンドラ本体（既存 block 3 ハンドラの `move.b/move.w (a2)+` 形式を踏襲）
4. 失敗時の復旧（プログラム flash の失敗はブートブロック復旧が要る。
   データ partial より一段階リスクが高い）
5. 配布（この機能を使う DME すべてにプログラムパッチを当てる運用。
   コミュニティパッチはデータのみ）

### 速度の見積

1 サンプル 1 交換 ≈ 要求線路 5.7 + write 14 + echo 8 + ECU 思考 ~40 +
応答線路 32 + FTDI 末尾 ≤16 ≈ **110 ms → 約 9 Hz**。ブロック間スキューも
無くなる。実装済みの A（約 4.7 Hz）に対して **1.8 倍**。

---

## 3. C が B より先に来る理由

`90-sources.md` の一次資料が示すとおり、**karter16 と Bry5on はすでに
CAN 経由 100 Hz ロギングを動かしている**（`0x7D0` / `0x7D1`、10 ms タスク、
thread 287069 p9–p18 および journal p20–p25）。未公開で、Community Patch V2
に入る予定（thread 343444 #9）。

同じ「プログラム領域を書く」という代償に対して:

- B は **9 Hz** を自作する
- C は **100 Hz** を、すでに他者が検証したコードで得る

さらに、しきい値の議論で karter16 が基準にしているのはこの 100 Hz である
（同 #161）。つまり B を作ると、**このツールだけが 9 Hz の独自ブロックを持ち、
コミュニティは 100 Hz の CAN を持つ**という分裂を自分で作ることになる。

---

## 4. 判定

**B は no-go。** 理由を優先順に:

1. 代償（プログラム flash 経路とブートブロック復旧）に対して 1.8 倍は釣り合わない
2. 同じ代償で 10 倍が、他者の実装として存在する
3. その 10 倍は公開予定であり、待てば代償そのものが消える
4. A がすでに ECU 無改変で効いており、次の実走で定数が確定する

**次に見るべきもの**（このドキュメントの更新条件）:

- Community Patch V2 が CAN 100 Hz を公開したら、**C の受け側**を検討する。
  その時点で必要なのは DS2 ではなく CAN フレームの受信であり、
  `logProfile.ts` の `LogExchange` はそのまま `{kind:'can', id:0x7D0}` を
  足せる形になっている（`exchanges` は交換の列であって DS2 の列ではない）。
- A の実測が WP6 の走行で 4 Hz を下回った場合、原因は FTDI の
  レイテンシタイマか ECU 思考時間のどちらかで、
  `TransferTimingReport.byExchange` がどちらかを名指しする。
