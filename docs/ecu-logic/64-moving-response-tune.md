# 移動中の記録から有限のVE更新を作るTune

2026-10-12。ブラウザの `moving-response` 方式の仕様。
運転点を保持することを前提にせず、記録時BINと各読取り時刻を持つRAW履歴から、
次の一回に適用するVE変更を求める。実装は `src/lib/ve-calculator/movingResponse*.ts`。

出力は、複数の輸送仮説と未使用区間で検査した**最大5%の有限更新**である。
補正後の名目VEを一意に識別した値、全ての物理誤差を解消した値、全不等式を同時に
満たした解という意味ではない。`rf_korr^α` の固定α、変更を1へ引き戻す正則化、
狭帯域O₂電圧からの数値AFR換算は使わない。

## 以前の推定差との関係

[63-response-identification.md](63-response-identification.md) は、比較用モデルの
−26.2%と−2.7%が変わった原因を記録した分析履歴である。−26.2%の勾配は特定の通過に
ほぼ集中し、その通過を除いた−2.7%は変更抑制項が倍率を1へ戻した結果だった。
別区間が−2.7%を積極的に測定したという結果ではない。

同文書の `pre-rf_korr` 基準空気、P増分2以上、I符号の継続時間を使う比較モデルを、
そのまま製品の書込み経路へ移したわけではない。本方式は以下の指令基準、センサーの
整数フィルタ、P増分3以上、未使用区間での検査に置き換える。以下が製品方式の仕様である。

## 記録BIN、RAW、各読取り窓

記録時BINからVE、ラムダ制御の上下限とI/P最大更新量、センサー校正、EGT/RF補正表、
`KF_TI_N_RF` を読む。現在の書込み予定設定や別のBINを、過去ログの校正として代用しない。
記録時の空気モデルが作動中、学習が停止していない、BINが不明、または入力VEの軸・全値が
記録時VEと一致しない場合は、新しいマップを返さない。RF補正表の同時書換えも扱わない。

RAWの行順と行番号を保持し、standard、ラムダRAM、噴射、RF Soll、RF Korrの
読取り窓を別々に扱う。フィルタでO₂根拠に使わない行も履歴から消さない。
各窓はホストが記録した中央時刻±通信所要時間/2である。これはDMEの内部更新が
原子的だったという保証ではない。

暖機、パージ停止、LTFT=1、BA=1、ラムダ両バンクON、制御上下限から離れていること、
噴射カットなし等をO₂根拠の条件とする。BAやカット中の既知の指令履歴は別に保持する。
時刻逆転、1.5秒を超える空白、欠けた読取り、カウンタのリセット・飽和を跨いで、
途中の制御量を補完しない。TIブロックがない古いログから製品のVE更新は生成しない。

## TIから作る指令基準と燃料範囲

バンクごとのTIは各3気筒の記録値の平均を使う。同じ噴射応答に含まれる
`injectionStft1/2` を `u_inj` として、次の基準を作る。

```text
B_b(t) = interpolate(TI_b / u_inj,b) * rpm(t) / 120
F_b,low(t)  = B_b(t) * u_b,low(t)
F_b,high(t) = B_b(t) * u_b,high(t)
```

`B` はラムダ成分を分離した**噴射指令の基準**であり、実測空気量や名目空気量ではない。
実際に適用されたRF Korr、温度補正、TI係数を既に含むため、RF Korrをもう一度掛けない。
異なる時刻のstandard STFTでTIを割ることもしない。

`u_low/high` はSlave `0x01D6A2` / `0x01DC42` のI/P更新則の外側範囲。
前後のSTFTを `u0,u1`、実行P回数の増分を `m` とすると、読取り窓の幅と10ms tickを
追加した次の二方向の到達可能範囲を交差させる。

```text
u_low(t)  = max(u0 - I-*(t-t0) - m*P-, u1 - I+*(t1-t) - m*P+)
u_high(t) = min(u0 + I+*(t-t0) + m*P+, u1 + I-*(t1-t) + m*P-)
```

途中のP動作を消すSTFTの直線補間は使わない。別ブロックで実測した `u_inj` を
この範囲と照合し、矛盾する箇所とその周辺は指令履歴を作らない。
範囲を広げて矛盾を消す処理はなく、検査数・不一致数・最大不一致を診断値に残す。

全気筒カットが前後の噴射読取りでともに6なら `F_low=F_high=0` とする。
この場合も `B` をゼロにしない。燃料停止中もエンジンを通る空気が残るためである。
カット数が部分的ならバンク別の気筒を特定できない。前後のカット数が異なる場合も
切替時刻が分からないので履歴を切り、読取り間の中央で切り替わったことにはしない。

## O₂の整数IIRから観測窓を作る

Slave `0x01E530` はADCを校正した後、`IIR_Filter_SS`（Slave `0x011544`）で
電圧をフィルタして `USV1/2` を作る。ラムダ制御が見るのはこのフィルタ後の電圧である。

```text
raw = floor(K_LAS_M * adc / 1024) - K_LAS_NP
delta = raw - y
y_next = y + trunc(delta / tau)
```

`tau=0` は直接更新。`delta!=0` なのに整数除算が0なら、符号に従って最低1mV動く。
タスク周期は10ms。校正値と表の場所は次のとおり。

| 校正 | Slaveの位置 | 解釈 |
|---|---:|---|
| `K_LAS_NP` | `0x4816` | 16bit、mVオフセット |
| `K_LAS_M` | `0x4818` | 16bit、ADCに掛けて1024で割る |
| 濃い側の閾値 | `0x4820` | 16bit、mV |
| 薄い側の閾値 | `0x4822` | 16bit、mV |
| `KF_LASV_TAU` 回転軸 | `0x4A4E` | 16bit×4 |
| 同RF軸 | `0x4A56` | 16bit×4、raw/1000 |
| 同値 | `0x4A5E` | 16bit×16、整数除数 |

ADCの範囲は観測電圧の最大・最小から推測しない。MC68336 QADCの
右寄せunsigned結果レジスタは10bit（0〜1023）。DMEの読取り位置はこの窓に属する。
[NXP MC68336/376 User's Manual D.5.9](https://www.nxp.com/docs/en/user-guide/MC68336376UM.pdf)
からハードウェア範囲を取り、BINの傾き・オフセットで電圧範囲へ変換する。
校正によるsigned shortのオーバーフローは拒否する。

記録968の校正では `K_LAS_M=1115`、`K_LAS_NP=0`、入力0〜1113mV、
フィルタ除数8、濃い閾値510mV、薄い閾値400mVである。
観測電圧を `y_obs` として「過去N回に生電圧が閾値を一度も越えなかった」と仮定する。
最も古いフィルタ状態を可能な極値、以後の入力を閾値の反対側で最も近い整数に置き、
表全体で最大の除数を使って整数IIRを反復する。その最長残留の軌跡でも `y_obs` を
維持できなくなるNを求める。これにより、そのN tick以内に少なくとも一度、
該当側の生電圧が存在したという必要条件を得る。

この校正の例では400mVの薄い観測が最大0.41秒、510mVの濃い観測が最大0.44秒、
875mVの濃い観測が最大0.04秒を遡る。ホスト読取り窓は別に加える。
いずれも正確なセンサー遅延を測った値ではなく、閾値通過の存在を囲む時間幅である。
電圧値をAFR誤差の大きさへ変換しない。

## PカウンタとI動作を何に使うか

P動作の最初の一回は観測区間より前に予約された可能性がある。
2回だけでは、ヒステリシス内で保持された制御符号と、新しい生電圧の閾値通過を
同一視できない。P実行回数が同一区間で**3以上増加**すれば、最初の実行後に
少なくとも2回の再予約が必要となり、濃淡両側の新しい閾値通過が得られる。
Pの実行方向が毎回交互であることは仮定しない。

前後の区間が有効でカウンタが未飽和なら、P増分3以上について濃い側・薄い側の
存在条件を一つずつ追加する。それぞれの左端を、該当閾値でのIIR遡及時間分だけ拡張する。
I更新量は噴射制御範囲の構成に使うが、I積分から生のAFR符号の継続時間を計算しない。
フィルタ後の電圧と符号ヒステリシスは、物理的な濃淡の継続時間そのものではないためである。

## 移動するセル寄与と11種類の輸送仮説

100ms刻みで運転点を再構成する。双線形補間の幾何学重みを `a_j(t)`、記録VEを `VE_j` とすると、
VEセルを倍率 `f_j` へ変える際の指令寄与は次である。

```text
w_j(t) = a_j(t)*VE_j / sum_k(a_k(t)*VE_k)
VE_ratio(t) = sum_j(w_j(t)*f_j)
X_b,j(t) = H[B_b*w_j](t)
C_b(t)   = sum_j X_b,j(t) = H[B_b](t)
Q_b,low/high(t) = H[F_b,low/high](t)
```

比を輸送するのでなく、指令基準・燃料・各セル寄与を正の線形演算 `H` で別々に輸送してから比較する。
運転点が移動しても、一つの固定セルの観測に置き換えない。

| 系統 | 仮説 |
|---|---|
| 時間遅れ | 0、0.25、0.5、1、2秒の5通り |
| 流量による滞留 | 基準流量で0.25、0.5、1秒の3通り |
| 流量による滞留＋混合 | 上記3通りに時定数0.25秒の混合を追加 |

流量時計は `rpm * RF_Soll * 100` の積分、基準は2000rpm・30%RFである。
4秒を超える遡及や欠損を跨ぐ履歴は採用しない。混合開始直後は5時定数を待つ。
これら11種類は、実車で同定済みの輸送時間の保証範囲ではない。
固定の「Tunerは1秒で補正が届く」という仮定を一つ選ぶのでなく、各仮説の有効な観測で
更新が悪化しないかを検査する条件集合である。燃料壁面付着の係数を新たにフィットしない。

## 候補計算と未使用区間での検査

濃い観測は観測窓内のどこかで `sum(X*f) <= Q_high`、薄い観測はどこかで
`sum(X*f) >= Q_low` が必要になる。候補計算では、窓内のセル寄与と燃料比の
極値から作った外側の不等式を使う。この極値係数の合計を1へ再正規化しない。
これは必要条件の緩和であり、後段に同時刻の検査を置く理由でもある。

誤差には指令基準で正規化した片側残差のHuber損失（境界0.025）を使う。
0.025は残差の許容幅ではなく、損失の傾きが変わる点である。
残差をゼロと見なしたり、不成立の観測を恣意的に緩めたりしない。
各輸送モデル・バンク・時間区間の平均損失を比較するため、単純な行の複製で重みは増えない。

一回の最大セル変更は `0.05 * min(1, learningRate)`。
正負両方向を試し、必要なら変更幅を半減する。セルごとに、両バンクで少なくとも2回の
独立した通過の改善を要求する。寄与0.001を超える根拠の間隔が5秒を超えたときに
別の通過とし、同じRAW行を複数の輸送仮説で評価しても通過数を増やさない。
複数セルを順に採用するときも、既に採用した変更と合算して検査する。

製品経路は時系列を5分割して交差検証する。

1. 一つの区間を評価用に残し、その前後20秒も学習から除く。残りだけで更新を求める。
2. 学習に使っていない区間で、その学習結果と無変更を比較する。これを5区間で繰り返す。
3. 少なくとも2つの学習結果が同方向を選び、逆方向を選んだ結果がないことを確認する。
4. 両バンクで少なくとも2つの評価区間に根拠があり、そのセルが寄与する運転領域の
   評価側の実通過が各2回以上改善することを要求する。
5. 学習した近隣セルを含む合算予測の損失差を対象セル寄与で重み付けし、
   各モデル・バンク・評価区間で無変更より悪化しないセルを残す。
6. 残ったセルだけを使い、全データで合算更新を再計算する。

5分割の番号はサンプルをランダムに分配したものではない。隣接した読取りの情報が
学習・評価双方へ入りやすい問題を、連続区間と前後20秒の除外で抑える。
評価通過は有限個の走行履歴であり、次の走行の物理的成功を証明するものではない。
区間平均が悪化しないという要件も、全観測点の残差が個別に小さくなるという意味ではない。
双線形補間では隣接セルの係数が重なるため、ある学習区間が補正を近隣セルへ配分することがある。
評価するのは、学習に使っていない運転領域での合算指令の予測である。対象セルだけを
変更し、同時に学習した隣接セルを1へ戻した仮想予測とは区別する。個別係数の診断値も保存するが、
領域の予測改善を対象セル一つの正解値の識別と読み替えない。

## 量子化後のRF・TI_STATを含む最終検査

候補のVEをBINと同じ0.001単位へ丸める。丸めは記録VEへ戻す方向とし、最大変更率を
丸めによって超えないようにする。以下の検査は個別セル案でなく、量子化済みの合算マップに対して行う。

変更後指令比は、観測RF Korrを保持する場合と、BINのentry/hold/reset分岐を再生する場合の
両方を評価する。後者はSlaveではなくMaster `0x021A70` のRF補正ゲートである。
観測RF Korrを基点とし、モデル排気温度の差に対する表の応答を反復する。
疎なTABGから求めた絶対値で、DMEが実際に適用したRF Korrを置き換えない。
反復が収束しない場合は、その指令比を有効としない。

```text
v(t) = sum_j(w_j(t)*f_j)
relativeK(t) = K_replay,changed(t) / K_replay,unchanged(t)
RF_old(t) = RF_Soll(t) * K_observed(t)
RF_new(t) = RF_old(t) * v(t) * relativeK(t)
R(t) = v(t) * relativeK(t)
       * KF_TI_N_RF(rpm,RF_new) / KF_TI_N_RF(rpm,RF_old)
```

保持モードは `relativeK=1`。無変更マップは、観測Kの時間変化やhold区間があっても
比を厳密に1にする。`KF_TI_N_RF` はROではなく最終RFを軸に読む。
Slave `0x01C6CA` ではVL、およびLLかつ `LLS_ST` のbit7が立つ場合に別表が選ばれるため、
本方式ではそれらの根拠を採らず、過去の該当分岐へ変更が及ぶ指令比も未知として扱う。
Slave `0x01C562` の `TI_F_GA=K_TI_GA` は定数なので、この変更前後比では相殺される。

最終検査では `C_new=H[B*R]` と記録燃料 `Q_low/high` を**同じ時刻**で比較する。
濃い観測の違反量は `max(0,min_t((C_new-Q_high)/C_old))`、薄い観測は
`max(0,min_t((Q_low-C_new)/C_old))`。最小化する時刻はその観測窓内に限る。
無変更側にも同じ式を適用する。

2種類のRF応答×11輸送仮説×バンク×時系列5区間で平均損失を比較し、いずれかが
悪化する場合は関連セルの変更を半減して再量子化・再検査する。縮小でも残る変更は戻す。
指令比が窓内で未知になる場合も成功扱いしない。所定回数で合算案の検査が通らなければ
全セルを無変更にする。無変更に対する残差そのものは診断結果へ残す。

ここで使うRF応答は、同じ走行のrpm・RF Soll・TABG等を基にした小幅変更の条件付き再生である。
変更後の実車の排気温度、運転者の操作、全てのバックグラウンドタスクまで予測するモデルではない。

## 加算項と残る条件

Slave `0x01B0E2` はラムダ等の乗算後に `TI_OFFSET_ADAPT`、さらに気筒別の
`TI_SYNC` を加えてTIを作る。従って `TI/u_inj` は、加算成分を含めて形式的に
分離した指令基準であり、純粋な乗算前燃料を厳密に復元したものではない。
LTFT=1だけでは加算学習値ゼロを証明しない。記録968ではユーザーが実施したリセットと
記録BINの学習停止が加算学習値を残さない条件の根拠になる。

気筒同期の加算項はSlave `0x01D0A0` で
`TI_SYNCc = K_N_LL_SYNC * TI_LL_Zc / max(N40,15)`。
記録BINの `K_TI_LL_MIN/MAX` は−100/+100、`K_N_LL_SYNC=25` なので、
2400rpm（N40=60）では絶対値が約41.7µs以下となる。
これを5%の乗算変更へ含めることによる差は約2.1µs以下、4ms指令の約0.053%である。
通常のTuneリセットが、別指定の気筒同期値リセットまで行ったとは仮定しない。
これは−26%の差を説明する量ではなく、指令モデルに残る有界な近似項である。

このほか、TIの量子化・最小最大クランプ、短パルスの実噴射特性、非ラムダ成分の
読取り間補間、100msグリッド、酸素センサーの物理応答、未同定の排気輸送に条件が残る。
整数IIRを扱う修正で以前の矛盾は減ったが、全ログの硬い不等式が全て成立したとは主張しない。
本方式の出力の根拠は、これらの条件下での有限変更と、未使用通過・最終合算案の検査である。

## STOP、保存、再計算

LIVE中はRAWを収集し、古いTUNED結果をクリアする。STOPまたは保存済みログの明示計算で
RAW全体をWeb Workerへ渡し、ブラウザUIを占有せず一回の履歴計算を行う。
Workerの失敗は画面へ返し、旧方式やメインスレッドの計算へ自動で切り替えない。
別セッション・リセット・新しい計算が始まった場合は前のWorkerを終了し、遅い結果を採らない。

採用セルがある場合だけ `newMap` を返し、`calibrationStatus='moving-validated'` と
方式version、最大ステップ、根拠行数、通過数、輸送モデル、変更前後損失等の監査情報を付ける。
未採用セルは記録VEのまま残る。根拠件数、要求倍率、実際の変更倍率、却下理由は別に返す。
ログ保存・同期の記録BIN参照を維持し、再計算の入力にはその記録BASEを使う。
同じRAWを同じBASEで再計算しても、既存TUNEDへさらに5%を重ねることはない。
計算や保存だけで車両へ書き込むこともない。

SAVE・DOWNLOAD・WRITEで共有する `useBinaryFile.buildPatchedBuffer` は、全ての
書込み処理とチェックサム補正後に出力バイトを記録BINと照合する。VEの全バイトが検証済み
マップと一致し、RF補正・センサー・制御ゲイン・TI_STAT・空気モデル等の記録時設定を
維持していることを確認する。SHAPEや手動編集を検証済みVEへ重ねることはできない。
別用途の暖機・WOT表とチェックサム以外に予定外の差があれば出力を止める。

## 検証と実ログ再生

```powershell
npm run verify:moving-response-inputs
npm run verify:moving-response-sensor
npm run verify:moving-response-history
npm run verify:moving-response-fit
npm run verify:moving-response-tune
npm run verify:moving-response-route
npm run analyze:moving-response-tune -- <D1-session-directory>
```

センサー検証は実装とは独立に整数IIR系列を生成し、169,407個の有効観測の遡及窓を検査する。
履歴・Tune検証は、既知の移動軌跡、繰返し通過、片側バンクの反証、未使用区間、
読取り欠落、カット境界、RF二重乗算防止、別TI_STAT分岐、BASE不一致等を扱う。

実ログ再生はD1エクスポート、記録BIN、記録校正のSHAを照合してから、製品と同じ
`calculateMovingResponseDetails` を実行する。出力は非公開の
`archive/moving-response-tune/<session-id>/analysis.json`。
セル別の採用値・根拠、交差検証、最終検査の失敗区間、ソースSHAも保持する。
ログ・BINそのものを公開文書やコミットへ含めない。

## 走行中の収録グリッド

START後は最初のRAW受信からMEASUREMENTを開く。セルの数値は記録点数であり、
色と記号は「未記録・条件外／欠測・解析候補・複数通過」を示す。CURRENT MAPでも
同じ収録状態をVE値に重ねる。セルを選ぶと記録数・候補数・通過回数を表示し、
詳細から欠測、パージ、加速補正、燃料カット等の理由を確認できる。

収録はRAWの増分を集計し、旧定常フィルターで落ちた領域も残す。候補は記録BINの
照合、必要な読取りと局所的な空燃比応答が揃った観測を意味する。複数通過は候補の
間隔が5秒を超えて再訪したことを示し、5秒の保持を要求するものではない。
この表示から採用マップや書込み値は生成しない。運転点の保持時間や「測定完了」の
表示も使わない。

STOPで履歴全体の輸送・噴射指令・両バンク・未使用区間の検証を実行し、採用結果が
あればTUNED MAPへ移る。解析中、採用ゼロ、解析エラーでも収録グリッドは保持する。
収録状態は保存済みRAWと記録校正から再構築でき、保存・BIN出力は従来どおり
最終検証結果を参照する。未計算のセルを「変更不要」として表示しない。

検証は `verify:moving-response-live`、`verify:moving-live-route`、
`verify:moving-acquisition-ui`。`preview:moving-acquisition` は実コンポーネントを
683×400と360×640で確認する合成データのローカル画面を生成する。

## 記録968を製品経路へ適用した結果

同じ記録BIN・RAWを製品計算へ通し、8セルを採用した。未採用の472セルは記録値のままである。

| RO | rpm | 記録VE | 出力VE | 変更率 |
|---:|---:|---:|---:|---:|
| 0.2% | 600 | 0.263 | 0.250 | −4.943% |
| 0.4% | 600 | 0.307 | 0.292 | −4.886% |
| 5% | 2100 | 0.613 | 0.606 | −1.142% |
| 5% | 2200 | 0.664 | 0.656 | −1.205% |
| 5% | 2400 | 0.550 | 0.544 | −1.091% |
| 7.5% | 2100 | 0.770 | 0.761 | −1.169% |
| 7.5% | 2200 | 0.758 | 0.749 | −1.187% |
| 7.5% | 2400 | 0.841 | 0.831 | −1.189% |

2400rpm・RO7.5%には根拠58行、両バンク各7通過があり、未使用区間の領域合算予測で
各5通過が改善した。単独係数だけの改善通過数は各1であり、領域合算の5とは区別する。
5分割の学習倍率は `[0.95,0.95,0.95,1,0.95]`。初期候補−5%をそのまま出力せず、
量子化後のRF・TI_STATを含む合算検査で縮小し、0.831へ確定した。
ここで確定したのは、この記録から次の一回に作成する出力値であり、最終的な真のVEではない。

最終損失は `0.0174899470 → 0.0162254833`（7.23%低下）。
2種類のRF応答×11輸送仮説×2バンク×5区間の220群で、平均損失の悪化は0だった。
この損失は指令基準に対する片側残差の集計であり、AFRが7.23%改善したという単位ではない。

この8セルを製品の `useBinaryFile.buildPatchedBuffer` へ渡して、65536バイトの候補BINを
実際に生成した。全VEセルが計算結果と一致し、変更はVEとチェックサムの範囲内の12バイトのみ。
Slave/Masterの両チェックサム、同じ入力からの再生成のバイト一致、記録時の補正設定保持を確認した。
候補は非公開の同じ結果ディレクトリへ `Tune_968_moving_response_candidate.bin` として保存し、
`candidate-bin-proof.json` に入力・出力・ソースのSHAとバイト差を残す。この検査で車両通信や
フラッシュ書込みは実行していない。

TIを持たない967には同じ8セルの固定出力を、再構成指令による追加診断として適用した。
集計損失は5.04%低下したが、220群のうち6群は最大約 `1.847e-9` 悪化した。
小さい値でも完全合格とはしない。実測TIによる製品入力ではなく、967からBIN生成を
許可したという結果でもない。診断は非公開の `archive/ve-moving/transfer-967-fixed-output.json` に残す。
