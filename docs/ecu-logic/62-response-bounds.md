# 移動する運転点の VE 制約推定

実装: `scripts/ve_response_bounds.py`。再生: `scripts/analyze-response-bounds.py`。
この実装は記録済みログから比較マップを計算する。ブラウザの Tune 計算にはまだ接続しておらず、
BIN の生成・ECU への書込みはしない。`calibrationStatus` は `comparison-only`。

## 計算する量

`f[j]` を記録時の VE セルに対する倍率とする。実噴射 TI と、`rf_korr` を掛ける前の
`rf_soll` を別々の履歴として扱う。既存の `analyze-nominal-response.py` が、読出し時刻、
完全燃料カット、回転数による質量流量、輸送・混合仮説を処理する。
TI に `rf_korr` を再度掛けない。

時刻 t における、輸送後の基準空気に対する燃料比を `q(t)`、セルごとの空気寄与を
`x[j,t]` とする。`x >= 0`、`sum(x) = 1`。仮定した輸送モデルの下で、
濃い側の観測は `sum(x[j,t] f[j]) <= q(t)`、薄い側の観測は逆向きの制約になる。
O₂ 電圧を空燃比の誤差量へ変換しない。

各観測が満たされた後、その観測の損失・勾配はゼロになる。濃い側の予測確率を
さらに高めるためだけに VE を下げ続ける対数尤度とは異なる目的関数を使う。

```text
value_i = X_i f + bank_i b
residual_i = value_i - clip(value_i, lower_i, upper_i)
objective = 1/2 sum(weight_i residual_i²)
          + penalty/2 sum((f_j - 1)²) + bankPenalty/2 b²
```

正則化は満たされた制約の内側で不要な変更を抑える。`rf_korr` の指数 α ではない。
ただし正則化で一意な解が出ても、実車データが各セルを一意に決めたことにはならない。
その区別を下記のプロファイル検証で保持する。

## 時間区間から得る情報

0401 Slave `0x01D6A2` / `0x01DC42` の I・P 更新式に従う。

```text
ΔSTFT = ∫(Ki_pos × lean_I - Ki_neg × rich_I)dt + ΣP
```

記録 BIN の Ki/Kp テーブルの全域最大値を用い、実行済み P カウンタの増分を m とすると、
`ΣP` は `[-m Kp_neg_max, +m Kp_pos_max]` の範囲となる。P 動作の方向が交互とは仮定しない。
ここから濃い側・薄い側の積分時間の下限を得る。P 待機は I 動作時間に含めない。
制御リセット、上限変更、Master/Slave 転送の未観測遅れが区間内にないことと、
公称 10 ms タスク周期は成立条件として出力する。

運転点の保持条件、1 秒や 3.5 秒の採用待ち、両バンク2周期の完了条件は置かない。
移動するセル寄与について `min_t x[j,t]` と `max_t x[j,t]` を求め、
燃料比の時間重み付き分位点と組み合わせて線形制約へ外側から近似する。
この近似は情報を失う場合があるが、正のセル倍率について固定運転点を仮定しない。

O₂ の一回の読取りは別扱いとする。読取り窓の「どこかで」濃い／薄いのであり、
窓全体が同じ側だったとは主張できない。時間割合の制約を流用せず、
濃い側は窓内燃料比の最大値、薄い側は最小値を使って外側から制約する。

## 検証と出力

```powershell
npm run verify:response-bounds
npm run analyze:response-bounds -- <session-directory>
npm run analyze:response-bounds-cross-log -- <analysis.json> <other-session-directory>
```

先行する記録較正付き DME 再生、nominal-response 再生の SHA とソースハッシュを照合する。
出力は `archive/response-bounds/<session-id>/analysis.json` と `fits.json`。
ログ・BIN・計算マップを公開ディレクトリに置かない。

- 外側4区間、内側3区間、20秒の間隔を空けた検証。バンクを別々の学習／検証側へ分離しない。
- 正則化の候補は内側区間のみで選び、外側の未使用区間で制約違反を採点する。
- 輸送仮説は、先行する同一ログ内の入れ子検証が選んだものを固定する。
  別走行での再現性検証という意味ではない。
- 読取り位置を開始／中央／終了に変え、燃料カット境界も変えた履歴を再構築する。
  中央時刻では未使用だったセルも消さず、全480セルの寄与を保持する。
- 各対象セルを最小・最大に動かし、全ての制約で当該フィットより悪化しない別解を
  線形計画で求める。この範囲は**条件付きの別解範囲**であり、統計的な信頼区間ではない。
- 探索範囲0.3〜1.7の全域が許されるセルを、補正不要のセルと区別する。
- `fullFitFactor` と時間分割／読取り時刻／正則化の感度を別々に保存する。
  全ログで再フィットしたマップの成績を未使用区間での成績と混同しない。

検査には、正しい VE に対する増量・I 減量、濃い側のみの有限な補正、
保持しない二セル軌跡からの既知倍率の復元、未識別のセル組合せ、矛盾する観測、
一回の読取りと時間割合の区別、500個の移動軌跡と500個の I/P 履歴を含む。

この推定が求めるのは、仮定した輸送と入力再構築の下での基準空気倍率。
実噴射量を入力としているため、書込み後の閉ループを再現した検証ではない。
ブラウザの自動補正へ採用する前に、残る入力・モデル依存性とセルごとの再現性を解決する。

## 別ログへの適用と候補の限定

`analyze-response-bounds-cross-log.py` は同じ記録 BIN・同じ VE マップでの別ログに
候補を当てる。旧ログに実噴射 TI が無い場合は、直接読取りの `rf_soll`、`rf_korr`、
STFT、BA から燃料を再構成する。λ OFF の燃料履歴は推測せず未知にする。
再構成燃料に0/3/5/10%の幅を置いた感度試験を併記する。この幅は実測の信頼区間ではない。

比較は全セルの候補、対象域のうち未変更値を許さないプロファイルを持つセルだけの候補、
そのセルを外側4分割の推定値のうち未変更値に最も近い倍率に留めた候補の3つ。
後者は今回の減量候補の感度を確認する処理であり、正しい減量幅を確定する規則ではない。
いずれも BIN 出力や自動採用を許可しない。

**2026-10-12 の訂正:** 後者の出力名 `conservative` は `weakestFold` に変更した。
2400 rpm の −2.7% は、強い情報を持つ通過を学習側から除くことで変更抑制項が倍率を
1 に戻した結果だった。「保守的な較正値」としては扱えない。切り分けと、変更抑制項を
使わない範囲計算は [63-response-identification.md](63-response-identification.md) を参照。

Session 968 による全域フィットは、再構成燃料を用いた Session 967 の比較では
全域の制約違反を増やした。全域候補は採用しない。対象2セルだけの比較では
両方の輸送仮説・燃料幅の全ケースで全域 RMS が悪化しなかった。
これは候補を局所化する根拠であり、実車での修正量の検証完了を意味しない。
