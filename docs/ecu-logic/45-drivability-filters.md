# 45 — ドライバビリティ・フィルタ（トルク要求の角の取り方）

用語は `00-glossary.md`。負荷鎖は `10-load-path.md`。
アドレスは **XDF アドレス**が主表記（ツールが編集する 64 KB パーシャル BIN ではこれがそのままオフセット）。
1 MB フルコンテナでは **master: XDF そのもの**、slave: `0x88000 + XDF`。

**値の出典**: `Full 211323000401PD31_TERRA.bin`。**自分の BIN を読んでから編集すること。**

> 本文書の中核（`FUN_00017052` / `FUN_00017400`）は `graph.json` で `stmts=0` だったため、
> **逆アセンブルで初めて機構が判った**部分である。方向（大きい／小さいでどちらに動くか）は
> 3 系統の独立検証を通してある（§10）。

## 0. 名前の読み解き

ドイツ語の略語なので、まず分解する。

| 記号 | ドイツ語 | 意味 |
|---|---|---|
| `KF` | **K**enn**f**eld | 3D マップ |
| `KL` | **K**enn**l**inie | 2D カーブ |
| `K_` | **K**onstante | 定数 |

| 名前 | 分解 | 日本語 |
|---|---|---|
| `KL_MD_LS_DMD` | **M**o**m**ent ＋ **L**ast**s**chlag（荷重の打撃）＋ d**M**o**m**ent | ティップイン時の許容トルク変化率を、踏み込み速度で補正 |
| `KL_MD_DASHPOT_DMD` | ＋ dashpot（緩衝器） | ティップアウト時の許容トルク変化率を、戻し速度で補正 |
| `KF_MD_LS_SPORT` / `_KOMF` | ＋ Sport / Komfort | ティップインの許容変化率（回転数×トルク） |
| `KF_MD_LS_DELTA_VER` | ＋ **Ver**zögerung / Verlauf | 残りトルク差による補正（軟着陸） |
| `KF_MD_DASHPOT` / `_FAKTOR` | | ティップアウトの許容変化率／その係数 |
| `KF_MD_WE` | ＋ **W**ieder**e**insetzen（再投入） | 燃料カット復帰時のトルク復帰レート |
| `KF_EGAS_WDK` | **E**lektronisches **Gas**pedal ＋ **W**inkel **D**rossel**k**lappe | 電子スロットルのスロットル板角度 |
| `KF_EGAS_WDK_KH` | ＋ **K**at**h**eizung（触媒暖機） | 同・触媒暖機用 |
| `KF_LLS_TV` | **L**eer**l**auf**s**teller（アイドル調整弁）＋ **T**ast**v**erhältnis（デューティ比） | アイドル弁の開度 |

`MD_FW_FILTER` = その制限後の値、`D_MD_REL` = 要求の変化率、`RF` = **R**elative **F**üllung、
`GANG` = ギア段、`Notlauf` = 非常走行。

## 1. 全体像 — これは「フィルタ」ではなく「スルーレート・リミッタ」

`FUN_00017052`（master `0x017052`, 942 B）が **ドライバー要求トルクの角を取る本体**。

```
MD_FW_FILTER = FUN_00017052(MD_FW)                 呼び出し元 master 0x016858
MD_IND_WUNSCH = MD_FW_FILTER + MD_SAWE_FILTER      master 0x016876
```

**普通のローパスフィルタではない。** 入力を常に鈍らせるのではなく、
**要求が許容量以内なら一切手を加えず素通しし、超えたときだけ頭打ちにする。**

適用部（ティップイン側、master `0x173A2`）:

```
上限 = MD_FW_FILTER + MD_LS_DELTA
if (MD_FW <= 上限)  MD_FW_FILTER = MD_FW        ← 素通し
else                MD_FW_FILTER += MD_LS_DELTA  ← 頭打ち（MD_DYN_ST bit6 を立てる）
```

ティップアウト側（`0x171E2`）は完全な鏡像（`sub`）。

> **∴ `MD_LS_DELTA` / `MD_DP_DELTA` は「10 ms あたりトルクを最大いくつ動かしてよいか」という許可量。**
> **大きい＝速く動ける＝ダイレクト＝シャクリやすい。小さい＝ゆっくり＝滑らか。**
> 単位は 0.1 Nm/10ms（`MD_FW_FILTER` が `K_MD_SK_MAX` = 800.0 Nm と比較されることから確定）。

### 分岐と作動条件

| 条件 | 行き先 |
|---|---|
| `MD_FW ≥ MD_FW_FILTER` | **ティップイン**（Lastschlag）→ `MD_LS_DELTA` |
| `MD_FW < MD_FW_FILTER` | **ティップアウト**（Dashpot）→ `MD_DP_DELTA` |

**完全バイパス**（master `0x173C6`）: `N < K_MD_DF_NMIN`(500 rpm) **または**
`V < K_MD_DF_VMIN`(3 km/h) **または** 駆動力が繋がっていない（`S_KRAFTSCHLUSS` / `GANG`）。
このとき `MD_FW_FILTER = MD_FW`（無制限）で両 DELTA をクリア。
→ **停車中・ニュートラルでは丸ごと効かない。**

## 2. ティップイン（踏み込み） — `KL_MD_LS_DMD` とその仲間

許容量は 4 つの掛け算でできている。

```
MD_LS_DELTA = KF_MD_LS_SPORT または KOMF( MD_LS_KF , N )      ← ①どこで走っているか
            × 段別係数[GANG] / 1024                            ← ②何速か
            × KL_MD_LS_DMD( D_MD_REL ) / 1024                  ← ③どう踏んだか
            × KF_MD_LS_DELTA_VER( MD_FW − MD_FW_FILTER , D_MD_REL ) / 1024   ← ④あとどれだけ
            （0x2710 = 1000.0 Nm/10ms でクランプ）
```

### ① どこで — `KF_MD_LS_KOMF`（master `0x9396`, z `0x93AE`）

**回転数と負荷の依存はここにある。** 縦＝回転数、横＝そのときのトルク（`MD_LS_KF`）、値＝Nm/10ms。

| rpm ＼ Nm | 20 | 50 | 100 | 200 | 250 | 400 |
|---|---|---|---|---|---|---|
| 1500 | 3.2 | 2.0 | **1.7** | 3.5 | 4.2 | 9.6 |
| 1750 | 3.8 | 3.2 | 2.4 | 3.7 | 4.5 | 12.0 |
| 2000 | 9.4 | 6.5 | 4.7 | 8.2 | 16.8 | 20.5 |
| 2500 | 30.0 | 7.8 | 4.3 | 10.9 | 26.2 | 29.2 |
| 3000 | 30.0 | 7.8 | 4.3 | 10.9 | 26.2 | 29.2 |
| 5000 | 30.0 | 7.8 | 5.1 | 10.9 | 26.2 | 29.2 |

**最小は 1500 rpm × 100 Nm の 1.7。** 「低回転で軽く流していて、そこから踏み増す」という、
シャクリが最も出やすい条件がピンポイントで抑えられている。
**30.0 は事実上の上限＝制限なし**。低トルク側と高トルク側は 2500 rpm 以上でほぼ開放されており、
残るのは 50〜200 Nm の帯だけ。

`KF_MD_LS_SPORT`（master `0x9334`）は **2500 rpm 以上が全セル 30.0**。
→ **Sport ボタンを押すと、2500 rpm より上ではティップイン制限が事実上消える。**

> **横軸は「今の要求」ではなく `MD_LS_KF` = 前回の `MD_FW_FILTER`**（＝前サイクルの制限後トルク）。
> XDF のラベル `md` は紛らわしい。`K_MD_LS_CONFIG`(master `0x91DC`) = 1 のとき絶対 Nm、
> 0 なら相対 % になり**マップの意味が変わる**ので、表を作り直さずに切り替えてはいけない。

**Sport / Komfort の選択**: `SCHALT_M_ST` bit0 が立ち、**かつ** `0xFFEB62`（FGR＝クルーズ状態）が 1 でないとき Sport。
→ **クルーズ作動中は Sport でも Komfort が強制される。**
なお `SCHALT_M_ST` bit0 は Servotronic のカーブ選択と同じビット。

### ② 何速か — 段別係数（master `0x927C`、16 bit、/1024）

| ギア | 0/範囲外 | 1 | 2 | 3 | 4以上 |
|---|---|---|---|---|---|
| 係数 | 1.00 | **0.75** | 0.80 | 0.90 | 1.00 |

低いギアほど小さい＝強く抑える。トルク倍率が高くシャクリが最悪だから。
**この形自体が「大きい＝ダイレクト」の独立した証拠**（逆なら 1 速が最も自由になり、成立しない）。
`GANG > 7` は**索引 0 に落ちる**（＝1.00、無制限）。

### ③ どう踏んだか — `KL_MD_LS_DMD`（master `0x940E`, y `0x9418`）

**このカーブには回転数軸も負荷軸もない。** 軸は `D_MD_REL` ただ一つ ＝
**トルク要求が 20 ms でどれだけ変化したか**（10 ms タスクの 2 サンプル差分）。
つまり**足をどれだけ速く動かしたか**だけで選ばれ、**5 つの数値はすべての回転数・負荷に一律に効く。**

| 軸 %/s | 全開まで | 実際の運転 | 倍率 |
|---|---|---|---|
| 0 | — | 定常 | 1.00 |
| **300** | 0.33 秒 | 意識して踏み増す | **0.72（最も抑えられる）** |
| 800 | 0.125 秒 | 追い越しでスッと | 1.00 |
| 1500 | 0.067 秒 | 蹴り込む | 2.00 |
| 2500 | 0.04 秒 | 床まで一気に | **3.00（ほぼ制限解除）** |

**非単調なのが味付けの本体**。中くらいの踏み方＝駆動系のガタをそっと通過する速度域＝
シャクリが最も耳につく領域を狙って抑え、床まで蹴り込んだら開放する。

> 変化率が負（戻し方向）のときは `0x1723C` で 0 にクリップされるので、
> **ティップイン側は自分の半分の信号しか見ない。**

### ④ あとどれだけ — `KF_MD_LS_DELTA_VER`（master `0x9424`, z `0x9438`）

縦＝踏み込み速度 %/s、横＝**残りトルク差**（`MD_FW − MD_FW_FILTER`）Nm。

| %/s ＼ 残り Nm | 10 | 40 | 80 | 100 | 120 | 150 |
|---|---|---|---|---|---|---|
| 0 | **0.158** | 0.842 | 1.316 | 2.187 | 3.136 | 4.401 |
| 300 | 0.554 | 0.921 | 1.316 | 1.633 | 2.266 | 3.215 |
| 1000 | 0.712 | 0.921 | 1.237 | 1.475 | 1.554 | 2.107 |
| 2000 | 0.763 | 0.921 | 1.158 | 1.396 | 1.475 | 1.949 |

**残りが少ないほど許容量が小さい**（10 Nm 手前で 0.16 倍）。
→ **直線ランプではなく、目標に近づくほど減速する一次遅れ。「そっと着地」させている。**
ここを見ずに ① だけ触ると、ティップインの形を読み違える。

## 3. ティップアウト（戻し） — `KL_MD_DASHPOT_DMD` とその仲間

```
MD_DP_DELTA = KF_MD_DASHPOT( MD_FW_FILTER , N ) / 1024
            × 段別係数[GANG] / 1024                      （master 0x929E）
            × MD_DP_FAKTOR / 1024                        （ラッチ値、下記）
            × KL_MD_DASHPOT_DMD( −D_MD_REL ) / 1024
```

`KF_MD_DASHPOT`（master `0x92D2`, z `0x92EA`、Nm/10ms）: 900 rpm/10 Nm で 1.0、6000 rpm/350 Nm で 26.0。
**低回転・低トルクほど小さい＝ゆっくり落とす。**

段別係数（master `0x929E`）: 1速 **0.60** / 2速 0.84 / 3速 0.91 / 4速 0.93 / 5速以上 1.00。
ティップイン側より 1 速の抑えが強い。

`KL_MD_DASHPOT_DMD`（master `0x93F8`, y `0x9402`）:

| 戻す速さ %/s | 0 | 25 | 50 | 100 | 200 |
|---|---|---|---|---|---|
| 倍率 | 1.0 | 1.0 | 1.0 | 1.090 | 1.200 |

**50 %/s までは 1.0 で無効。** バッと離したときだけ最大 1.2 倍まで許容量が増える
＝**速く戻したときの方がトルクを速く落とす**。軸の幅がティップイン側（〜2500 %/s）より
一桁狭い点に注意。

> **`MD_DP_FAKTOR` はラッチ値である。** `KF_MD_DASHPOT_FAKTOR`（master `0x946A`, z `0x9478`、0.20〜1.00）は
> **ダッシュポットが初めて頭打ちした瞬間に 1 回だけ採取**され、そのイベント中は凍結される
> （`MD_DYN_ST` bit4 で判定、master `0x1716C`）。毎回引き直されていない。
> 参照軸は `(N, MD_FW)` で**生の要求**を使う — 同じ分岐内で `KF_MD_DASHPOT` は
> `MD_FW_FILTER` を使うのと対照的。

## 4. 燃料カット復帰 — `KF_MD_WE`

`FUN_00017400`（master `0x017400`, 306 B、これも `stmts=0` から回収）。
`SA_WE_ST` bit1/bit3 と `DYN_ST` bit1 で分岐し `KF_MD_WE(MD_WUNSCH_REL, N)` を引く。
出力 `MD_SAWE_FILTER` は §1 のとおり `MD_IND_WUNSCH` に**加算**される。

`KF_MD_WE`（master `0x9492`, z `0x94AA`）、**z = Nm/10ms**:

| rpm ＼ 要求 | 0 % | 5 % | 10 % | 20 % | 50 % | 100 % |
|---|---|---|---|---|---|---|
| 700 | 40 | 40 | 40 | 50 | 50 | 50 |
| 800 | 10 | 10 | 20 | 50 | 50 | 50 |
| 1200 | 4 | 10 | 20 | 50 | 50 | 50 |
| 1500〜6000 | **3** | 10 | 20 | **50** | 50 | 50 |

- **低回転が速いのはエンスト回避**
- **高回転で軽く触れたときが最も穏やか**（3 Nm/10ms = 300 Nm/s）
- **20 % 以上踏んだら常に即時**（50 = 5000 Nm/s）— 待たせない

> **§2/§3 との役割分担**: §2/§3 は「アクセル操作」に対する制限、§4 は「燃料カットからの復帰」に対する制限。
> **別経路で両方が `MD_IND_WUNSCH` に入る。** 惰性走行から踏み直したときのショックは §2 ではなく §4。

## 5. スロットル目標 — `KF_EGAS_WDK`

`egas_compute_throttle_target`（master `0x0270B0`）:

```
egas_wdk = KF_EGAS_WDK(N, RF_SOLL_WDK)
if (ask_zustand_dpr&1)==0 && (AVAN1_ST&0x10)!=0:
    egas_wdk += (AVAN1_SOLL_FAKTOR × (KF_EGAS_WDK_KH(...) − KF_EGAS_WDK(...))) >> 14
egas_wdk = min(egas_wdk, 1000)      ; 100.0 % ハードクランプ
WDK_SOLL = egas_wdk
```

**縦軸は `rf` ではなく `RF_SOLL_WDK`**。ここが非自明で、
**アイドル弁が受け持つ空気分 `ML_SOLL_MAX_LLS` を引いてから**、さらに
`K_EGAS_WDK_TAU`(255) の PT1 で遅らせた値で引かれる。
→ rf だけ見て行を予想すると系統的に高く外す。

| rf | 600 | 1700 | 3000 | 5000 | 6000 | 7000 | 8000 |
|---|---|---|---|---|---|---|---|
| 1.00 / 1.05 | 70 | 95 | **100** | 100 | 100 | 100 | 100 |
| 0.95 | 70 | 95 | 100 | **82.9** | **83.5** | **83.8** | 100 |

**rf = 1.0 で初めて全開**（0.95 では 5000–7000 rpm で 83 % 程度）。
これが `70-max-power-methodology.md` §13.2「SU1 を上げてもスロットルは開かない」の根拠。

3 枚目 `kf_egas_wdk_ask`（master `0x8828`）がスノーケルフラップ開時に選ばれる。

**方向性**: 上げればスロットルは早く開くが、**Füllungsregler が閉ループで後から補正する**ので
定常は戻される。**効くのは過渡だけ。** 100 と書かれた欄を上げても意味はない。

## 6. アイドル調整弁 — `KF_LLS_TV`

`lls_tv_calc`（master `0x025D0A`）。**軸は (回転数, 要求空気量 kg/h)**、値はデューティ %。

```
blend  = KF_LLS_TV + (AVAN1_SOLL_FAKTOR × (KF_LLS_TV_KATH − KF_LLS_TV)) >> 14
x      = PT1(max(blend, KL_LLS_TV_MIN_START(N)), K_LLS_TAU2=32)
LLS_TV = (x − K_LLS_TV_DREHPUNKT[30.08%]) × KL_LLS_UB_KORR(UB) >> 8 + x
         clamp K_LLS_TV_MIN(14%) … K_LLS_TV_MAX(97%)
Notlauf(LLS_ST&0x40): K_LLS_TV_NOTLAUF_MIN(3%) … _MAX(75%)
```

**`K_LLS_TV_DREHPUNKT` は電圧補正の「支点」**（Drehpunkt ＝ 回転の中心）。
30.08 % を軸にシーソー状に補正するので、**その付近では電圧の影響を受けない。**

## 7. 横断 — `AVAN1_SOLL_FAKTOR` が 3 つを同時に動かす

`_KH` と `_KATH` は**同じ仕組み**で、**1 つの係数**が 3 箇所で同じ線形ブレンドを駆動する。

| 対象 | 普段 | 触媒暖機用 | 関数 |
|---|---|---|---|
| 充填目標 | `kf_rf_soll` | `kf_rf_soll_kath` | `rf_soll_calc` |
| スロットル角度 | `KF_EGAS_WDK` | `KF_EGAS_WDK_KH` | `egas_compute_throttle_target` |
| アイドル弁 | `KF_LLS_TV` | `KF_LLS_TV_KATH` | `lls_tv_calc` |

触媒暖機が働くのは `KL_VAN_KATH_TMOT` により
**始動後およそ 120–130 秒、かつ始動時水温 −12〜+32 °C のときだけ**。

> **暖機後は `AVAN1_SOLL_FAKTOR = 0` で、暖機用 3 枚は一切効かない。**
> 冷間始動の最初の 2 分の話であり、パワーにも暖機後のドライバビリティにも無関係。

## 8. `KL_TAN_NTC` — これだけ性格が違う

`tan_calc`（master `0x01B3AA`）:

```
TAN_ROH = klu_wint(KL_TAN_NTC, tan_ad)        ; AD 値 → °C
tan_filter = IIR(TAN_ROH, K_TAN_TAU = 1300 ms)
TAN = (tan_filter + 2) >> 2
```

| AD 生値 | 107 | 394 | 567 | 744 | 882 | 964 | 1002 | 1019 |
|---|---|---|---|---|---|---|---|---|
| °C | 140 | 80 | 60 | 40 | 20 | 0 | −20 | −48 |

**チューニング用の表ではなく、NTC センサの特性線形化テーブル。**
動かす＝温度計に嘘をつかせることで、
`TAN` → `KL_RF_TAN_KORR` → `RF_PT_KORR` → `rf_soll` → **燃料全体**へ波及する
（`70-max-power-methodology.md` §17.1 で code-confirmed）。

> **センサを別品番に交換したとき以外は触らない。**
> 「吸気温を低く見せて濃くする」は充填モデル全体を歪める。濃くしたいなら `KF_TI_N_RF_VL`。

## 10. 症状 → どこを見るか

| 症状 | 見るもの |
|---|---|
| アクセルを離すとガクッとくる | `KF_MD_DASHPOT` を下げる／`KL_MD_DASHPOT_DMD` を下げる |
| 踏んだ瞬間に駆動系がガクガクする | `KF_MD_LS_KOMF` の**該当回転数・トルクのセル**を下げる |
| 惰性走行から踏み直すとドンとくる | **`KF_MD_WE` を下げる**（ティップイン側ではない） |
| 踏み始めの付きが悪い | `KF_MD_LS_KOMF` を上げる／`KF_MD_LS_DELTA_VER` の残り少側 |
| 1〜2 速だけ穏やかにしたい | 段別係数（master `0x927C`） |
| 2500 rpm 以上でだけ穏やかにしたい | Sport マップを使っているなら `KF_MD_LS_SPORT`（全部 30.0 になっている） |
| 冷間 2 分だけ挙動がおかしい | `KF_EGAS_WDK_KH` / `KF_LLS_TV_KATH` |
| アイドルが安定しない | `KF_LLS_TV` |

**「2000 rpm の踏み増しだけ直したい」なら `KL_MD_LS_DMD` ではなく `KF_MD_LS_KOMF`。**
前者は回転数軸を持たないので全域に一律に効く。

## 11. 検証の経緯と、ログ上の注意

### 方向はどう確定させたか

`Nm/10ms` という単位表記は**量**を示すだけで、**適用のされ方**は示さない。
確定させたのは適用部の `add.w d2,d3` / `sub.w d2,d3`（フィルタ状態への加減算）である。
さらに較正自身の形から 2 つの独立した裏取りが取れた:

- **Sport が Komfort より 36 セル中 31 セルで大きい** — Sport が「よりダイレクト」である以上、
  大きい＝ダイレクトで確定
- **1 速の段別係数が最小**（0.75 / 0.60）— シャクリが最悪の 1 速を最も強く抑える、という
  物理的に正しい形。逆の解釈だと 1 速が最も自由になり成立しない

### ログ上の注意

**`MD_LS_DELTA`(`0xFFD8B8`) / `MD_DP_DELTA`(`0xFFD8BA`) はどこからも読まれていない。**
1 MB 全域を走査して、書き込み 2 箇所ずつのみ。**観測専用の値**である。

> **ログで 0 が出たときは 2 通りの意味があり、区別がつかない。**
> ① §1 の完全バイパス（無制限）
> ② `MD_DYN_ST` bit0 ＋ `KF_MD_LS_WE > MD_SAWE_VERH` による**凍結**（許容量 0 ＝ 最大制限）
> `MD_DYN_ST`(`0xFF8180`) のビットで判別する — bit6 = ティップイン制限が実際に効いた、
> bit4/5 = ダッシュポット制限が効いた、バイパス時は bit4–6 がクリアされる。
> なお `KF_MD_LS_WE`(master `0x94F4`) は**全ゼロ**なので、②は本 BIN では到達しない。

### 確立できなかったこと

| 項目 | 状態 |
|---|---|
| `0xFFEB62`（Sport 選択の第 2 条件） | FGR（クルーズ）状態バイトと判断したが、値の意味は未確定 |
| `MD_DYN_ST` の全ビット定義 | bit0/4/5/6 のみ確認 |
| `KF_MD_LS_DELTA_VER` の `VER` の語 | Verzögerung か Verlauf か未確定（機能は確認済み） |
| 段別係数テーブルの XDF 名 | XDF に定義が無い。アドレスと形状のみ確認 |
