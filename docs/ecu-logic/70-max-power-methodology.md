# 70 — 最大パワー方向のチューニング手順（CSL '0401'）

用語は `00-glossary.md`、負荷鎖の基礎は `10-load-path.md` を参照。

**値の出典**: すべて `Full 211323000401PD31_TERRA.bin` から復号した値。
**あなたの車両は Community Patch 派生なので、アドレス・スケーリング・ロジックは共通でも数値は違いうる。**
必ず自分の BIN を読んでから編集すること。

**アドレス表記**: 本文は **XDF アドレス**を主表記にする。ツールが編集する 64 KB パーシャル BIN では
XDF アドレス＝オフセット（両バンクとも）。1 MB フルコンテナでの対応は下表
（出典: `CSL_0401_Binary_Disassembly_Notes/docs/vanos_ds2_target_override.md` §0。本文書でも軸をバイト照合して再確認済み）。

| ノード種別 | bank | フル BIN オフセット |
|---|---|---|
| func / code | master | `addr` |
| param (XDF) | master | `addr` |
| func / code | slave | `0x80000 + addr` |
| param (XDF) | slave | `0x88000 + addr` |

> **注意**: `q.py` の `file=` 列は **master パラメータについて 0x80000 過大**。そのまま使ってはいけない。

# 第 0 部 — 先に読む

## 1. 要約

あなたが標準 M3 で使ってきた 3 つのパラメータは、**別々の軸に乗っており、うち 1 つはパワーに効かない**。

| パラメータ | bank / XDF | 実体 | 最大パワーへの効き |
|---|---|---|---|
| `KF_TI_N_RF_VL` | slave `0x0B30` | 全負荷時の噴射補正 `TI_F_STAT` | **効く。WOT の混合気そのもの** |
| `KL_MD_MAX_VL_RF_SU1` | master `0x8BFA` | トルクモデルが想定する全負荷充填 | **モデル。上げても出力は増えない**（§13.2） |
| `KL_EDK_VORST` | master `0x8132` | スロットル H ブリッジの PWM 前置補償 | **効かない**。効くのはティップイン feel |

そして **本当に WOT を支配しているのは、あなたがこのツールで既に触っている VE テーブル**
`kf_rf_soll (CSL Alpha-N)` master `0xD2FE` である。XDF の記述にこうある —
"This is the main volumetric efficiency table for the 0401 code"。
`k_rf_hfm_cfg = 0`（master `0xD202`）で **HFM(MAF) 経路は死んでおり、RF は純 alpha-n**。
つまり **VE 作業は最大パワーの前段そのものであって、別作業ではない。**

### 計測手段の制約（この手順書の形を決めている）

**ワイドバンド λ もダイナモも無い。EGT と DS2 ログだけ。** したがって:

- **目標 AFR を狙う手順は書けない。** 「WOT を λ 0.85 に合わせる」は実測できない。
- 代わりに **2 段に分ける**（STEP 4 → STEP 7）。VE を正しくしてから、`KF_TI_N_RF_VL` は
  **純正比の相対増量**としてだけ動かす。
- **`KF_TI_N_RF_VL` を希薄側へ振ってはいけない。** 確認する手段が無いので。

### 安全境界 — 先に読むこと

中核手法は **PATCH 状態（`KF_BZ_WDK_VL` = 102.3 %）のまま全開まで踏む**。
これは **λ≈1.0 で全負荷を回す**ことを意味する（純正 VL は λ≈0.85）。**純正より希薄側である。**

したがって:

- **EGT 計測は「あると良い」ではなく、この手法の必須条件。**
- EGT 上限を**先に**決めてから走る。
- 短いプルにする。連続全開をしない。高回転側は最後に回す。
- **`rf_korr`（EGT 由来の保護増量）は 5100 rpm 以上で厳密に 1.0** — つまり
  **ピークパワー回転域では EGT 保護は一切効かない**。そこの余裕は自分で作るしかない。

## 2. 標準 M3 との違い（ここを外すと以降を誤読する）

| | 標準 M3 (S54) | CSL '0401' |
|---|---|---|
| 負荷検出 | HFM(MAF) ベース | **純 alpha-n**（`k_rf_hfm_cfg = 0`） |
| `RF` の性質 | 空気量の**測定**に由来 | **(スロットル, rpm) からの計算値。空気量の測定ではない** |
| 主 VE テーブル | — | `kf_rf_soll` master `0xD2FE`、24×20 |

**転用できる勘**: `KF_TI_N_RF_VL` の使い方はそのまま通じる。全負荷の噴射補正という役割は同じ。

**転用できない勘**: 負荷検出まわり。特に —
**CSL では `rf` チャンネルを見ても実際の充填改善は見えない**。
`RF = kf_rf_soll(N, aq_rel_rf) × RF_PT_KORR × rf_korr` であって、スロットルと回転数の関数でしかない。
カムを動かしても、排気を変えても、**`rf` は 1 も動かない**。これは STEP 2 の VANOS 手順で決定的に効く。

# 第 1 部 — 手順

## 3. 順序は依存関係で決まる

```
  カムを動かす ──→ 実空気量が変わる ──→ VE テーブルが古くなる
  VE を直す    ──→ RF が変わる      ──→ 点火・トルクモデルの「読むセル」が移動する
```

∴ **VANOS → VE →（収束）→ 全開 → トルクモデル → 燃料 → 点火** の順。
**逆順にやると全部やり直しになる。**

各ステップは `目的 / 前提 / 操作 / ログで見るもの / 合格基準 / やめる条件` の型で書いてある。

---

## STEP 1 — Alpha-N (VE) のベースライン再導出

**目的**: 以降のすべての測定が意味を持つようにする。
**前提**: 吸気・排気を変更しているので**必須**。純正 VE は既に合っていない。

**操作**: 既存ツールの通常フロー（`60-tuning-logic.md`）。PATCH → ログ → 更新 → 書き戻し。

**ログで見るもの**: `la_f_regler1/2`（block 19 offset 40/42）。
**合格基準**: λ 積分器が全走行域で規定幅に入る。
**やめる条件**: 積分器がクランプに張り付く領域が残っている間は次へ進まない。

> **これが終わるまで、以降のどの測定も意味を持たない。**

---

## STEP 2 — VANOS で最大 VE を探す

**目的**: 吸排気変更後の実際のエンジンにとって最良のカムタイミングを見つける。

### 2.1 何を見るのか（ここが全部）

**`rf` を見ても改善は絶対に見えない。** §2 のとおり `RF` は計算値だから。

反応するのは **λ 積分器**:

```
カムが良くなる → 同じモデル RF に対し実空気が増える → 希薄化
              → 閉ループが燃料を足す → la_f_regler が上がる
```

∴ **ある運転点での最大 VE ＝ λ 積分器の要求が最大になるカム角**。

**なぜ VE が完璧でなくても成立するか**: 同一セル内でカム角だけを振るので、
そのセルの VE 誤差は**定数オフセットとして相殺される**。安定してさえいればよい。
これが STEP 2 を VE 収束前に置ける根拠。

### 2.2 運転点が逃げない（VANOS 側の利点）

`KF_EVAN1_SOLL` / `KF_AVAN1_SOLL` の軸は **(n, aq_rel)** であって `rf` ではない。
→ カムを変えても**目標セルが移動しない。正帰還なし。** 点火（rf 軸）とは対照的 — §12 に一覧がある。

### 2.3 走行中にカム角を直接指令できる（再フラッシュ不要）

`vanos_ds2_target_override.md` が逆アセンブルレベルで解明済み。**これが手順を現実的にしている。**

```
DS2:  12 07 0C <pin> <angle> 00 <XOR>
      pin 0x07 = 吸気バンク1 / pin 0x0A = 排気バンク1
      angle = 符号付きバイト、1 °KW 刻み、範囲 −20 … +80 °KW
      応答 payload[1]:  0 = 受理 / 2,3 = 範囲外 / 4 = 条件未成立
```

受理条件は `ZUSTAND_MOTOR & 0x1C`（LL|TL|VL）と `EVAN1_ST` bit3（油圧レディネス）**だけ**。
**車速判定も回転数判定も存在しない**（VANOS 診断ブロック全域の RAM xref 列挙で確認済み）。
「停車必須」はツール側（`RequiredVehicleStationary`）と純正 SGBD 手順の都合であって、DME の制約ではない。

保持は `b_diag`（DS2 セッション）依存。**キープアライブ `0x9E` を止めれば次の周期でマップ制御に自動復帰**
— これを**中断手順（フェイルセーフ）として使う**。

> **最初にやる 5 分の確認**: `0C 07 <angle> 00` を 1 回投げて応答 payload[1] を見る。
> 0 が返り `evan1_ist` が動けば経路は確定する。
> （master 側の葉ディスパッチは RAM 常駐テーブル経由で未追跡 — 元文書 §8 が自認している唯一の穴）

### 2.4 この経路特有の安全設計（DME の保護が外れる）

| # | 事実 | 必要な対処 |
|---|---|---|
| 1 | `K_EVAN1_SOLL_MIN/MAX`(slave `0x180C`/`0x180A`) と `KL_EVAN_SOLL_BEGR`(slave `0x1862`) が**バイパスされる**。残るクランプは −20/+80 のみ | **回転数・負荷に応じた探索範囲制限を自分でかける**（補足: 本 BIN の `KL_EVAN_SOLL_BEGR` は 5 点すべて 60.0 ＝ MAX と同値で実質非拘束） |
| 2 | オーバーライドは −20…+80 を受けるが、**マップは吸気 0–60 / 排気 0–45 しか保持できない** | **探索窓を保存可能域に閉じ込める。** でないと書き戻せない最適点を見つけてしまう |
| 3 | 偏差 `EVAN1_XD` > `K_EVAN1_XD_MAX`(slave `0x1824` = 10.0 °KW) で **VANOS DTC が記録される** | ステップではなく**ランプで動かし、`evan1_ist` の追従を待ってから次へ**。到達不能角度を投げない |
| 4 | 学習中（`VAN_ADAP_ST` bit4/5）は受理されない | 開始前に学習状態を確認。VANOS 学習値はクリアしておく |
| 5 | **排気の受理は吸気バンクのレディネスに依存**（`finding_vanos_readiness_flag_asymmetry.md`。設計上の結合でありバグではない） | 排気だけ振る場合も吸気側 `EVAN1_ST` bit3 を確認 |
| 6 | 点火・充填モデルは**マップ上の cam を前提**にしている | 高負荷の探索は最後に、EGT と `tz`（遅角の有無）を見ながら狭い範囲で |

### 2.5 マップの実体

| | 吸気 `KF_EVAN1_SOLL` | 排気 `KF_AVAN1_SOLL` |
|---|---|---|
| XDF (slave) | `0x18D0`、z `0x1910` | `0x1BF6`、z `0x1C36` |
| 形 | 16×16、signed byte | 16×16、signed byte |
| z 式 | `70 + x` → 表示 70–130 | `128 − X` → 表示 128–83 |
| raw 範囲 | **0–60 °KW** | **0–45 °KW** |
| 上下限 | `K_EVAN1_SOLL_MIN/MAX` 0.0 / 60.0 | `K_AVAN1_SOLL_MIN/MAX` 0.0 / 45.0 |
| x 軸上端 | 7800 rpm | **7400 rpm** |

- **範囲外を書いても無言でクランプされる**（XDF は入力を許してしまう）。
- y 軸は両方とも **最大 85.0 % aq_rel** → **WOT は最終行にクランプ**。
  しかも純正は 65 % 行と 85 % 行が**バイト同一**。WOT で触るのは実質 1 行。
- **排気カムは 7400 rpm より上にブレークポイントが無い。** 8000 rpm リミットまで最終列を保持＝**上端に穴**。

### 2.6 ログと前提条件

**ブロック 35 "VANOS/CSL Measurements"（39 B）**:
`evan1_ist`(off 2) / `evan1_soll`(off 4) / `avan1_ist`(off 6) / `avan1_soll`(off 8)、いずれも 0.1 °KW。

> **`ist` が `soll` に到達していないサンプルは測定として無効。** 必須ゲート。

**前提条件（ほぼツールの PATCH がそのまま満たす）**: MAP 積分 off（`k_rf_cfg` 0x12→0x02。
切らないと `rf_p_saug_i` が改善分を黙って吸う）／ LTFT 凍結（`K_LAA_TMOT_MIN` slave `0x4824`
69 °C → 100 °C）＋ RESET ADAPT ／ 高負荷でも閉ループ維持（`KF_BZ_WDK_VL` → 102.3 %）／
水温 ≥ 75 °C・油温 ≥ 40 °C。

**レートについて**: {3,19,35} で約 3.0 Hz と遅い。しかし
**カムスイープは定常測定なので低レートは害にならない。** 各点で保持して平均を取ればよい。
サンプル不足が効くのは STEP 4 の全開プルの方。

**合格基準**: 各セルで λ 積分器のピークが再現する。
**やめる条件**: `evan1_ist` が追従しない／DTC が出る／EGT が上限に近づく。

## STEP 3 — VE 再導出（収束ループ）

**目的**: STEP 2 で実空気量が変わった。VE テーブルはもう古い。

STEP 1 ↔ STEP 2 を、**カム最適点の移動と VE 補正量がともに閾値未満**になるまで反復する。
実務上は 2〜3 周で収まるはず。収束しない場合は測定条件（暖機・過渡除外）を疑う。

---

## STEP 4 — 全開域まで VE を伸ばす（PATCH 維持）

**目的**: 中核手法の 1 段目。**全開でも λ 閉ループを生かしたまま VE 誤差を測る。**

`KF_BZ_WDK_VL` が 102.3 % のままなら VL に入らない → λ 積分器が全開でも生き続ける。

**§1 の安全境界を必ず読んでから走ること。** λ≈1.0 で全負荷を回している。

**ログ**: block 3 の `rf`(off 8) `aq_rel`(off 20) `wdk1`(off 27) `tabg`(off 14)、block 19 の `la_f_regler`。

**サンプル数の現実**:

| ブロック構成 | 実現レート（算術値） |
|---|---|
| {3} | 11.1 Hz |
| {3,35} | 5.4 Hz |
| **{3,19}（現状ツール）** | **4.1 Hz** |
| {3,19,35} | 3.0 Hz |
| {3,19,35,83} | 2.2 Hz |

3000→8000 rpm のプルは 5〜7 秒。5.4 Hz でも **27〜38 サンプル**しか取れず、
`KF_TI_N_RF_VL` の 18 列より粗い。**1 本のプルでセル別に詰めるのは不可能。反復が前提。**

> このレートは**実測されていない**（算術値）。リポジトリ自身が
> 「both documented sample rates are wrong」と記録している。

## STEP 5 — SU1 を実測 RF に合わせる

**目的**: トルクモデルを実態に一致させる。**出力を増やす作業ではない**（理由は §13.2）。

STEP 4 のログから **スロットル全開サンプルの `rf` 対 rpm** を取り出す。
**それが `KL_MD_MAX_VL_RF_SU1` が本来入れるべき中身そのもの。** ダイナモは要らない。

`KL_MD_MAX_VL_RF_SU1` master `0x8BFA`（x）/ `0x8C1E`（y）、18 点、raw/1000、量子化 0.001。

現在値:

| rpm | 600 | 800 | 900 | 1000 | 1200 | 1300 | 1700 | 1900 | 2000 |
|---|---|---|---|---|---|---|---|---|---|
| rf | 1.33 | 1.10 | 1.08 | 1.04 | 0.67 | 0.70 | 0.96 | 1.11 | 1.16 |

| rpm | 2100 | 2400 | 2700 | 3200 | 3400 | 3600 | 4400 | 4600 | 7400 |
|---|---|---|---|---|---|---|---|---|---|
| rf | 1.14 | 0.97 | 0.99 | 0.99 | 1.07 | 1.12 | 1.11 | 1.17 | 1.17 |

> **4600 → 7400 rpm がひと区間**しかない。パワーバンド全域が 1 本の直線で表されている。
> 実測に合わせるならここが最も雑で、最も改善余地がある。

**併せて確認**: `KF_MD_MAX_LA_VL`（master `0x8BB2` / z `0x8BC1`）は
**全負荷で想定する λ = 0.851562（1760 rpm 以上）、0.898438（1240 rpm 以下）**。
STEP 7 で WOT 混合気を変えるなら、**この表も一緒に動かさないとトルクモデルの効率項が嘘になる**（§13.3）。

## STEP 6 — PATCH を戻し、VL 境界を確認

`KF_BZ_WDK_VL`（master `0xAC44` / z `0xAC54`）を純正値へ戻す。

| rpm | 1300 | 2000 | 3000 | 4000 以上 |
|---|---|---|---|---|
| VL 突入 WDK | 35.0 % | 55.0 % | 63.0 % | 65.0 % |

ヒステリシス `K_BZ_WDK_VL_HYST`（master `0xAC06`）= 6.0 % → 離脱は 29 / 49 / 57 / 59 %。
tmot 軸は 4 行すべて同一＝**不活性**。

**VL に入った瞬間に切り替わるもの**:

| | 部分負荷 | → 全負荷 (VL) |
|---|---|---|
| 燃料 | `KF_TI_N_RF` | **`KF_TI_N_RF_VL`** |
| 点火 | `KF_TZ_GRUND` | **`KF_TZ_VL`** |
| 気筒別補正 | — | `KL_TI_N_VL_ZYL1..6` が起動 |
| λ 制御 | 閉ループ | **切れる（開ループ）** |

> **重要**: 「全負荷」は 100 % ペダルのことではない。**約 2/3 スロットルから上はすべて VL。**
> つまり `KF_TI_N_RF_VL` の支配域は思っているより広い。

**現状ツールの限界**: ログに VL 判定が無い。`wdk1`（block 3 offset 27）を
`KF_BZ_WDK_VL(N)` と比較すれば判定できるが、未実装（付録 A）。

## STEP 7 — WOT 燃料 `KF_TI_N_RF_VL`

**目的**: 正しくなった VE の上に、狙った全負荷増量を**相対量として**乗せる。

slave `0x0B30`、z `0x0B5A`、3×18、u8、**raw/128**（1 step ≈ 0.78 %）。

現在値（3 行すべて**バイト同一**。raw を括弧内に）:

| rpm | 700 | 900 | 1000 | 1200 | 1300 | 1400 | 1700 | 1900 | 2100 |
|---|---|---|---|---|---|---|---|---|---|
| 係数 | 0.953 (122) | 1.133 (145) | 1.078 (138) | 1.063 (136) | 1.219 (156) | 1.180 (151) | 1.156 (148) | **1.047 (134)** | 1.094 (140) |

| rpm | 2300 | 2600 | 3000 | 3300 | 3500 | 4400 | 5800 | 6400 | 8000 |
|---|---|---|---|---|---|---|---|---|---|
| 係数 | 1.141 (146) | 1.281 (164) | **1.297 (166)** | 1.188 (152) | 1.242 (159) | 1.211 (155) | 1.211 (155) | 1.219 (156) | 1.219 (156) |

最も濃いのは 3000 rpm（raw 166）、局所的に薄いのは 1900 rpm（raw 134）、最小は 700 rpm（raw 122）。

### rf 軸の使いどころ

3 行（rf = 0.8 / 0.9 / 1.0）は**バイト同一なので現状は死んでいる**。
ただし **軸が届かないわけではない**。WOT の実 RF は共鳴の谷で 1.0 を下回る:

| rpm | 1800 | 2100 | 2200 | 2400 | 2700 |
|---|---|---|---|---|---|
| WOT 時の rf | 1.042 | 0.932 | 0.879 | 0.868 | 1.037 |

→ **概ね 1900–2600 rpm では 0.9 行と 1.0 行の間を補間している。**
**この帯だけ濃くしたいなら、軸を触らずに 0.9 行と 1.0 行を差別化すればよい。**
2700 rpm 以上と 1300 rpm 以下は端でクランプするので、そこは 3 行とも同じ値にしておく。

> **軸（`0x0B54`）は動かさないこと。** 動かすと隣接セルの意味が全部変わる。

### 禁止事項

**ワイドバンドが無い以上、希薄側へは振らない。** 濃い側への相対変更のみ。
量子化は raw 1 = 0.78 % なので、たとえば +3 % は raw +4（`enc` で確認してから書く）。

## STEP 8 — 部分負荷点火 `KF_TZ_GRUND`

**目的**: VE が正しくなって**初めてセルが正しく引かれる**ようになった点火マップを詰める。

`KF_TZ_GRUND` master `0xAD1A` / z `0xAD56`、12×18、**signed** 16bit、x/10、軸 = (n, **rf**)。
rf 軸 0.1–1.1、rpm 600–7600。

> 既存 `60-tuning-logic.md` §1.1 ① が「VE がずれると点火を間違ったセルで引く」と述べている。
> **その前提が STEP 1–3 で解消された今、初めてこのマップを触る意味が出る。**

### 8.1 まず読む（触る前に）

**`tz1..tz6`（気筒別・実際に出た点火角）は block 19 offset 22–32、0.1 °KW。**
**block 19 はツールが λ 積分器のために既に取得している ＝ 追加の通信コストはゼロ。**

`tz` 実測値と `KF_TZ_GRUND(N, RF)` の差分 ＝ 全補正の合計。これで:

- **ノック制御が生きているかが実車で決まる**（§17 の未確定事項が 1 つ消える）。
  負荷時に `tz` がマップ値を下回り、**0.1 °/step の極端に遅い復帰**を示せば生きている。
- 変化率制限やトルク介入が効いている区間も見分けられる。

同ブロックに `ti1..ti6`（気筒別噴射時間、offset 6–16、0.001 ms）もある。裏取りに使える。

### 8.2 ダイナモ無しの MBT 探索

**一定車速・一定ギア・平坦路で、同じ速度を保つのに必要なスロットル開度が最小になる点**。
定常では要求トルクが一定なので、効率が上がれば `aq_rel`(block 3 off 20) / `wdk1`(off 27) が下がる。

**罠（VANOS と非対称なので必ず意識する）**:
点火マップの軸は **rf** であり `RF = f(スロットル, rpm)`。
**スロットルが下がるとセルが移動する＝弱い帰還がある。** VANOS（軸が aq_rel）には無い。
→ 1 反復あたりの変更量を小さくし、反復回数で稼ぐ。

### 8.3 天井と床

- **`K_TZ_MAX`（master `0xAC82`）= 60.0°**。低負荷・高回転側の多数のセルが**既にこの天井に張り付いている**
  （例: rf 0.1 行は 3500 rpm 以上ですべて 60.0）。**そこは進角不可。反復を浪費しない。**
- 床は `KF_TZ_MIN`（master `0xB0A8` / z `0xB0C4`、6×8、signed、x/10）。
  rf = 1.0 行は 850→6000 rpm で `−20, −12, −10, −3, 0, 8, 8, 8` → **4000 rpm 以上で +8.0°**。

### 8.4 マップの滑らかさは機構上の要求

変化率制限 **`K_TZ_ZWB_B2`（master `0xAC86`）= 4.0 °/segment**（B1/B3 = 2.0、領域判定 `K_TZ_RF_ZWB` = 0.3）。

**セル間の段差がこの制限を超えると、過渡で目標に追いつけず効果が遅れて出る。**
各セルが個別に最適でも、マップが凸凹なら体感は悪化する。**平滑性は美観ではない。**

## 13. トルクマネジメント

### 13.1 `MD_IND_MAX` の式（`code-confirmed`）

`MD_Maximum_Moment_FUN_00017a76`（master `0x017a88`）:

```
MD_IND_MAX = ( md_max_md_la × KF_MD_MAX_MD_IND_OPT[ (KL_MD_MAX_VL_RF_SU1(N) × RF_PT_KORR) , N ] ) >> 7
MD_IND_MAX = MD_IND_OPT_KORR        [if MD_IND_MAX < MD_IND_OPT_KORR]   ← 実測到達値で床上げ
```

`MD_Torque_Interventions...FUN_000166bc`（master `0x0166f6`）:

```
MD_ST |= 0x80              [if MD_IND_MAX < _DAT_00ff816c]   ← 「トルクモデルが制限中」フラグ
_DAT_00ff816c = MD_IND_MAX [if MD_IND_MAX < _DAT_00ff816c]   ← 要求はここでクランプされる
MD_IND_WUNSCH_RED_KORR = _DAT_00ff816c
```

### 13.2 なぜ SU1 を上げても出力が増えないのか

要求トルクは確かに `MD_IND_MAX` でクランプされる。**しかし**:

1. `MD_IND_MAX` は **実際に出ているトルク `MD_IND_OPT_KORR` で床上げされる**。
   → **実出力を下回って絞ることはできない。**
2. `KF_EGAS_WDK` は 3000 rpm 以上で SU1 が要求するどの rf でも**既に 100 % に飽和**しており、
   `egas_wdk = 1000 [if 1000 < egas_wdk]` でハードクランプされている。
   → **SU1 を上げてもスロットルは 1 度も余分に開かない。**

∴ **`KL_MD_MAX_VL_RF_SU1` は「上げて出力を増やす」対象ではなく、「実態と一致させる」対象。**
ずれたままだと SMG が見る「使えるトルク」と CAN 報告トルクの基準が狂う（§13.4）。

> **EGS（AT）経路は本車には無い**: `cfg_m.getriebetyp` = `cfg_s.getriebetyp` = **0x40**。
> EGS のトルク介入は `(cfg_m_getriebetyp & 0x30) == 0x30` で条件付けられており、`0x40 & 0x30 = 0` で不成立。
> 一方 SMG コードは `cfg_s_getriebetyp == 0x40` でゲートされている（`task_10ms` slave `0x012a44`）
> ＝ **本バイナリは SMG 構成であり、SMG 経路が生きている。**

### 13.4 SU1 のドライバビリティ影響は「SMG 経由だけ」

**ペダルフィールには効かない。** ペダル→スロットルは `MD_IND_MAX` を通らない:

```
MD_FW_REL = kfu_wint(KF_MD_FAHRER, N, PWG_SOLL)      md_pwg        master 0x023302
EGAS_SOLL = MD_FW_REL                                 EGAS_SOLL_BERECH master 0x022934
EGAS_SOLL = 1000   [if 1000 < MD_FW_REL]
```

→ **ペダルの効き方を変えたいなら `KF_MD_FAHRER`（master `0x8298` / z `0x82B4`、6×8、軸 = n × pwg）**
であって SU1 ではない。参考に現在値（z = %、行 = pwg）:

| pwg \ rpm | 1100 | 1400 | 1500 | 1700 | 2300 | 2700 | 3000 | 4300 |
|---|---|---|---|---|---|---|---|---|
| 4.5 % | 5.5 | 5.5 | 5.5 | 4.5 | 4.5 | 4.5 | 4.5 | 4.5 |
| 15 % | 16.5 | 18.0 | 17.0 | 15.4 | 15.5 | 15.3 | 15.1 | 14.5 |
| 30 % | 34.0 | 37.0 | **42.0** | 36.0 | 32.3 | 32.2 | 32.0 | **28.8** |
| 65 % | 68.2 | 68.0 | **76.0** | 67.2 | 69.8 | 65.2 | 65.2 | **59.4** |
| 100 % | 100.0 | 100.0 | 100.0 | 100.0 | 100.0 | 100.0 | 100.0 | 100.0 |

低回転ほど同じペダルで開度が大きい（1500 rpm で 30 % → 42 %、4300 rpm で 28.8 %）。
100 % 行は全域 100 % なので**全開位置は rpm に依らない**。

**効くのは SMG のトルク余裕**。`smg_driver_torque_ramp_update`（slave `0x03b33e`、20 stmts）:

```
DAT_00ffdb2c = MD_ETA_KR                                    ← ノック遅角による効率（初期値 0xffff = 1.0）
DAT_00ffdb5a = (md_ind_max_dpr × DAT_00ffdb2c) / 0xffff − DAT_00ffdb58
             ±= K_SMG_MD_FW_SA_D_M                          ← slave 0x282E = 50.0 Nm/s（レート制限）
DAT_00ffdb5a = 1000  [if 10000 < …]  /  = −500  [if … < −5000]   ← クランプ、超えると flag bit 0x80
DAT_00ffdb22 = PT1_Filter_SS(DAT_00ffdb5a, …, K_SMG_TAU_MD_FAHRER)   ← slave 0x2800 = 0.0753 s
```

`K_SMG_MD_FW_SA_D_M` の単位が **Nm/s**、`K_SMG_TAU_MD_FAHRER` が字義どおり「ドライバトルク」の
時定数であることから、`DAT_00ffdb5a` は **トルクの余裕（差分）** と読める。
`smg_start_window_torque_ramp_update`（slave `0x038866`）も同じ `md_ind_max_dpr` を使い、
`K_SMG_MOT_NL_T_MAX`（slave `0x2858` = 2000 ms）で**発進ウィンドウ**を作っている。

∴ **SU1 → MD_IND_MAX → md_ind_max_dpr → ×MD_ETA_KR → PT1 → SMG の「使えるトルク余裕」。**
**SU1 が過大なら SMG は余裕を過大に見積もる**（変速判断と発進トルクランプがずれる）。
`根拠`: 式は code-confirmed。ただし `DAT_` 名が未解決で SMG 本体は別 ECU なので、
**「SMG がその値をどう使うか」は inference**。

### 13.5 過大側と過小側は非対称

`MD_IND_MAX = max( SU1 モデル , MD_IND_OPT_KORR )` — **実測 RF 由来の値で床上げされる。**

| SU1 の誤り | 結果 |
|---|---|
| **過小** | 床上げが働き `MD_IND_OPT_KORR` が採用される → 害は限定的 |
| **過大** | 床は効かない（上限側にガードが無い）→ **そのまま SMG と CAN に伝わる** |

∴ **迷ったら低め。** 実測に合わせるのが正解だが、外すなら過小側のほうが安全。

なお `MD_IND_MIN >= MD_IND_MAX` で `MD_FW_DPR = 0` ＋ 診断コード `0x21` という経路も存在するが
（`MD_IND_MIN` は `md_verbraucher` master `0x017748` が作る補機要求の下限）、
**上記の床上げがあるため SU1 単独でここへ到達させるのは難しい。**

### 13.6 パワーフィール（定常）にも効かない — クランプの後ろにアクチュエータが無い

「ペダルには効かない」（§13.4）と「ピーク出力には効かない」（§13.2）は別の話で、
**「踏んでいる最中の力の出方（パワーフィール）」がもう一つの論点**になる。
定常については **効かない**。理由が 3 つ独立にある。

1. **空気側の経路が無い** — `KF_EGAS_WDK` は 3000 rpm 以上で既に 100 % 飽和（§13.2）。
2. **クランプは実測値で床上げされる** — `MD_IND_MAX = max(SU1モデル, MD_IND_OPT_KORR)` で、
   `MD_IND_OPT_KORR` は**現在の RF での最適トルク**。
   → **クランプが「今の充填で出せる値」を下回ることは構造的に起こらない。**
3. **クランプ結果に消費者が無い** — `MD_IND_WUNSCH_RED_KORR`（= クランプ後の値）を参照する関数は
   回収済みグラフでは**それを書いている関数 1 つだけ**。読み手がいない。

そして**点火遅角はクランプから来ていない**。トルクマネージャ側の遅角要求は:

```
_MD_TZ_RED = MD_LLRP + MD_LLR_TZ + FUN_00016f02( DAT_00ffd958 | EGS_MD_IND_GS )
             ↑アイドル制御P  ↑Laufruheregelung  ↑外部（EGS/ASC/SMG）からの低減要求
```
`MD_IND_MAX` は**この式に出てこない**（`FUN_000166bc` master `0x0166f6`、code-confirmed）。

さらに点火効率 `MD_ETA_ZW_VE/NE` は `md_eta_calc`（slave `0x0155aa`）が
**実際の点火角由来の `ETA_VE8` / `ETA_NE8` / `ETA_NE1` から気筒平均で算出**している。
つまり **「遅角でどれだけトルクを失ったか」を報告する側**であって、遅角を命じる側ではない。
`MD_IND_MAX` はここにも出てこない。

> ∴ **MSS54 のトルクモデルは全開域では記述的（descriptive）であって指令的（prescriptive）ではない。**
> SU1 がずれていても、エンジンを押さえ込むことはしない。報告値がずれるだけ。
> これが「合わせる対象であって梃子ではない」ことの、出力側から見た理由。

**例外は SMG の過渡**（§13.4）。変速時・発進時のトルクランプは `md_ind_max_dpr` で大きさが決まるので、
**SMG 車では「シフトの当たり」と「発進の付き」という形でパワーフィールに出る。**
定常全開では出ない。ここを混同しないこと。

**`FUN_00016f02` は逆アセンブルで回収済み**（capstone / CPU32。手順は §22）。ASC/MSR の最小値選択だった:

```
FUN_00016f02(x)  master 0x016F02, 56 byte
  d1 = (ASC_ST bit0) ? MD_IND_ASC_ABS : 0xffff     ; ASC/DSC の要求、無ければ「制限なし」
  d1 = min(d1, x)
  if (ASC_ST bit1)  d1 = min(d1, MD_IND_MSR_ABS)   ; MSR = エンジンドラッグトルク制御
  return d1
```

→ **外部低減要求はトラクション制御（ASC/DSC/MSR）由来であって、`MD_IND_MAX` は現れない。**
`_MD_TZ_RED` の全 3 項が確認できたので、**この結論は否定的証拠ではなく code-confirmed になった。**

**残る未確立**: `MD_ETA_ZW_*` の要素（`ETA_VE8` / `ETA_NE8` / `ETA_NE1` の作られ方）は未回収。
ただし `md_eta_calc` が**実点火角から効率を算出している**構造は回収済みなので、
向き（報告であって指令でない）は変わらない見込み。

### 13.7 CAN 報告トルクの正規化は SU1 ではない

`MD_Interface_to_ASC_DSC`（master `0x017f6c`）: `MD_IND_IST = (MD_IND_WUNSCH << 8) / MD_NORM`、
`MD_NORM = K_MD_NORM × 0xa0`、`K_MD_NORM`（master `0x91D8`）= **496.0 Nm の定数**。
→ **分母は SU1 ではない。** ただし分子 `MD_IND_WUNSCH` は `MD_IND_MAX` でクランプされるので、
SU1 は**間接的に**報告値の上限を決める。

### 13.3 `KF_TI_N_RF_VL` と `KF_MD_MAX_LA_VL` の連動（3 パラメータのうち 2 つを結ぶ配線）

`KF_MD_MAX_LA_VL`（master `0x8BB2` / z `0x8BC1`、3×12、raw/128、rf5 軸は 3 行同一＝不活性）は
**「全負荷ではこの λ で回っている」という宣言**:

| n40 | 600 | 1000 | 1240 | 1760 以上 |
|---|---|---|---|---|
| 想定 λ | 0.898 | 0.898 | 0.898 | **0.852** |

その λ を `KL_MD_MAX_MD_LA`（master `0x8BE8`）が効率に変換する（λ 0.80–0.90 で約 1.047 とピーク）。

→ **STEP 7 で `KF_TI_N_RF_VL` を動かして実際の全負荷 λ を変えたのに
`KF_MD_MAX_LA_VL` を放置すると、トルクモデルの効率項が実態と食い違う。**

## 22. 未回収関数を回収する手順

```
アドレス規則（コードも含む完全版）
  func/code  master → file offset = addr
  param(XDF) master → file offset = addr
  func/code  slave  → file offset = 0x80000 + addr
  param(XDF) slave  → file offset = 0x88000 + addr
```

CPU は **CPU32（MC68336 系）、ビッグエンディアン**。capstone の
`CS_ARCH_M68K | CS_MODE_M68K_020 | CS_MODE_BIG_ENDIAN` でほぼ読める（CPU32 固有の `TBL` のみ非対応）。
`graph.json` の `ram` / `param` / `func` ノードから絶対オペランドを名前解決すると一気に読めるようになる。
`q.py func <regex>` で `size=` を取り、その長さだけ切って流す。

### コード中のオペランドはファイルオフセットとは別（ここで詰まる）

**master コードがパラメータを参照するときのランタイムオペランドは `0x80000 + XDF アドレス`。**
ファイルオフセット規則（master = addr）とは**別物**なので、混同すると隣の表を読んでしまう。

2 例で検証済み:

| 例 | オペランド | 指しているもの |
|---|---|---|
| `kd_cfg_calc`: `movea.l #$8a28d, a0` | `0x8A28D` = 0x80000 + `0xA28D` | `K_KD_QUELLE`（値 2、ファイル 0x0A28D） |
| `edk_vorst_calc`: `pea.l $88130` | `0x88130` = 0x80000 + `0x8130` | `KL_EDK_VORST` の**構造体先頭** |

**テーブルへのポインタは XDF が示すアドレスより 2 バイト手前を指す。**
そこに点数（`sizeX`）が入っており、補間ヘルパは `&table.sizeX` を受け取る仕様。
上の例では `0x8130` の 1 バイトが **10**（= `KL_EDK_VORST` の 10 点）で、
`0x8132` から x 値（0.0 / 0.1 / 0.4 / 2.0 …）が始まる。

補間ヘルパの実体も名前解決できる — 例: master `0x4096C` = `klu_wint`。
`jsr` 先を引くとその文が `klu_wint(TABLE, AXIS)` だと確定できる。

> **注意**: master ランタイム（`0x88000–0x8FFFF`）と slave パラメータのランタイム
> （`0x88000 + slave XDF`）は**アドレス範囲が完全に重なる**。
> どちらの解釈か迷ったら、両方のファイルオフセットの値を読んで
> **意味の通る側**（その関数が読むはずのパラメータ）を採る。上の 2 例はこの方法で確定した。

## 19. VANOS 自動チューニング

**成立根拠**（§STEP 2.1 の再掲）: 同一セル内でカム角だけを振るので、
そのセルの VE 誤差は定数オフセットとして相殺される。**VE が完璧でなくても最適角は正しく求まる。**

```
for each セル (n, aq_rel) in 走行で保持できるグリッド:
    for Δ in {−6, −3, 0, +3, +6} °KW:          # 1 °KW = raw 1 LSB。量子化誤差ゼロ
        DS2 0x0C で目標角を Δ へランプ
        wait until |evan1_ist − evan1_soll| < tol      # 到達ゲート（必須）
        dwell し la_f_regler を平均                     # 定常測定なので低レートで可
    二次当てはめ → 頂点 = 最大 VE 角
    if 下に凸でない or 頂点が掃引範囲外: 棄却して現状維持   # 外挿しない
    減衰して更新 → 隣接セルとの段差上限を適用 → 保存可能域へクランプ
```

**ゲート（1 つでも外れたらサンプル破棄）**:
`evan1_ist ≈ evan1_soll` ／ 定常（既存 transient filter）／ 水温 ≥ 75 °C・油温 ≥ 40 °C ／
対象セルの重み > 閾値 ／ **λ 積分器がクランプ近傍でない**（張り付くと比較が壊れる）。

**中断**: DS2 セッションのキープアライブを止めれば純正マップ制御に自動復帰する。これをフェイルセーフとして使う。

**安全設計**は §STEP 2.4 の 6 項目をそのまま実装要件とする。特に
**探索窓を保存可能域（吸気 0–60 / 排気 0–45）に閉じ込める**こと。

**収束後は VE 再導出へ戻る**（STEP 3）。

> **非対称性**: 点火側には同等の DS2 オーバーライドが見つかっていない。
> **点火の自動化は反復ごとにフラッシュが要る。** VANOS だけが 1 回の走行で完結できる。

## 20. 点火 自動チューニング

### モード 1 — 遅角学習（安全。先に実装すべき）

```
新値 = 旧値 + gain × mean(tz実測 − マップ値)        # gain < 1、進角方向へは決して動かさない
```

`tz1..tz6` は block 19（コスト増ゼロ）。**原理的に安全**（マップを実際に出ている角度へ近づけるだけ）。
DME が恒常的に引いている領域＝マップが進み過ぎている領域なので、
これだけで「DME が補正し続ける状態」を解消できる。

**ゲート**: 定常であること。変化率制限中やトルク介入中の `tz` は基本マップの評価に使えない。

### モード 2 — MBT 探索（進角側。慎重に）

定速・固定ギアで `aq_rel` 最小を探す。
**MBT は尖った頂点ではなく平坦域**なので、**「改善がノイズ以下になった最初の角度」で止める**。
頂点を追ってはいけない — 行き過ぎても得は無く、ノックリスクだけ増える。

**ハードゲート**: `K_TZ_MAX` = 60.0° を超えない ／ **一度でも遅角が観測されたセルは進角禁止** ／
60° 天井に張り付いているセルは対象外。

**罠**: rf 軸なので効率が上がるとセルが移動する。1 反復あたりの変更量を小さくし反復回数で稼ぐ。

|---|---|---|---|
| **吸気カム 進角側** | 吸気の早開き・早閉じ。低中回転の充填改善、オーバーラップ増 | 低中速トルクが出る。アクセル初期が力強い | 高回転が伸びない（頭打ち感）。軽負荷でオーバーラップ過大 → 燃焼不安定、アイドルばたつき、ティップインのもたつき |
| **吸気カム 遅角側** | 遅閉じ。高回転の慣性過給を活かす | 上が伸びる | 下がスカスカ。発進が重い |
| **排気カム（オーバーラップ増方向）** | 残留ガス増（内部 EGR） | 中回転の充填に効くことがある | 軽負荷で燃焼が荒れる（`Laufunruhe`）。アイドル不安定 |
| **排気カム（オーバーラップ減方向）** | 掃気重視 | 軽負荷が安定 | 中回転の充填を落とすことがある |

> **符号について**: オーバーラップは「吸気開き」と「排気閉じ」で決まる。
> 両マップの raw は**静止位置からの調整量**（吸気 0–60 / 排気 0–45 °KW）であり、
> **それが進角側か遅角側かは実車の `evan1_ist` / `avan1_ist` の動きで必ず確認してから語ること。**
> ここを取り違えると作業全体が反転する（§17）。

### 点火

| 動かす向き | 物理 | 体感 | 行き過ぎたときの症状 |
|---|---|---|---|
| **進角** | MBT に近づく間は同じ空気でトルク増 | **同じ速度に必要なスロットル開度が減る**＝軽い、レスポンス良い、燃費改善 | MBT 超でトルク低下 ＋ ノック |
| **遅角** | 燃焼が遅れ、排気に熱が逃げる | トルク低下、レスポンス低下 | 排気温上昇（触媒暖機以外では損） |

**ノックさせたときに何が起きるか（体感上の実害）**:
DME は **3–4°（強ノックなら 6°）を一気に引く**。戻りは **0.1°/step と極端に小さい**。
（復帰タスク周期が未回収なので時間は確定できないが）
**一度ノックさせると、その後しばらくパワーの無い状態で走ることになる。**
サーキットで 1 周目にノックさせると、以降のラップがずっと遅い、という形で出る。

### 両マップ共通 — 段差の害

点火は `K_TZ_ZWB_B2` = 4.0 °/segment、VANOS は `KF_EVAN1_SOLL_DMAX`(slave `0x1B54`) /
`KF_AVAN1_SOLL_DMAX`(slave `0x1E7A`) で変化率が制限される。

**セル間の段差がこの制限を超えると、過渡で目標に追いつけず効果が遅れて出る**
＝ ティップインが「ゴムっぽい」「効き遅れる」。

**各セルが個別に最適でも、マップが凸凹なら体感は悪化する。**
∴ **自動チューニングの出力には平滑化制約を必ず入れる。これは美観ではなく機構上の要求。**
