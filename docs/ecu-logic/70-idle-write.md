# アイドル書き込み —— 何を測り、どう計算し、どのバイトを書くか

## 1. 計算式

測定から書き込みまで、5 行で全部です。

```
① 測定    e  = trimmean(md_llri) + trimmean(md_llra) − (−K_LFR_MDADAPT_OFFSET)      [Nm]

② ゲイン  g  = (∂KF_LLS_TV/∂ml_ll)|(n, ml)  ×  g_air(n)                            [%/Nm]
              g_air(n) = K_G_AIR × n / n_ref  =  0.40 × n / 780                   [(kg/h)/Nm]

③ 全補正  Δ  = g × e                                                                [%]

④ 減衰    s  = clamp(±maxStepPct, stepFraction × Δ)                                 [%]
              （stepFraction = 0.5、maxStepPct = 3.0 %。ただし |Δ| が 1 量子を超えるなら
                s は最低 1 量子。減衰でループを分解能以下に凍らせないため）

⑤ 分配    sᵢ = s × wᵢ / Σ_{j∈W} wⱼ²        書き込み可能な各格子点 i ∈ W へ           [%]

⑥ 書込    KF_LLS_TV[i] ← quantise( clamp(K_LLS_TV_MIN, K_LLS_TV_MAX, stockᵢ + sᵢ) )
```

`wᵢ` は **DME 自身が使う双一次補間の重み**です（§4）。

### この車の実数

セッション #1 の実測アイドル: `n = 880 rpm`、`ml_soll_lls = 14.0 kg/h`。

```
∂KF_LLS_TV/∂ml_ll = (23.0 − 14.0) / (15 − 11) = 2.25 %/(kg/h)     ← マップ自身の傾き
g_air(880)        = 0.40 × 880/780            = 0.451 (kg/h)/Nm
g                 = 2.25 × 0.451              = 1.015 %/Nm
```

つまり **ガバナが 1 Nm 余計に踏ん張っていたら、バルブデューティを約 1.0 % 上げる**。

### 符号

`e > 0` ＝ ガバナが安静点より**トルクを足している** ＝ 空気が足りない ＝ **デューティを上げる**。

`slope > 0` かつ `g_air > 0` なので `Δ = g·e` の符号は `e` と同じ。方向は合っています。

**較正自身の形による裏取り**（マップの数値がこの読みと矛盾しないか）:
800 rpm 列は 11 → 15 → 20 kg/h で 14.0 → 23.0 → 33.6 %。要求空気が増えればデューティが増える、単調増加。逆向きに読んでいたらこの形と矛盾します。

## 2. 書き換えるパラメータ

| | |
|---|---|
| **定義名** | `KF_LLS_TV` |
| 種別 | map |
| XDF アドレス | `0x9DE2`（軸）/ 値 `0x9E10` |
| ファイルオフセット | `0x09DE2` / `0x09E10` |
| bank | **master**（`master addr = file offset`） |
| 形 | 13 行 × 10 列 = 130 セル、16bit 符号なし |
| スケーリング | `x / 50` → **1 段 = 0.02 %** |
| 単位 | デューティ % |
| x 軸 | rpm: 500 600 **800 950** 1400 1700 2350 3000 5000 7000 |
| y 軸 | ml_ll [kg/h]: **11 15** 20 25 30 40 50 60 65 70 75 80 85 |
| 上下限 | `K_LLS_TV_MIN` = 14.0 % / `K_LLS_TV_MAX` = 97.0 %（BIN から読む、定数を信じない） |
| 根拠 | **code-confirmed** —— `lls_tv_calc` が唯一の消費者で、復元された文の中でこのマップを引いている |

### なぜこのマップなのか

```
_ML_SOLL_DPR ─┬─ min(·, ML_SOLL_MAX_LLS) → ML_SOLL_LLS ─┐
              │                                          ├→ KF_LLS_TV(n, ml_ll) → LLS_TV → バルブ
              └─ max(0, · − ML_SOLL_MAX_LLS) → ML_SOLL_WDK → スロットル
```

トルク経路の要求を天井で分割したものが弁への空気要求です。**専用のアイドル空気マップには読み手がいない** —— それが次項です。

### 封印されたまま残るもの

`KF_LLR_QVS_GRUND`（`0xA04E`）は**永久に封印**です。書いても車は何も変わりません。

`lls_tv_calc`（master `0x025D0A`）の呼び出し元は 2 つあり、`cfg_m.egas`（`0x8012`）で排他です。この車のバイナリでは **`0x00`** ＝ トルク経路が生きている側。裏取り: `LLR_QSOLL`（`0xFFEF1A`）は 1 MB 中に絶対参照が 1 箇所しかなく、それは自分への書き込みです。

つまり `KF_LLR_QVS_GRUND → LLR_QVS → LLR_QSOLL` は、**誰も読まない値を計算している生きたコード**です。

## 3. 測るデータ

IDLE プロファイルが 3.00 Hz で読むもののうち、**計算に入るのは 4 つだけ**です。残りは全部「その測定に意味があるか」を判定するためのもの。

| チャネル | RAM/ブロック | 役割 |
|---|---|---|
| `MD_LLRI` | RAM | **測定そのもの。**ガバナの I 項 [Nm] |
| `MD_LLRA` | 同じ電文 | 適応。I 項から値が移るので**和で不変量にする** |
| `ML_SOLL_LLS` | 同じ電文 | **y 軸の座標。**弁に与えられた空気 [kg/h] |
| `n` | ブロック 3 | **x 軸の座標** |

`MD_LLRI + MD_LLRA` を使うのは、`lfra_adapt` が最大 0.333 Nm/s で I 項から適応へ値を移すためです。暖まって落ち着いた車は、フィードフォワード誤差がいくつであっても I 項だけ見れば安静点を読みます。和は「どれだけ長くアイドルしていたか」に対して不変です。

### 判定に使う残り

- 事前条件（§7.1）: `FR_REGLER` `LFR_ZUSTAND` `EGAS_SOLL` `WDK_SOLL` `EVAN1_ST` `MD_RES_LRW_ST` `LWS_LRW` …
- 除外ゲート: `ZUSTAND_MOTOR` bit2（LL 状態）、`KKOS_ST` bit0（A/C）、`UB`（電気負荷）、`LLR_N_SOLL`（目標が動いていないか）
- モデルゲート: `LLS_TV` —— **DME が実際に出したデューティ**を `KF_LLS_TV` の補間値と突き合わせる

最後のモデルゲートが、この機能で一番重要な安全装置です。**「このマップが本当にこの車のデューティを決めているのか」を、書く前に毎回確かめます。** 合わなければ `model-disagrees` で拒否。

### サンプルではなく dwell が単位

推定しているのは時定数 5.12 s の積分器がどこに落ち着くかです。サンプルを直接ビン分けするとランプの途中の点を数えることになります。だから 20 秒以上の**整定した窓**を 1 単位として、その中で 20 % トリム平均を取ります。

## 4. 分配 —— なぜ 4 点に書くのか

**この車は 880 rpm でアイドルします。x 軸のブレークポイントは 800 と 950 です。**

DME は双一次補間します。880 rpm・14.0 kg/h で DME が読む値は、4 つの格子点の重み付き和です:

```
              n=800    n=950
ml_ll=11      0.117    0.133      ← 合計 0.250
ml_ll=15      0.350    0.400      ← 合計 0.750
                                     Σwᵢ = 1.000
```

**最も近い 1 セルだけに Δ を書くと、動作点は 0.400 × Δ しか動きません。** 残り 60 % は動かず、そのセルは物理が要求する 2.5 倍まで引きずられ、950 rpm ちょうどの面が歪みます。「近傍セルに書く」設計は、ここでは単に遅いのではなく**間違っています**。

そこで最小ノルム分配を使います。書き込み可能な集合 `W` について

```
sᵢ = s × wᵢ / Σ_{j∈W} wⱼ²
```

とすると、動作点での変化は `Σᵢ wᵢ sᵢ = s` で**厳密**です。重みが 1 点に集中していればその点だけが動き、均等ならすべてが等しく動く —— 両端で正しく退化します。

### 書き込まない格子点

| 除外 | 理由 |
|---|---|
| **y = 11 kg/h の行（row 0）** | 全 rpm で 14.0 % ＝ `K_LLS_TV_MIN`。これは「11 kg/h 以下では弁に権限がない」という較正の宣言そのもので、この機能の床の定義でもあります。動かしません |
| **500 rpm 列（col 0）** | 失速キャッチ。暖機後アイドルの証拠は何も言っていません |
| **row > 1（20 kg/h 以上）** | 暖機後アイドルは 11〜15 kg/h。それ以上は今回の走行が保持しなかった負荷で、暖機測定から冷間行を書くのと同じ間違い |

880 rpm・14 kg/h では `W` = { (15 kg/h, 800), (15 kg/h, 950) }、重み 0.350 と 0.400、`Σw² = 0.2825`。

```
s(15,800) = s × 0.350/0.2825 = 1.239 × s
s(15,950) = s × 0.400/0.2825 = 1.416 × s
検算: 0.350×1.239 + 0.400×1.416 = 1.000        ✓
```

床の行を除いた分、格子点の移動量は s の 1.24〜1.42 倍に増幅されます。**これは隠れた副作用ではなく、`maxStepPct` = 3.0 % が各セルに効いた上での意図した挙動です。** 増幅率はレポートに出します。

### 副作用の範囲

950 rpm の格子点を動かすと、800〜1400 rpm を補間する領域すべてが動きます。アイドル帯を超えた 950〜1400 rpm はアイドルではなく、そこでの `ml_ll` は 15 kg/h よりずっと高いので、実際に触るのは「低回転・低要求」の角だけです。**それでもゼロではありません。** これは記録しておくべき既知の帰結です。

## 5. 全表書き込みの安全性 —— 実測

`setEcuMapValues` は**動かしたセルだけでなく 130 セル全部**を書き、全部に上下限を適用します。旧ターゲットではここが第 2 の封印理由でした（30 セル中 16 セルが上限の外にあり、冷間セルが黙って書き換わるところだった）。

新ターゲットで測り直しました（`npm run inspect:lls-tv`）:

```
K_LLS_TV_MIN / MAX        14 / 97 %
cells                     130
min / max cell            14 / 97 %
cells below K_LLS_TV_MIN  0
cells above K_LLS_TV_MAX  0
```

**130 セル全部がレールの内側**なので、触っていないセルは書き戻してもバイト同一です。旧ターゲットの第 2 理由は新ターゲットには当てはまりません —— 議論ではなく測定です。

## 6. 封印を解く条件と、その充足

seal.ts の条件は「**論理から導かれた名前つきパラメータがあり、それがエンジンに届くと示されたとき**」でした。

| 条件 | 状態 |
|---|---|
| 論理から導かれた名前つきパラメータ | ✅ `KF_LLS_TV`、code-confirmed、`lls_tv_calc` が唯一の消費者 |
| エンジンに届く | ✅ 出力 `LLS_TV` は弁のデューティそのもの。**さらに毎回の走行でモデルゲートが照合する** |
| 全表書き込みが安全 | ✅ §5 で実測 |
| `KF_LLR_QVS_GRUND` | ❌ 封印継続。読み手がいないことに変わりなし |

**まだ実車で確かめていないこと**: 1 セルに大きな差分を書いて `LLS_TV` と rpm が予想どおり動くか、という確認走行。モデルゲートは「マップが DME のデューティを説明する」ことを示しますが、「書き換えたら車が変わる」ことの直接証明ではありません。

だから初回の書き込みは **`stepFraction` = 0.5、`maxStepPct` = 3.0 %** の減衰つきで、1 パスあたり最大でも 3 % のデューティ変化です。アイドル空気にすると約 1.3 kg/h、トルクにして約 3 Nm 相当。**この量は、次のログでモデルゲートが差分を検出できる大きさであり、かつ失速させる大きさではありません。**

## 7. 変えてはいけないもの

| パラメータ | なぜ |
|---|---|
| `K_LLS_TV_MIN` / `K_LLS_TV_MAX` | 弁の物理レール。ここを動かすと上下限の意味が消える |
| `KF_LLS_TV` の y = 11 kg/h 行 | 権限の床の定義そのもの（§4） |
| `K_LFR_MDADAPT_OFFSET` | 測定の**基準点**。動かすと過去のログと比較できなくなる |
| `KF_LLR_QVS_GRUND` | 死んでいる。書いても何も起きないので「効かない」という誤った学習だけが残る |
| `cfg_m.egas`（`0x8012`） | ここを 1 にすると制御構造そのものが別物になる |

## 8. まだ確立できていないこと

- **実車での差分試験。** 上記のとおり、書いたものが動くことの直接証明はまだ。
- **`g_air` は既定値のまま。** 0.40 (kg/h)/Nm は物理下界に寄せた保守値で、動作点が示唆するのは 0.47〜0.56。低いほうに外しているので、外れ方は「1 パス余計にかかる」であって「振動する」ではありません。2 パス目以降 `gain.ts` が実測から学習します。
- **950 rpm 側の副作用の実測。** §4 の帰結は幾何から確実ですが、その領域を走ってログを取ったわけではありません。
