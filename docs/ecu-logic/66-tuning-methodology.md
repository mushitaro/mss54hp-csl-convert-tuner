# 66 — チューニング・メソドロジー：何を証明してから、どのバイトを書くか

**この文書は「手順」ではなく「順序と門」を決める。** どのテーブルをどう動かすかは
`60-tuning-logic.md`、誰がどのバイトを握っているかは `65-workflows.md`、
**実際に何をどの順でやるかは `67-tuning-procedure.md`**。ここが決めるのは
**書いてよい条件**と、**その条件をどう機械的に確かめるか**である。

前提はひとつだけ:

> **アプリが読んでいる表が、DME が読んでいる表と同じであることを、その車のデータで示せない限り、
> 1 バイトも書かない。**

## 0. モデルゲート — 入口の条件（`verify:model-gate`）

DME 自身が計算した値を、BIN の算術だけで再現できるか。**チェーン全体を 1 つの数字で試す
唯一の検査**で、部分ごとの検査が全部通っても捕まらない誤りを捕まえる。

```
aq_rel_rf = AQ_REL / kl_aq_rel_rf_fakt(N)              ← 除数。1 未満なので aq_rel_rf は大きくなる
RF        = kf_rf_soll(N, aq_rel_rf) × RF_PT_KORR      ← × rf_korr（20 km/h 以下では 1.000）
RF_PT_KORR = KL_RF_TAN_KORR(TAN) × KL_RF_P_UMG_KORR(P_UMG)
```

> **これは簡約形である。** DME の実際の `rf_soll` には触媒暖機ブレンド・ASK 加算・一次遅れの
> 3 項がある —— §5。落としてよいのは「暖機が抜けている・フラップが閉じている・定常」の
> ときだけで、**その 3 条件が満たされていなければゲート自身が落ちる。**

**`AQ_REL` はログの `rawLoad`。** これは自明ではなく、2 回間違えた:

| 誤り | 症状 | なぜ生き延びたか |
|---|---|---|
| `rawLoad` を y 軸として直接使う | 残差 15〜18 % | 「マップがずれている」ようにしか見えない |
| `RF_PT_KORR` を掛け忘れる | **中央値はほぼ動かない** | 吸気温が 42→56 °C と動く走行では、両端が逆方向にずれて中央値で相殺される |

2 番目が方法論上いちばん重要な教訓である。**中央値だけを見る検査は、この誤りを通す。**
ゲートが中央値と**散らばりを並べて**報告するのはそのため。

### 合格の基準（実測に固定）

Session #920（52 分、水温 51→90 °C、標高 503 m）の整定アイドル **578 サンプル**:

```
実測 rf / 予測 rf  =  0.9938      sd 0.0054
```

**sd 0.5 % は `rf` チャンネルの分解能そのもの**（20.4 に対し 0.1 刻み = 0.49 %）。
つまりチェーンは、その値が表現できる精度で正確である。

| | 閾値 | 根拠 |
|---|---|---|
| 中央値 | 1.000 ± 0.02 | `rf` の量子化 2 個ぶん |
| 散らばり | sd ≤ 0.02 | 同 4 個ぶん。実測 0.0054 は 2 倍以上の余裕 |
| 最小サンプル数 | 20 | それ未満は分布を語れない |

**不合格は「エンジンが悪い」ではない。** アドレスかスケーリングか、モデルに無い項があるという
意味であり、**そのランから導いた補正は書く価値がない。**

### ゲートが成立する範囲

| 状態 | 実測 | |
|---|---|---|
| `wdk1 ≤ 1.0 %`（アイドル） | **0.9938** (n=578, sd 0.005) | 成立 |
| `wdk1 = 1.1 %`（部分負荷） | **0.849** (n=968, sd 0.027) | **成立しない** |

`KL_BZ_WDK_LL` は全 rpm で 1.2 %（ヒステリシス 0.2）なので LL/TL 境界は 1.0〜1.2 %。
**境界を跨いだ瞬間にモデルに無い項が入る。** 15 % は誤差ではなく別の項であり、
散らばりが 0.027 と小さい（＝間違った中心の周りで一貫している）ことがその証拠。

**したがって現時点でゲートが保証しているのはアイドル経路だけ。** 部分負荷・全負荷の補正は
この項が同定されるまで「ゲート未通過」として扱う。原因の切り分けは §6.4、未確立事項は §8。

## 1. 証拠から補正へ — 算術

充填モデルが実際の空気より多く見積もれば、DME は λ ループで燃料を抜く。その抜いた量が誤差である。

```
kf_rf_soll_new = kf_rf_soll_old × STFT × LTFT × rf_korr
```

| 記号 | 何か | 出どころ |
|---|---|---|
| `STFT` | λ 短期補正 `la_f_regler`。いま λ ループが動かしている分 | `stft1` / `stft2` の平均 |
| `LTFT` | λ 長期学習 `laa_f`。前回までの走行が覚えた分 | `ltft1` / `ltft2` の平均。無ければ 1.0 |
| `rf_korr` | 排気温が低いときに DME が `rf_soll` に掛ける補正 | `RF ÷ (kf_rf_soll × RF_PT_KORR)` |

**掛け算であって割り算ではない。** そして**この式は表全体で 1 本**である —— 低開度も高負荷も
同じ式で、違うのは**どの行を誰が持つか**と**証拠ゲート**だけ（§2）。

### かつてここにあった `TI_F_STAT` を外した理由

`TI_F_STAT`（`KF_TI_N_RF`）も掛けていた時期がある。読みはこうだった ——
「`rf = 0.10` 行の 1.148〜1.297 は BMW の意図的な増量で、λ=1 のループはそれを取り返すから、
掛け戻さないと補正を発明してしまう」。**車はそう言わなかった。**

session #920 の暖機後クローズドループ 1,479 サンプルで、係数が約 1.17 から厳密に 1.000 へ
落ちる `rf = 0.15` の折れ点を跨ぐ（rpm は 1 バンド内に固定）:

```
トリム中央値              0.9685 （下）  →  0.9699 （上）    +0.1 %   連続
トリム × TI_F_STAT        1.0728 （下）  →  0.9699 （上）    −9.6 %   跳ぶ
(トリム−1) を (TI_F_STAT−1) に回帰した傾き:  −0.025
```

増量説が正しければ傾きは **−1**、そして**トリムのほう**が段差を持つはずである。実際は
トリムが連続で**積のほうが跳ぶ**。**λ トリムはこの係数と戦っていない。**
`KF_TI_N_RF` は短パルス域のインジェクタ補償であって意図的な増量ではなく（形もそう言っている:
どこでも 1.000、最短パルスでだけ立ち上がり、rpm が上がるほど更に立つ）、掛ければ**普通の走行が
最もよく踏む低開度セルに、車が求めていない補正を最大 +15 % 発明する**。
`verify:ti-factor` がこの実測を保持しており、どの導出であれ係数を戻せば最後の表明が落ちる。

表の形（`rf ≥ 0.15` の行は全て厳密に 1.000、`rf = 0.10` 行だけ 1.148〜1.297）と、DME が
この係数を噴射時間に掛けている事実は**そのまま正しい**。変わったのは、それが**チューニングの
補正式に入るかどうか**だけである。

`readAlphaNTables` はこの構造（1.0 でない行が row 0 だけ）を指紋として検査し、
崩れていれば **null を返して拒否する**。1.0 で代替しない —— 係数は補正に入らなくなったが、
「何サンプルが DME の補償域で取られたか」をパネルが報告するために今も読んでいる。

### 証拠にならないサンプル

| 除外 | 理由 |
|---|---|
| λ トリムが無い | `calculator.ts` は `if (!banks.length) return` —— **1.0 として投票させない** |
| ~~`V > 20 km/h`~~ | **除外しない。** 走行中こそ主たる証拠で、フィルタにも `calculator.ts` にも車速の除外は無い。20 km/h が出てくるのは §0 のモデルゲート（`modelGate.ts`、`GATE_MAX_SPEED_KMH = 0`）の話で、あの簡約形が `rf_korr = 1.000` を前提にしているため |
| トリムが凍結（分散 ~0） | 収束した 0.87 と凍結した 0.87 は見分けがつかない |
| `ti < K_LA_TI_MIN` | DME が λ ループを開いている |
| 訪問が 1 回 | 同じ運転点の反復であって独立な観測ではない |

## 2. 書き込みの単一点

**`kf_rf_soll` には writer が 1 つしかない。** 全ての寄与は `composeVeGrid` を通り、
所有権はセル単位で決まる:

```
LOW LOAD が測定/修復したセル  → LOW LOAD（式は VE と同一。違うのは持ち行と証拠ゲートだけ）
VE が accepted したセル       → VE
どちらも触っていないセル      → BASE のまま
両方 OFF                      → テーブルに 1 バイトも触れない
```

書き込みの意思表示は**ハブの WRITE / RESTORE / PATCH マニフェスト 1 箇所**。
パネル内の ARM ボタンは廃止した —— 入口が 2 つあると、いつか食い違う。

**VE の書き込みもトグル**（既定 OFF）。「導出できたから書く」は廃止。
ファイル名の `Tune_` / `Base_` はマニフェストに従う。

## 3. 反復と停止条件

0. **RAM チェーン読み**（§6.2）を一度通す。ここを飛ばすと、以降は端から端まで 1 個の数しか見えない
1. **BASE を読む** → セッションを開く
2. **モデルゲート**（§0）。不合格ならここで止まる
3. ログを録る（§6.1 のランのどれかとして。§1 の除外規則が効く運転点を含むこと）
4. 導出 → マニフェストで arm → ダウンロード / フラッシュ
5. **フラッシュ後に読み直し、その READ から子セッションを分岐**
   （64 KB 書き込みは全部を置き換えるので、系譜規則に従う）
6. 2 に戻る

**停止条件**

| | 条件 | 意味 |
|---|---|---|
| 収束 | 対象セルが全て `sub-quantum`（\|変更\| < 1 LSB） | 量子化より小さい補正は書けない。緑で出す |
| 発散 | 補正の符号が 2 パス連続で反転し、絶対値が縮まない | 収束ではなくハンチング。別メッセージで止める |
| 無効 | モデルゲートが落ちた | 較正ではなく、読み方が間違っている |

`kf_rf_soll` の 1 LSB は 0.001（x/1000）。アイドルのセル 0.200 に対して **0.5 %**。
**λ トリムが 1 % 以内なら、書けるものは何もない。**

## 4. アイドルは二層でできていて、LOW LOAD は下の層にしかいない

```
━━━ 空気側 — 閉ループ。回転数と安定性を決める ━━━━━━━━━━━━━━━━━━━━━━━━━

  KL_LFR_NSOLL_GRUND(TMOT) ──→ 目標回転 LFR_N_N_SOLL
                                   │  dn = 目標 − N
                     LFR 制御器（P: KL_LFR_DQP_POS ／ I: KF_LFR_DQI ／ 点火: KL_LFR_TZ_POS）
                                   ▼ トルク [Nm]
                          モーメントマネージャ ──→ ML_SOLL_DPR [kg/h]
                                   │
       ┌───────────────────────────┴────────────────────────────┐
       │ ML_SOLL_LLS = min(ML_SOLL_DPR, ML_SOLL_MAX_LLS)        │ ML_SOLL_WDK = PT1(max(0, 差))
       ▼   ← アイドル弁が先に食う                                ▼   ← 余りがスロットルへ
   KF_LLS_TV(N, ML_SOLL_LLS) [%]                            WDK_SOLL [%]
       ▼ PT1(K_LLS_TAU2)                                        ▼
   KL_AQ_ABS_LLS(duty) → AQ_ABS_LLS [mm²]            KL_AQ_ABS_WDK(WDK_SEGM) [mm²]
       └───────────────────────────┬────────────────────────────┘
                                   ▼
━━━ 測定側 — 開ループ。燃料とトルクモデルを決める ━━━━━━━━━━━━━━━━━━━━━━

              AQ_ABS    = AQ_ABS_LLS + aq_abs_wdk
              AQ_REL    = AQ_ABS / 11781 × 100                       [%]
              aq_rel_rf = AQ_REL / kl_aq_rel_rf_fakt(N)
              RF        = kf_rf_soll(N, aq_rel_rf) × RF_PT_KORR      ← LOW LOAD が触るのはここだけ
              TI        = RF_TI_CONST × RF / 2000
```

分担は `egas_compute_throttle_target`（master `0x0270B0`、code-confirmed）:

```
ML_SOLL_LLS = min(ML_SOLL_DPR, ML_SOLL_MAX_LLS)
ML_SOLL_WDK = PT1(max(0, ML_SOLL_DPR − ML_SOLL_MAX_LLS), K_EGAS_WDK_TAU)
```

**アイドル弁が先に食い、余りがスロットルに行く。** だからアイドル域の空気は事実上すべて
`KF_LLS_TV` が決めている。

### 4.1 LOW LOAD にできないこと

**`kf_rf_soll` を 1 % 上げても、アイドル回転は変わらない。** LFR は回転を見て閉じているので、
測定値が変われば要求トルクが変わり、同じ回転で釣り合う場所に戻る。変わるのは噴射時間だけ。

> LOW LOAD は **「入った空気の測り方」** を直す。**「入る空気の量」は 1 mm² も動かさない。**

アイドルの高さ・垂れ・ハンチング・A/C 投入時の落ち込みは、**すべて空気側**である。
LOW LOAD をいくら回してもそこには届かない。

### 4.2 順序を逆にできない理由

`KF_LLS_TV` を動かすと弁開度が変わり、`AQ_ABS_LLS` が変わり、`AQ_REL` が変わり、
**アイドルが `kf_rf_soll` の別の行へ移動する**。この車は今 y = 0.391 % の行にいる（§6.0）。

> **空気側 → 測定側の順でしか進められない。** 逆にやると、LOW LOAD が集めた証拠は
> 「もう使わないセルの証拠」になる。

### 4.3 この BIN の空気側は参照から大きく離れている（実測で確認済み）

870 rpm、`ML_SOLL` ≈ 18.35 kg/h、`wdk1` 0.9 % で:

| | TERRA 参照 BIN | **この車の BASE** |
|---|---|---|
| `KF_LLS_TV` → デューティ | 30.0 % | **36.7 %** |
| `KL_AQ_ABS_LLS` → 面積 | 13.0 mm² | **27.4 mm²** |
| → 予測 `AQ_REL` | 0.173 % | **0.295 %** |
| **実測 `AQ_REL`**（整定アイドル中央値） | — | **0.317 %** |

**空気側の鎖もログと閉じる。** 実測 0.317 % はこの BIN の弁マップで `ML_SOLL` ≈ 18.9 kg/h に
相当し、TERRA のマップだと 24 kg/h が必要になって実測 `ML_SOLL` と合わない。
つまり **この BIN の `KF_LLS_TV` が車で動いているものだと、ログ側から裏が取れた。**

`KL_AQ_ABS_LLS` はこの領域が最も非線形（raw 400→0、1000→4、1500→13、2500→56 mm²）なので、
**デューティ 7 ポイントの差が面積では 2 倍**になる。アイドル弁は曲線のいちばん急なところで
動いている。

## 4.4 「触るな」ではなく「解錠条件」

前版はここを禁止事項として書いていた。**それは誤りである。** 未確立と禁止は別のことで、
アイドルの挙動を変えたいなら空気側を触る以外に道はない。以下は禁止ではなく、
**何を測れば動かしてよいか**の一覧である。

| パラメータ | 何を決める | 現在値 | 解錠に必要な証拠 | 動かすと車がどうなる | 外すとどう失敗する |

| **`KF_LLS_TV`**<br>Z `0x9E10`、13×10、`x/50` % | 空気要求 → 弁デューティのフィードフォワード | 870 rpm/18.35 kg/h で **36.7 %**（参照 30.0 %） | **`MD_LLRA`（`0xFFD8F2`）が整定暖機アイドルで 0 から離れて張り付いていること。**RAM 1 リードで読める | 弁とスロットルの分担、`AQ_REL`、**アイドルが載る `kf_rf_soll` の行** | ずれは LFR の I 項と適応が吸う。`K_LFR_MDADAPT` の +40 / −30 Nm を超えると恒久オフセットになり、A/C・負荷ステップで戻らなくなる |

## 5. `rf_soll` の完全な式（`rf_soll_calc` @ master `0x01A9D2`、code-confirmed）

§0 のゲートが使っている式は、**この式の 3 項を落とした簡約形**である。落としてよい条件が
そのまま「どの条件でログを録るか」を決めるので、まず完全形を置く。

```
rf_soll_no_filter = kf_rf_soll(N, aq_rel_rf)
                  + (AVAN1_SOLL_FAKTOR × (kf_rf_soll_kath(N, aq_rel_rf) − kf_rf_soll(N, aq_rel_rf))) >> 14
                                                          ← AVAN1_SOLL_FAKTOR ≠ 0 のときだけ
                  + kf_rf_soll_ask(N, aq_rel_rf)          ← ask_zustand_dpr bit0 が立っているときだけ

rf_soll_filter    = PT1(rf_soll_no_filter, τ)   τ = rf_soll_tau_up（上昇時） / k_rf_soll_tau_down = 0.0700（下降時）

rf_soll           = (rf_soll_filter × RF_PT_KORR) >> 12       4096 = 1.000
RF                = (rf_soll × rf_korr)          >> 10        1024 = 1.000
```

| 落とした項 | 落としてよい条件 | 落とせないと何が起きるか |
|---|---|---|
| **KATH ブレンド** | `AVAN1_SOLL_FAKTOR = 0`（触媒暖機が抜けている） | 実動作点（875 rpm, y 0.4534 %）で 0.2161 対 0.2301 = **+6.5 %**、1100 rpm では **+45 %**。rpm で桁が違うので単一の数字で警告してはいけない。→ `67-tuning-procedure.md` STEP 9 |
| **ASK 加算** | スノーケルフラップ閉（`ask_zustand_dpr` bit0 = 0） | 加算項なので RF が上振れる |
| **一次遅れ** | 定常サンプルのみ（`aq_rel_rf` が動いていない） | 過渡では表の瞬時値ではなく遅れた値が出る |

**重要なのは、ゲートがこの 3 つを自分で検出することである。** どれが生きていても
予測は実測から外れ、§0 の中央値／散らばり判定に落ちる。つまり *`AVAN1_SOLL_FAKTOR` を
読めなくてもよい* —— ゲートが「この区間は証拠にならない」と言う。

### 冷間の書き込み先は `kf_rf_soll` ではない

`kf_rf_soll_kath`（CSL Alpha-N Cold）は**別テーブル・別軸**である。

| | `kf_rf_soll` | `kf_rf_soll_kath` |
|---|---|---|
| Z | `0xD356`、24×20、`x/1000` | `0xD770`、24×20、`x/1000` |
| X 軸 | `0xD2FE`、600…**7900** rpm | `0xD718`、600…**4600** rpm（低回転が密） |
| Y 軸 | `0xD326`（0.1465 を含む） | `0xD740`（2.808 を含む） |

スケーリングは**検証済み**になった：XDF から復号した純正 `kf_rf_soll_kath` が、アプリの
`CSL_STOCK_WARMUP_MAP`（スクリーンショット転記）と全セル一致する。`ADDRESS_WARMUP_MAP = 0xD770`
は正しい。ただし**この車の BASE の cold 表は既に純正ではない**（row 0–3 の 80 セル中 56 セルが相違）。

> **⚠️ 2 表を行番号で対応させてはならない。** y 軸が違う（kath に 0.146 % は無い）ので、
> `kf_rf_soll` の row3 は y 0.391、kath の row3 は y **0.610** である。行番号で比べると
> ブレンド幅が +44 % に見えるが、同じ y で内挿した実際の値は **+3.6 %**（870 rpm）である。
> 書き込みセルも y 値で引くこと —— y 0.391 / 900 rpm は `0xD7C2` であって `0xD7EA` ではない。

## 6. 測定計画 — どの条件で、どれだけ録ると、どのバイトが動くか

### 6.0 セルはこの車ではほとんど埋まらない、という事実から始める

Session #920 は 52 分・13,608 点。そのうち §0 のゲートを通ったのは 578 サンプルで、
**その 87 % が 1 セル**——`kf_rf_soll` (870 rpm, y = 0.391 %) に落ちる。

```
r3(y=0.391) c1(870rpm)  104 サンプル      ← 暖機後アイドルはここしか踏まない
r5(y=0.806) c2(1100rpm)   5
r5(y=0.806) c1(870rpm)    4
r6(y=1.001) c2(1100rpm)   4
その他                     3
```

**52 分走って、証拠が付いたセルは実質 1 個。** これが「もっと録れば埋まる」ではない理由で、
以降の 4 ランは全て「**アイドルを別のセルに動かす**」ための手順である。

### 6.1 ラン一覧

| # | ラン | 条件 | 必要量 | 埋まる／得られるもの |
|---|---|---|---|---|
| **0** | **RAM チェーン読み** | エンジン始動・停車のみ。走行不要 | 10 分 | 鎖を項ごとに観測可能にする（§6.2） |
| **1** | 暖機後アイドル | 水温 ≥ 80 °C、N レンジ、車速 0、`wdk1` ≤ 1.0 %、AC OFF | **取得済み #920** | (870, 0.391) の 1 セル。補正 0.9 % → **書くものなし** |
| **2** | アイドル回転を振る | 同上 ＋ AC ON/OFF・据え切り・電気負荷・D/N | 各状態 15 秒 × 3 回、状態間 5 秒以上。**約 10 分** | row 3–6 × col 1–2 の 6〜8 セル |
| **3** | 冷間始動 ×3 | キー ON 時 **水温 < 30 °C**、N レンジ、無負荷、水温 80 °C まで放置 | 1 回 10〜15 分 × **別の日に 3 回** | `kf_rf_soll_kath` の低回転行 ＋ **`AVAN1_SOLL_FAKTOR` の実測カーブ** |
| **4** | 低負荷定常 | 一定スロットル巡航、6 速、1600–3000 rpm | 各点 15 秒 × 3 回 | 診断専用。§6.4 |
| **5** | **空気側の据わり** | 暖機後アイドル、N、AC OFF → AC ON → 据え切り | 各 30 秒。**約 5 分** | `MD_LLRA` の張り付き＝`KF_LLS_TV` の解錠条件（§4.4） |

**なぜ「3 訪問」なのか。** `la_f_regler` は 2 点制御で 1–2 Hz のリミットサイクルを持ち、
DS2 は 3–5 Hz。30 サンプルは 1 周期の 30 点でありうる。信号待ち 1 回は「1 観測の 30 回反復」で
あって 30 観測ではない。`minVisits = 3` / `visitGapSec = 5.0` はこれを見分けるためにある。
冷間始動は回転が単調に落ちるので **1 回の始動で 1 訪問**にしかならない —— だから 3 日必要になる。

### 6.2 RUN 0 — 走らずにできる、いちばん効くやつ

鎖の全項が連続 RAM に並んでいる（`aq_rel_calc` / `rf_soll_calc` の逆アセンブルより）:

| シンボル | アドレス | 意味 |
|---|---|---|
| `AQ_REL` | `0xFF80DE` | スロットル＋アイドルバルブの相対開口 |
| `AQ_ABS` | `0xFFE970` | 絶対開口 [mm²] |
| `AQ_ABS_LLS` | `0xFFE972` | **そのうちアイドルバルブ分** |
| `aq_rel_rf_pt_fakt` | `0xFFE974` | `(aq_rel_rf_fakt × RF_PT_KORR) >> 12` |
| `aq_rel_rf_fakt` | `0xFFE976` | `kl_aq_rel_rf_fakt(N)` の現在値 |
| `aq_rel_rf_pt_fakt_ds2` | `0xFFE978` | DS2 用の PT 込み版 |
| **`aq_rel_rf`** | **`0xFFE97A`** | **DME が `kf_rf_soll` を索いた Y 座標そのもの** |
| `rf_soll_filter` | `0xFFEDEC` | PT1 後・`RF_PT_KORR` 前 |
| **`rf_soll`** | **`0xFFEDEE`** | `RF_PT_KORR` 後 |
| `RF_PT_KORR` | `0xFF81CA` | |
| `AVAN1_SOLL_FAKTOR` | `0xFF81EC` | KATH ブレンド係数（16384 = 1.000） |
| `ask_zustand_dpr` | `0xFF8299` | フラップ状態 bit0 |
| **`MD_LLRA`** | **`0xFFD8F2`** | **アイドル需要適応（コンプレッサ OFF）[Nm]** — `KF_LLS_TV` の誤差がここに溜まる |
| `MD_LLRA_KO` | `0xFFD8F4` | 同（コンプレッサ ON） |
| `LFRA_MD_INTEGRATOR` | `0xFFEA20` | 適応の積分器そのもの |
| `LFRA_SPERREN` | `0xFFEA16` | 適応の禁止フラグ |

`0xFFE970`–`0xFFE97B` は **6 ワード連続＝ 1 回の 12 バイト読み**。`0xFFEDEC`–`0xFFEDEF` が
もう 1 回の 4 バイト読み。合計 5 リード・22 バイトで、

```
  ゲート:    RF  ≟  kf_rf_soll(N, rawLoad / fakt) × RF_PT_KORR     ← 端から端まで 1 個の数

  RUN 0 後:  aq_rel_rf ≟ rawLoad / fakt                            （索引が合っているか）
             rf_soll   ≟ kf_rf_soll(N, aq_rel_rf) × RF_PT_KORR     （表と補正が合っているか）
             RF        ≟ rf_soll × rf_korr                         （下流が合っているか）
```

**推測から、項ごとの同一性検査に変わる。** §6.4 の未解決項はこれで一発で切り分けられる。

### 6.3 RUN 3 — 冷間始動は、テーブルより先に「ブレンド係数」を測る

`AVAN1_SOLL_FAKTOR` は 3 関数から読まれるが、**書き手が復元されていない**（`xref-only`）。
しかし §5 の式を解けば実測できる:

```
AVAN1_SOLL_FAKTOR / 16384 = ( RF / rf_korr / RF_PT_KORR − kf_rf_soll ) / ( kf_rf_soll_kath − kf_rf_soll )
```

停車アイドルなら `rf_korr = 1.000`（`V < k_rf_korr_v_min = 20 km/h` では保持枝も成立しない）ので、
右辺は全部ログと BASE から出る。

**ただしアイドル回転域では分解能が足りない。** 実動作点の分母は `0.2301 − 0.2161 = 0.0140` で、
`rf` の 1 LSB = 0.001 に対して全レンジ 14 段。ゲートの sd 0.0054 だけで全スケールの 9 % を食う。
**測るべきは触媒暖機アイドルが実際に居る 1100–1400 rpm** で、そこでは分母が 0.039–0.061 に広がる。

予測（訂正）: この BASE ではアイドル域で `kath > kf_rf_soll` なので、モデルゲートの比は
触媒暖機中 **1 を超える**（1100 rpm で 1.45）。**0.7 に落ちるのではない** —— 0.7 になるのは
600 rpm 行だけで、そこはクランキング領域である。この符号を逆に置くと、正しく録れたランを
「録り直せ」と判定して冷間ステップが永久に開かない。

#920 は 51 °C 始まりで cold セグメント（水温 < 80 °C）も 1.00 に乗っているので、
**51 °C ではブレンドは既に抜けている**。測れる窓は水温 30 °C 未満から始まる。

### 6.4 RUN 4 — 部分負荷の 15 %：潰した仮説と、残った 1 つ

`wdk1 = 1.1` の定常サンプル（車速 0、水温 86、60 サンプル連続）で:

```
              rawLoad   aq_rel_rf   RF 実測   RF 予測   比
アイドル       0.317      0.453      22.0      22.07    0.998
wdk1 = 1.1     0.375      0.536      19.9      23.60    0.845
```

**開度が 18 % 増えているのに充填が 9.5 % 減っている。** 同一回転・同一水温の定常でこれは起きない。

| 仮説 | 判定 |
|---|---|
| MAP 積分 `rf_p_saug_i` が加算されている | **却下**。BASE の `k_rf_cfg`（`0xE5E4`）= `0x02`、bit4 は既に落ちている |
| 一次遅れ（過渡） | **却下**。`wdk1` = 1.1 が連続、RF 19.4–20.1 で定常 |
| `k_aq_rel_wdk_segm_nullage` の不感帯 | **却下**。`0xD220` = **0.3 %**。両群とも上にいる |
| `rf_korr` が 1.000 でない | **却下**。V = 0 では保持枝の条件（`V ≥ 20`）も成立せず `rf_korr = 0x400`。かつ `KF_RF_KORR_DRREL` は下限 1.0 の増量側 |
| `rf_soll_calc` に LL/TL 分岐がある | **却下**。全 14 文を読んだが状態分岐は KATH と ASK のみ |

**残るのは 1 つだけ**: 逆算すると、実測 RF に合う `aq_rel_rf` は 0.405（ログ由来は 0.536）で、
これは `rawLoad` 換算 0.284 —— **ログの `rawLoad` が、DME が実際に索いた値より 32 % 高い**。
アイドルでは両者が 1 % で一致する。よって誤差は表でも下流でもなく、**`rawLoad` チャンネルの
同一性**にある。`aq_rel_calc` は `AQ_REL`（`0xFF80DE`）と `aq_rel_rf_pt_fakt_ds2`（`0xFFE978`、
`RF_PT_KORR` で割った別物）の**両方**を書いており、DS2 がどちらを出しているかは未確定。

**RUN 0 がこれを 10 分で終わらせる。** `aq_rel_rf`（`0xFFE97A`）を直接読み、`rawLoad / fakt` と
比べるだけでよい。それまで **部分負荷の補正はゲート未通過**のままとする。

## 7. 書いたら車がどう変わるか

### 7.1 `kf_rf_soll` の 1 セルは燃料だけを動かさない

```
RF ──→ TL = RF_TI_CONST × RF / 2000 ──→ TI（噴射時間）          燃料
   ──→ ML = N × (RF × m_norm / 1000) / 25000                    空気質量 [kg/h]
   ──→ KF_MD_MIN_LW_N_RF ほか（RF 軸のトルクモデル）             トルク → 点火・EGAS
   ──→ KF_TI_N_RF（rf 軸）                                      低開度増量の行選択
```

**「燃料だけ 1 % 濃くする」はできない。** 1 LSB = 0.001、アイドルのセル 0.200 に対して
**0.5 %**。それを 1 段上げると TI が 0.5 % 増え、同時に ML とトルクモデルの充填も 0.5 % 増える。

### 7.2 クローズドループでは何も感じない —— それが要点

| 状態 | λ ループ | 表を直すと |
|---|---|---|
| 暖機後アイドル・巡航 | **閉** | STFT が同じ量を戻すので**体感は変わらない**。変わるのはトリムの中心が 0 に寄ること＝適応の余裕 |
| 冷間始動〜 λ センサ加熱前 | **開**（`K_LA_TI_MIN` / `K_LAA_TMOT_MIN`） | **ここは直接効く**。始動直後の荒れ、アイドルの高すぎ／低すぎ、最初のアクセルでのつまり |
| 加速増量・ティップイン | 実質開 | 踏み始めの薄み／濃すぎ |
| オーバーラン復帰 | 開 | 復帰時のショック |
| WOT | 開 | 出力と安全マージン |

**だから「暖機後アイドルで 0.9 % ずれている」は直す価値が無く、「冷間の表がずれている」は
直接体感になる。** 冷間ランが最優先である理由はここにあって、テーブルが未測定だからではない。

### 7.2b 空気側は逆で、閉ループだからこそ即座に体感になる

測定側（`kf_rf_soll`）と空気側（`KL_LFR_NSOLL_GRUND` / `KF_LLS_TV` / LFR ゲイン）は、
**「閉ループだと体感が無い」の向きが逆である。**

| | ループが閉じている先 | 1 段動かすと |
|---|---|---|
| 測定側 | **λ**（混合比） | STFT が戻すので体感なし。開ループの瞬間にだけ現れる |
| 空気側 | **回転数** | LFR は新しい釣り合いへ動く。**定常アイドルそのものが変わる** |

`KL_LFR_NSOLL_GRUND` の 80 °C セルを 870 → 900 にすれば、暖機後のアイドルは 900 になる。
LFR がそこへ持っていくのが仕事だからで、証拠は要らない —— これは測定ではなく選択である。

`KF_LLS_TV` は逆にフィードフォワードなので**定常回転は変えない**。変えるのは
弁とスロットルの分担・応答・そして `AQ_REL` すなわち**アイドルが載る `kf_rf_soll` の行**。
ずれた分は LFR の I 項と `MD_LLRA` が吸い、`K_LFR_MDADAPT` の +40 / −30 Nm を超えたところで
吸えなくなる —— そこから先が「A/C を入れると戻ってこない」である。

### 7.3 この車で今わかっている「効かない」こと

| | 実測 | 結論 |
|---|---|---|
| 暖機後アイドルの λ トリム | bank1 0.998 / bank2 0.985 | 補正 0.9 % = **量子化 2 段**。書いても丸め以下 |
| バンク間差 | 1.3–1.8 %（bank2 が濃い） | `kf_rf_soll` は両バンク共通。**較正では直せない**（インジェクタ／片バンク吸気漏れ／O2） |
| 暖機中（51→80 °C） | −4.2 % | `AVAN1_SOLL_FAKTOR` が既に 0 の領域なので `kf_rf_soll` の証拠として有効。ただし 51 °C 未満は 1 サンプルも無い |

## 用語

| 語 | 意味 |
|---|---|
| **モデルゲート** | BIN の算術が車自身の `rf` を再現するかの検査。書き込みの入口条件 |
| **武装 (arm)** | 導出した表を次の書き込みに載せると宣言すること。バイトはまだ動かない |
| **封印 (seal)** | 導出はするが、バイト境界で書き込みを止めてあること |
| **sub-quantum** | 補正量が 1 LSB 未満 —— 書けないので収束扱い |
