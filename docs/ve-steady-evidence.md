# VE / RF KORR の定常比較と追加観測

2026-10-08。実装は比較・観測段階。実車の直接RAM読出しと、異なる熱状態での再現性は未確認。
既存セッションの計算方式を維持し、WORKS の VE フィルター設定から新方式を選択する。

## 固定 α を採用しない理由

定常状態で、パージなどの加算項と学習を分離でき、目標空燃比等が同じと仮定すると、
燃料側の倍率を `T`、その点で現在適用される補正を `k_applied`、次に適用される補正を
`k_planned` として、局所的な比較式は次になる。

```
C = T * k_applied / k_planned
VE_comparison = VE_old * C^η
```

同じ補正と運転条件を保つ比較では `k_applied = k_planned` なので `C = T`。
これは Δ30 での絶対的な VE を測定したという意味ではない。VE の変更で補正ゲートや
運転点が変われば、同じ補正を保てるという前提も崩れる。

従来の `T * k` は参照条件についての仮説を含む。`T * k^α` を繰り返すと、理想化した
一定条件でも補正が止まるのは `T = k^-α` となり、α は単なる更新速度の設定にはならない。
更新を弱める場合は補正全体に η を掛ける（上式では指数として適用する）。η は真値や
補正モデルの正しさを証明しない。新方式では既存の DIRECT authority / STATISTICAL の
更新抑制を併用せず、η を唯一の更新率とする。既存のセル採用条件は引き続き適用する。

同じ N/RO、同じ燃料・学習・加算項等の条件で熱状態 A/B を比較できれば、
`(T_A*k_A)/(T_B*k_B)` は相対的な熱補正形状を調べる材料になる。
Δ30 がないことだけで相対形状の比較が不可能になるわけではない。一方、VE と補正表の
絶対尺度を同時に一意決定するには、独立なアンカーか明示した事前仮定が必要。
現実装はこの比から RF KORR テーブルを自動更新しない。

## 実装した判定

`steady-retain` は、フィルターで行を落とす前の時系列から過去5秒を調べる。
未来のサンプルは使わず、LIVE の途中結果と停止後の同じ区間の判定を一致させる。
同じ時刻が再登場しても元の行番号で照合し、時計のリセットで履歴を切る。

初期値は取得条件の暫定値であり、実車から同定した定数ではない。

| 判定 | 初期条件 |
|---|---|
| 時間・密度 | 過去5秒、10点以上、隣接読出し間隔1秒以下 |
| 回転数・負荷 | 全幅200 rpm以下、補正後RO全幅1ポイント以下、RF全幅5ポイント以下 |
| 両バンクのSTFT | 全幅0.12以下、前半/後半の時間平均の変化0.03以下 |
| 学習値 | 両バンクが取得でき、窓内全幅0.005以下。比較計算への採用時は双方1.000 |
| パージ | TETVが取得でき、0 ms。作動・欠測で窓をリセット |
| トリム限界 | 記録時BINの上下限から0.02以内を除外 |
| 状態 | 冷間、燃料カット、全負荷、触媒保護、補正切替・応答待ち、欠測を除外 |

5秒継続することや `LA_FREEZE_FLAG=0` だけでは閉ループの証明にならない。
直接RAM値も判定の代用にはしない。温度・触媒保護設定と除外時間帯を引き継ぐ。

記録時BASEで MAP/HFM/加算MAP経路の停止と学習停止を確認できなければ、
観測結果のみを表示する。UIの「次に書くパッチ」の選択を、記録時に適用済みの証拠として
扱わない。この前提を満たしても、新方式は比較専用としてBIN生成の入口で拒否する。
ダウンロード・書込み・手動セル編集・暖機表等から迂回できない。
生ログと設定・BASE由来の保存は別経路で継続する。既にTUNEDがあるdraftでは、
観測用の新しいdraftへ分けて元のBIN・設定・ログを保持する。

## WORKS に追加する観測値

0401 のローカル逆アセンブル資料に対応するマスター側アドレス。実車の応答照合前なので
`rfDirectSource = ram-0401-unverified` を付け、VE計算の入力へ自動昇格させない。

| ログ列 | RAM | 解釈 | 頻度 |
|---|---|---|---|
| `rfKorrDirect` | `0xFFEEA6` | unsigned 16 bit / 1024 | 毎サンプル |
| `rfSollDirect` | `0xFFEDEE` | unsigned 16 bit / 1000。平滑化・PT補正後の目標充填量 | 毎サンプル |
| `rfMapIntegratorDirect` | `0xFFEED8` | signed 16 bit / 64000。MAP積分器の格納値 | 8サンプルごと |

各列に読出し中点の `…Time`（開始から秒）と通信所要時間の `…ReadMs` を記録する。
三者および既存ブロックは同時測定ではない。失敗・短い応答時は欠測とし、直前値を
埋め戻さない。MAP格納値の存在は、その値が現在適用されている証拠にはならない。
実際の演算には負数の丸めもあるため、格納値をそのままRFから引かない。

9600 baud の通信モデルでは約110.9 ms/サンプル増え、WORKS の見積りは
約4.42 Hzから約2.97 Hzになる。実測レートは未確認。PRODUCTION の通信項目は変更しない。

## 次の検証順序

1. 追加計測を含む WORKS を用意し、実車の0401で短い診断ログを採る。
   計測だけのためにECU校正を変更する必要はない。まずRAM応答の欠測率・読出し時間と
   既存信号との整合を確認する。
2. 記録時BINと各パッチの由来を固定して、直接 `rf_korr` と再構成値の差を、
   ゲート切替前後・MAP補正状態ごとに調べる。`rf_soll` は平滑化後なので、
   過渡時にVEテーブル補間値と一致することを要求しない。
3. 台上などで同じN/ROを繰り返せる条件を用い、パージ不作動・学習一定・
   トリム非飽和が確認できる複数の定常窓を取得する。2200～2700 rpm、RO 7.5～10%に
   加え、隣接RO 5～7.5%も対象にする。異なる熱状態の比較は窓ごとに行う。
4. 一方の熱状態で作った比較が別の熱状態のトリム誤差も減らすか、保留したデータで
   評価する。成立しなければVEとRF KORRの更新を切り分け、絶対尺度のアンカーを検討する。

定常窓が0なら「補正不要」ではなく「そのログからは校正量を決められない」。
強い減量・下限到達は別途確認すべき観測として残す。

## D1 と再解析

接続にはプロジェクト専用の Wrangler ラッパーを使う。読取りスクリプトはID列挙と
個別読取りを分け、圧縮BLOBを分割取得する。観測されたAPI 7403に限り最大2回再試行し、
継続する失敗は通知する。上流で7403が発生する根本原因は未特定。
SHA-256でBASE/TUNEDの一致を確認し、実ログ・BIN・レポートは非公開の `archive/` に置く。

```powershell
npm run db:sessions
node scripts/fetch-d1-sessions.mjs --id <session-uuid> --out archive/d1/review
node scripts/analyze-ve-evidence.mjs archive/d1/review/<session-uuid> --out archive/ve-evidence/review
```

レポートは `report.html`、`analysis.json`、`points.csv`。従来の単点補正式と
条件付きの維持比較を表示するが、保存済みTUNED全体の再現や推奨αとは区別する。
このコマンドはD1・ECUに書き込まず、BINも生成しない。

検証コマンド: `verify:rf-direct`、`verify:steady-evidence`、`verify:operating-policy`、
`verify:comparison-output`、`verify:comparison-save`。既存の `verify:incremental`、`verify:file-workflow`、
`verify:ve-divisor` で従来経路の互換性も確認する。
